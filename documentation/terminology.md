# Как называются объекты в KOT, СППР и Vanessa Automation

Если вы только начинаете, достаточно различать три вещи: **сценарий описывает действия**, **настройка запуска задаёт вариант выполнения**, а **клиент тестирования открывает проверяемую базу**.

| Термин в интерфейсе | Что это означает | Где искать |
|---|---|---|
| Сценарий СППР / SPPR scenario | Исходный сценарий работы пользователя на языке Turbo Gherkin для СППР. Может вызывать другие сценарии и принимать параметры. | `scen.yaml` или пара `meta.yaml` + `scen.feature` |
| Главный сценарий / Main scenario | Сценарий СППР, для которого есть связанная настройка запуска. Его можно выбрать для компиляции в Менеджере тестов KOT. | Исходник и папка `test` рядом с ним |
| Вложенный сценарий / Nested scenario | Повторно используемый сценарий СППР. Его вызывает другой сценарий или шаг процесса. | Библиотека KOT |
| Процесс / Process | Последовательность сценариев и вложенных процессов СППР с передачей параметров между шагами. | YAML процесса |
| Главный / вложенный процесс | Роль процесса в KOT: главный имеет настройку запуска, вложенный используется как шаг другого процесса. Это пояснение роли, а не другой формат СППР. | Мастер создания, свойства и преобразования |
| Настройка запуска / Run settings | Связанный YAML с `ТипФайла: НастройкаТеста`. Определяет сценарий или процесс, эталонную базу, профиль пользователя и значения параметров для компиляции. | Вкладка настроек запуска в свойствах; папка `test` |
| Функциональность / Feature | Документ Gherkin с заголовком `Функциональность:` / `Feature:`. В нём может быть несколько сценариев. | Самостоятельный или скомпилированный `.feature` |
| Самостоятельный feature-файл / Standalone feature | Функциональность Vanessa, написанная сразу в Gherkin, без компиляции СППР. | Раздел самостоятельных feature-файлов |
| Экспортный сценарий / Exported scenario | Переиспользуемый сценарий Vanessa из feature-библиотеки. Данные передаются аргументами в названии вызова. | Раздел экспортных сценариев в Библиотеке |
| Встроенный шаг / Built-in step | Действие из библиотеки самой Vanessa Automation. | Библиотека, автодополнение и подсказки |
| Пользовательский шаг / User step | Шаг, реализованный в своей обработке 1С. Экспортный сценарий и пользовательский шаг — разные способы переиспользования. | Библиотека пользовательских шагов проекта |
| Параметр сценария / Scenario parameter | Значение, подставляемое компилятором СППР в `[Имя]`. | Шапка параметров и вызовы вложенных сценариев |
| Аргумент / Argument | Значение, которое передаётся при вызове сценария или шага. | Например, `"Учебный покупатель"` в строке шага |
| Переменная Vanessa / Vanessa variable | Значение во время выполнения. Например, `$Имя$`; сохранённый контекст использует `$$Имя$$`. | Панель «Переменные сеанса» |
| Параметры запуска Vanessa / Vanessa launch parameters | JSON с библиотеками, отчётами, клиентами и другими параметрами Vanessa. Это отдельный слой после компиляции СППР. | Параметры запуска, `VAParams.json` и сформированный JSON |
| Компиляция / Compilation | Преобразование сценариев и процессов СППР в feature-файлы и сопровождающие файлы. Надпись «Собрать» в KOT запускает именно этот этап. | Менеджер тестов KOT |
| Выполнение / Run | Прохождение шагов Vanessa. Успешная компиляция ещё не означает успешное выполнение. | Кнопка запуска и подсветка шагов |
| Менеджер тестов KOT / KOT Test Manager | Панель VS Code для выбора, компиляции и запуска тестов. | Боковая панель KOT |
| Менеджер тестирования / Test manager | Сеанс 1С, в котором работает Vanessa Automation и который управляет клиентами тестирования. | Запущенная Vanessa; состояние соединения в строке состояния VS Code |
| Клиент тестирования / Test client | Сеанс проверяемой информационной базы, которым управляет Vanessa. | Информационные базы → клиенты тестирования |
| Служебная информационная база / Service infobase | База для работы компилятора и менеджера тестирования. Её не следует путать с базой проверяемого приложения. | Настройки подготовки и запуска KOT |
| Эталонная база / Reference infobase | Сохранённое исходное состояние тестовой базы и связанные профили пользователей для подготовки прогона. | Каталог эталонных баз, `bases.yaml` |
| Исследователь формы / Form Explorer | Просмотр элементов открытой формы клиента тестирования и получение подходящих шагов. | Команда и панель исследования формы KOT |
| Ответственный / Responsible person | Участник, отвечающий за сценарий в СППР. Не определяет автоматически автора серии номеров или пользователя 1С. | Свойства сценария |
| Автор серии / Numbering-series author | Участник, которому выделен диапазон кодов KOT. | Каталог авторских серий |

## Форматы без лишних названий

В пользовательском интерфейсе используются имена **«Сценарий в одном YAML»** и **«Текст feature + метаданные YAML»**. Служебные значения настроек `legacy` и `native` сохраняются для совместимости. Файл `scen.feature` в паре СППР не становится самостоятельной функциональностью Vanessa: перед полным запуском такой сценарий компилируют.

Слова «метаданные СППР» означают поля самого сценария в `meta.yaml`. «Метаданные KOT» — группы, порядок, описание и другие сведения в соседнем `*.kot.yml`. Исходные имена полей, UID, API MCP, команды расширения и ключи настроек не переименовываются при изменении подписей.

## Основания для словаря

- [Руководство СППР 2.0, глава 11](https://its.1c.ru/db/sppr2doc): процессы, сценарии работы пользователей, настройки сценариев, компиляция, эталонные базы. Часть подробных разделов требует доступа ИТС; форматы файлов дополнительно сверены с поддерживаемыми шаблонами и парсерами KOT.
- [Официальная документация Vanessa Automation](https://pr-mex.github.io/vanessa-automation/dev/): feature-файлы, сценарии, библиотеки, профиль запуска и клиент тестирования.

Названия панелей KOT и роли «главный / вложенный» дополнительно уточняют работу расширения; словарь не объявляет их новыми объектами СППР или Vanessa.
