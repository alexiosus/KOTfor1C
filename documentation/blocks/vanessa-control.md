# Управление Vanessa из KOT

В палитре и Test Manager доступны **Control Vanessa**, **Start managed Vanessa** и **Attach to running Vanessa**. Для сохранённого feature добавлены **One step**, **Run from this step** и контекстный F11 вне стороннего сеанса отладки. На Vanessa 1.2.043.45, devkit 0.6.6 и платформе 8.5.1.1522 проверены отдельный безопасный шаг, запуск с середины сценария, Stop длинного шага, ошибка и восстановление подключения. F11 с выбором следующей строки и точки останова проверены в редакторе VS Code; ограничения циклов и экспортных вызовов описаны ниже. Обычный Debug с сохранёнными клиентами работает независимо.

## Компоненты и их назначение

1. **MCP devkit** устанавливается в базу менеджера тестирования и предоставляет MCP-сервер с транспортом WebTransport. Для KOT целевая база — уже существующая служебная ИБ `.vscode/kot-runtime/startup-infobase/ib`, которую KOT подготавливает для сборки и запуска Vanessa.
2. **VAExtension** устанавливается в тестируемую базу и добавляет возможности отдельных шагов и инструментов, например выполнение кода в контексте клиента/сервера и получение дополнительных данных. Оно не является обязательной зависимостью команд управления самим менеджером: запуска сценария/шага, остановки, открытия feature и точек останова. При выполнении конкретного шага его собственные зависимости остаются в силе. См. [назначение VAExtension](https://github.com/Pr-Mex/vanessa-automation/blob/1.2.043.45/docs/VAExtension/VAExtension.md) и [обработчики команд менеджера](https://github.com/Pr-Mex/vanessa-automation/blob/1.2.043.45/VanessaAutomation/Forms/MCPVA/Ext/Form/Module.bsl).
3. **VanessaExt** — внешняя компонента Vanessa; её подготовка уже используется при запуске из KOT. Для точек останова нужен **Vanessa Editor**. Компоненты Vanessa и WebTransport devkit проверяются по своим версиям и возможностям.

LLM и расширения Cline/Continue для кнопок KOT не требуются: KOT обращается к MCP напрямую. [Общая инструкция Vanessa](https://github.com/Pr-Mex/vanessa-automation/blob/1.2.043.45/docs/AI/index.md#быстрый-старт) описывает более широкий набор MCP-инструментов, включая действия в клиенте; её полный список зависимостей не должен становиться общим условием подключения KOT к менеджеру.

## Как запустить сервер для проверки

Откройте Vanessa в базе менеджера в режиме `/TESTMANAGER`, затем нажмите **Запустить** в интерфейсе MCP devkit. Задайте и запомните порт сервера. Альтернативный запуск из PowerShell (замените пути и версию платформы):

```powershell
& 'C:\Program Files\1cv8\<version>\bin\1cv8c.exe' ENTERPRISE /TESTMANAGER /F 'C:\KOT\TestManager' /Execute 'C:\Tools\Vanessa\vanessa-automation.epf' /C 'runMcp;mcpPort=9876'
```

Адрес такого сервера — `http://127.0.0.1:9876/mcp` на том компьютере, где запущена 1С. Если VS Code работает на macOS, а 1С — в Windows, `localhost` у них различается: нужен доступный из macOS адрес Windows и явно настроенный доступ к серверу. Не публикуйте сервер в интернете. Доступность URL сама по себе не подтверждает совместимость: KOT проверяет MCP-handshake и схемы инструментов.

## Автоматическая подготовка служебной ИБ

Для управляемого запуска подготовка MCP должна быть частью существующего механизма служебной ИБ KOT. При первом таком запуске KOT проверяет базу, подготавливает совместимый devkit и транспорт, запускает Vanessa с явным `runMcp;mcpPort=…` и ожидает MCP-handshake и список инструментов. Последующие запуски переиспользуют подготовленные компоненты. Отдельная база и отдельный обязательный мастер для этого не требуются.

Подготовка вызывается по требованию управляемого режима. Обычная сборка не должна получать зависимость от MCP или ждать его установки. Состояние компонентов хранится отдельно от состояния шаблона служебной ИБ; для обновления компонентов не нужно пересоздавать базу. Установка/обновление согласуются с работающими служебными сеансами и общим механизмом сериализации подготовки.

Автоматическая установка относится к служебной ИБ, которой управляет KOT. Для подключения к уже открытой сторонней Vanessa KOT только проверяет endpoint и доступные команды. Отсутствие VAExtension в клиенте не блокирует подключение и управление менеджером; при необходимости его проверяет конкретная операция клиента.

Безопасный режим отключается только у **client_mcp** в служебной ИБ KOT: ему требуется доступ к feature-файлам и действиям менеджера. Защита от опасных действий сохраняется. Для внешней базы Attach эти настройки не меняет.

В текущей реализации команда **Start managed Vanessa** использует существующий механизм служебной ИБ. Новый DT может включать devkit заранее: после восстановления KOT проверяет manifest и хеш DT, поэтому повторная загрузка CFE в новую базу не требуется. Для старой базы без компонентов KOT проверяет отсутствие активных служебных сеансов и устанавливает официальный CFE однократно, без восстановления DT. Подключение **Attach** не изменяет базу и не запускает 1С.

В `.45` регистрация MCP-библиотек может вызвать `VanessaExt.НайтиФайлы` до успешного подключения компоненты. Для MCP KOT отключает только поиск файлов через VanessaExt в конечной runtime-копии VAParams: библиотеки находятся штатным поиском 1С. Использование самой VanessaExt, исходный профиль и JSON, а также обычный Debug сохраняются. Это обход ошибки запуска `.45`, не проверка готовности всех возможностей внешней компоненты.

При `State unavailable` явное подключение сначала обновляет состояние, затем при неуспехе отсоединяет недоступный транспорт и заново ищет сеансы. Сам процесс Vanessa при отсоединении не закрывается. Если регистрация инструментов завершилась ошибкой в 1С, повторное подключение к тому же неисправному серверу её не устраняет: нужен исправленный новый запуск.

Devkit v0.6.6 содержит WebTransport. Включение devkit в DT не устанавливает нативную компоненту в профиль ОС: на новом компьютере 1С может показать собственный диалог её установки при первом запуске сервера. KOT ожидает готовности endpoint; наличие devkit в базе само по себе не считается успешным подключением. Открытые вопросы лицензирования вложенного WebTransport перед публичной поставкой отмечены в [`THIRD_PARTY_LICENSES.md`](../../THIRD_PARTY_LICENSES.md#webtransport-included-by-devkit).

## Границы управления

Запуск с выбранного шага пропускает предшествующую подготовку и не восстанавливает состояние базы, окна или переменные. Остановка на точке и новый запуск с этой строки не равны продолжению приостановленного BSL-стека. Неизвестный формат ответа отображается как неизвестное состояние; отсутствие выполнения не считается успешным результатом теста.

Прогресс N/M передаёт счётчик Vanessa, который при запуске с середины может включать пропущенные строки. Он не подтверждает результат шага. Для успеха KOT проверяет ответ выполнения, для короткой ошибки — также обновившийся результат с совпадающими файлом и строкой. При потере связи результат остаётся неизвестным до нового подтверждения. В проверенной версии Stop иногда оставляет запрос запуска без ответа; KOT завершает ожидание только после подтверждённого состояния остановленного шага, сохраняя подключение.

После успешного F11 KOT выбирает следующую исполняемую строку, которую сообщает редактор Vanessa, если исходник и локальная позиция не изменились. Условия, вложенный вызов и сохранение переменных проверены в служебном сценарии. Для автоматического перехода назад в цикле выявлена ошибка проверенной версии MCP: повторное выполнение заголовка пропускает итерацию. Такой переход KOT не делает и показывает пояснение; дальнейшую строку можно выбрать вручную. При ошибке курсор остаётся на проблемном шаге.

Точки останова требуют готового встроенного редактора Vanessa. KOT сверяет активный сохранённый файл перед изменением и подтверждает точки повторным чтением. В Vanessa `.45` список без точек сопровождается подсказкой «файлы не открыты» даже при открытом документе; эта подсказка не блокирует работу. Ответ о недоступности самого редактора остаётся ошибкой.

Перед ручным шагом и изменением точек KOT сравнивает сохранённый исходник с содержимым редактора Vanessa. Чистая устаревшая копия перезагружается по команде с сохранением чужих точек; несохранённая копия Vanessa остаётся защищённой. Содержимое проверяется при команде, не при каждом опросе состояния, и не сохраняется в снимке сеанса.

В `.45` проверена остановка перед шагом в цикле и повторный запуск с начала этого сценария. Точка внутри экспортного сценария при вызове из другого сценария в той же feature в проверке была пропущена Vanessa. Поддержка остановки внутри такого вызова пока не подтверждена; пошаговое выполнение циклов также имеет указанное выше ограничение. Новый запуск с выбранной строки заново загружает feature и сбрасывает счётчики циклов.

## Подготовка управления из YAML

Успешная сборка теперь может сохранять `.kot-build-manifest.json` рядом с результатом. Он связывает хеши YAML, эталонных баз, профиля и EPF компилятора с окончательными feature и `.str`, отдельно для каждой части сборки. В манифесте нет значений параметров или паролей. Перед сохранением повторно проверяются входные данные после возврата временно убранных настроек. Ошибочная, отменённая или изменившаяся сборка не получает подтверждения актуальности.

После сборки **Execute one step / F11**, **Run from this step** и **Toggle KOT breakpoint** доступны также в тексте YAML. При повторных вызовах или вариантах параметров KOT предлагает выбрать точное вхождение: часть сборки, feature и строку. После выбора актуальность сборки проверяется повторно. Открытые несохранённые зависимости блокируют выполнение. Состояние шага и точки показываются на соответствующих строках YAML; автопереход после F11 ограничен следующими строками того же исходного файла.

Проверены реальная компиляция двух частей, вложенный процесс, повторный сценарий, два сочетания параметров, точное прямое/обратное соответствие и безопасный одиночный шаг по карте. В Extension Development Host также проверены выбор одного из восьми вхождений, F11 и отметка результата у исходного YAML, добавление и удаление маркера точки останова. Для пробы до сборки добавлена отдельная команда **Try YAML step without compilation** в палитре и подменю KOT редактора. Она выполняет один однозначно найденный обычный шаг из каталога Vanessa с его таблицей или многострочным текстом. Нужен открытый проект с готовым каталогом. Конструкции СППР, вложенные/экспортные/пользовательские вызовы, подстановки параметров, outline и файловые аргументы требуют сборки. Язык и отступы сохраняются; исходный YAML остаётся обычным документом. Результат показывается у исходной строки, переход на следующую строку не угадывается. Пробный запуск обычного шага и отметка результата в исходном YAML проверены в Extension Development Host на указанной выше Vanessa `.45`. Если точный каталог выбранной версии недоступен, KOT сообщает об этом до выполнения. Наличие старого `.str` даёт обычную навигацию по исходнику, но не разрешает выполнение из YAML.

## Тест-клиенты и сохранённые подключения

В **Control Vanessa → Test clients and saved connections…** и отдельной команде палитры доступны сохранённые подключения Debug и список клиентов текущего сеанса. Редактор повторно использует Infobase Manager, пользовательские ключи запуска и прежнее защищённое хранилище. **Use as connection template** создаёт копию с отдельным именем, идентификатором и свободным портом; сохранение набора не подключает клиентов к уже работающей Vanessa.

Для работающего сеанса **Apply saved connection** применяет выбранный профиль и повторно читает все поддерживаемые поля. В MCP Vanessa `.45` нет поля порта: перед применением KOT сообщает об этом и предлагает применить поддерживаемые поля. Полный набор, включая порты, используется при управляемом запуске. Частичный или неизвестный ответ не считается успехом и не вызывает автоматического повтора. Активный профиль перед изменением требуется отключить.

Подключение, отключение и закрытие выполняются для явно выбранного клиента с повторной проверкой состояния. В `.45` отключается текущий клиент: KOT разрешает эту команду только когда его можно однозначно определить по списку. Закрытие дополнительно проверяет точный ответ обработчика, который ожидает завершения процесса; PID в таблице Vanessa может сохраняться и после закрытия. Во время запуска или закрытия клиента KOT ожидает ответ до двух минут. При неизвестном результате следует обновить список перед повторным действием.

Смена сеанса во время выбора отменяет действие. Пароли и полные строки подключения не выводятся в меню и публичное состояние сеанса. Attach сам по себе не изменяет подключения.

На указанной выше Vanessa `.45` проверены добавление двух профилей, изменение профиля, подключение, отключение, повторное подключение и закрытие через production adapter/session. Использовалась отдельная копия служебной ИБ. Разбор списка учитывает разделители тысяч в PID. В Extension Development Host проверены вход в меню и сохранение набора через общий мастер Debug.

## Runtime variables

**Control Vanessa → Runtime variables** открывает компактный вид справа с локальным (`$var$`) и сохраняемым (`$$var$$`) контекстом. Значения автоматически загружаются при открытии вида и подключении готового сеанса; для повторного запроса есть Refresh. Закрытие вида и смена сеанса очищают значения. Значения не сохраняются в YAML, настройках или общих логах.

В проверенной Vanessa .45 MCP возвращает текстовое представление без типа. Добавление и изменение задают строку, в том числе пустую; при изменении KOT повторно читает значение и отклоняет устаревшую правку. Удаление доступно для локального контекста. Удаление из сохраняемого контекста отключено: проверенный обработчик .45 игнорирует для этой операции `is_global`.

## Ручное выполнение в редакторе

Точки KOT можно ставить и снимать кликом в левом поле feature и в исполняемой части YAML. Подтверждённые точки используют нативные маркеры VS Code; при ошибке или отмене неподтверждённый маркер убирается. Точки стороннего отладчика сохраняются. Состояние шага показывается цветом всей строки. Ошибка содержит причину в уведомлении и при наведении на строку.

В feature F11 сверяет открытый в Vanessa файл и его содержимое, переоткрывая его только при смене файла. В YAML F11 по умолчанию выполняет обычный шаг напрямую через служебный фрагмент, независимо от наличия сборки. Выбор вхождения не нужен. Для выполнения по карте сборки есть отдельная команда **Execute compiled YAML step** в подменю KOT. Она нужна для вложенных вызовов и конструкций СППР и при повторных вхождениях предлагает точный вариант.

**Vanessa: Run selected steps** выполняет только одно выделение обычных шагов в YAML или feature, с полными таблицами и многострочным текстом. Окружающая подготовка не включается; используются текущие клиенты и переменные Vanessa. Неразрешимые параметры, вложенные вызовы и частично выделенная таблица отклоняются до запуска.

Табы в отступах сгенерированного Gherkin допускаются; при подготовке фрагмента отступ перед шагом нормализуется. Содержимое аргументов и многострочных значений сохраняется. Это не разрешает табы в структурных отступах самого YAML.

## Автоподключение и переменные

Настройка **Vanessa Control: Auto Attach** включена по умолчанию. KOT ищет локальный MCP-сеанс при старте и перед ручным выполнением: проверяет сохранённые локальные адреса, порт `9876` и на Windows loopback-порты процессов 1С. Совместимость подтверждается MCP-handshake и списком инструментов; тесты при поиске не запускаются. К единственному сеансу KOT подключается автоматически, при нескольких предлагает выбор. Удалённый адрес вводится или выбирается явно. Если Vanessa запущена позже расширения, поиск повторяется перед следующей командой выполнения; в подключённом сеансе повторного поиска нет.

**Runtime Variables** находится в правой панели рядом с Test Properties и по умолчанию свёрнута. VS Code сохраняет последующее расположение и раскрытие панели, выбранные пользователем. Значения читаются только для открытой панели или по команде обновления.

## Полный запуск с сохранением Vanessa

В настройке **Run Vanessa: Execution Mode** можно выбрать `mcp`. Кнопки Run в Test Manager и Properties используют обычную подготовку базы и JSON выбранного теста, запускают отдельную управляемую Vanessa и выполняют весь feature вместе с Background. Сохранённый набор клиентов Debug не подменяет подключения теста; авторский JSON не изменяется. Manager остаётся открытым после результата, а **Stop execution** доступен из статуса Vanessa и палитры. Прежний режим `process` сохраняется для несовместимых версий и автоматических запусков с закрытием менеджера. Настроенный шаблон команды имеет приоритет.

После подтверждённой остановки на точке доступно **Continue from breakpoint**. Оно использует текущее состояние Vanessa без повторной загрузки feature; изменение исходника или выбранной строки Vanessa блокирует продолжение. Обычный Stop не сохраняет BSL-стек и не даёт гарантии безопасного продолжения посередине шага: после него следует явно выбрать строку запуска. Отдельный обычный Debug остаётся доступным для работы без MCP.

## Form Explorer через MCP

В Form Explorer кнопка **Source** выбирает MCP или прежний snapshot-мост; автоматический источник предпочитает совместимый MCP-сеанс. Для MCP нужен один подключённый тест-клиент. Дерево и прочитанные данные выбранного элемента используются также существующими подсказками редактора. Ошибка чтения не подменяет форму snapshot другого клиента.

Фоновая проверка отслеживает смену клиента, окна и формы. При неизменившейся форме полное дерево повторно не читается и список не перестраивается. **Refresh** перечитывает структуру внутри текущего окна; он нужен, например, после изменения состава элементов той же формы. Первое чтение большой формы может занимать несколько секунд на стороне Vanessa.

Клик по строке дерева выбирает элемент. Группа сворачивается и разворачивается только отдельной стрелкой слева; стрелка не меняет выбранный элемент. Если выбранный дочерний элемент скрывается внутри закрытой группы, его подробности и шаги остаются открытыми. Выбор строки доступен также через Enter/Space, стрелка — отдельная кнопка с клавиатурным фокусом.

При выборе доступного элемента KOT переводит на него фокус в тест-клиенте, читает значение и автоматически получает **Vanessa steps**. Группы, скрытые элементы и неоднозначные технические имена не активируются; клик или изменение значения не подставляются вместо фокуса. Шаги показаны в текстовом поле только для чтения: можно выделять и копировать отдельные строки. Кнопка **Insert full form checks** находится в блоке **Current form** и вызывает прежнюю генерацию проверок всей формы с выводом в нижнюю панель.

Быстрые переключения объединяются: после задержки 350 мс нужен только последний выбранный элемент. Уже начатый анализ `.45` может продолжать работу в Vanessa; KOT отбрасывает устаревший ответ и не отправляет следующие запросы от старого выбора. Новый анализ ждёт завершения текущего, чтобы не смешать глобальное состояние MCP Vanessa. Это логическая отмена, а не обещание остановки BSL-кода.

Результаты хранятся только в памяти, максимум для 64 элементов одной формы, сеанса и языка. При возврате к элементу сохранённый текст показывается сразу, если контекст и уже известные данные элемента совпадают; он остаётся видимым во время проверки в фоне. Сворачивание и разворачивание блока не вызывает сеть. Повторное событие выбора того же элемента не перезапускает текущую проверку.

Для подтверждения актуальности KOT заново сверяет данные выбранного элемента и Gherkin-состояние формы, которое возвращает Vanessa. Если состояние отсутствует, неоднозначно или изменилось, выполняется полный анализ. При ошибке проверки прежний текст не остаётся показанным как актуальный результат. Refresh, смена формы/клиента/сеанса, языка и источника очищают кеш. `.45` не возвращает дешёвую полную ревизию всех элементов: эта фоновая проверка тоже занимает время и не доказывает неизменность данных, не включённых Vanessa в ответ.

Интерактивный locator и полная выгрузка строк UI-таблицы пока доступны через snapshot-мост: MCP `get_table_data` читает данные БД и не заменяет снимок таблицы формы. [Текущий статус возможностей и ограничений](../../docs/superpowers/audits/2026-10-21-vanessa-capabilities.md) отдельно описывает готовые функции, возможные доработки KOT и необходимые расширения API Vanessa.


## Запись и получение шагов

Установите каретку внутри `ТекстСценария` YAML или сценария feature. **Start recording actions** начинает запись в подключённом клиенте; **Stop recording and insert steps** останавливает её и вставляет шаги у текущей каретки одной операцией Undo. Отдельный временный редактор и обязательное подтверждение черновика не нужны. Если сценарий закрыли или вставка не удалась, последние полученные шаги остаются в памяти и доступны через **Insert captured steps here** или **Copy captured steps**; это не блокирует следующую запись.

Для автоматической вставки останавливайте запись кнопкой **Stop recording and insert steps** в KOT. Если запись уже остановлена средствами Vanessa и MCP возвращает её состояние, KOT сбрасывает свою кнопку без перезагрузки окна и оставляет текст в Vanessa. Повторный Stop в `.45` заново завершает запись и может заменить сгенерированный текст пустым, поэтому KOT его не посылает. Прочитать уже остановленную запись отдельным MCP-запросом в этой версии нельзя. Если признак записи отсутствует, надёжно обнаружить внешнюю остановку также невозможно.

**Generate form checks in Vanessa** и **Get Vanessa steps for current client element** показывают текст в нижней панели **Output → Vanessa generated steps**. Его можно выделить и скопировать обычной командой Copy; **Copy captured steps** копирует весь последний результат, **Insert captured steps here** вставляет его отдельно у каретки. Вторая команда относится к активному элементу клиента тестирования. В Form Explorer доступный элемент активируется при выборе в дереве, а его нативные **Vanessa steps** автоматически появляются в поле только для чтения; старые локальные подсказки в MCP скрыты.

KOT сохраняет язык и текст, возвращённые Vanessa, и исправляет только общий отступ при вставке. Автоматического перевода нет. Перед новым ручным или управляемым запуском KOT учитывает языковые поля Additional Vanessa parameters активного профиля; `gherkinlanguage` / `ЯзыкГенератораGherkin` и `Lang` в runtime JSON согласуются. Если явного языка нет, используется `New scenario language`. Это относится и к запуску собранной feature. Исходный JSON не меняется; выбранные при подготовке база и feature не заменяются повторно путями из профиля. Подключение к уже работающему endpoint не перезагружает его настройки: после изменения языка нужен новый служебный сеанс или изменение настройки в самой Vanessa.

Запросы отображаются в статус-баре, а запись и генерация — также progress-нотификацией. Фоновый опрос состояния не меняет `Ready`. На большой форме из примерно 1700 элементов в проверенном `.45` получение полного Gherkin заняло 32 секунды, полного анализа с подсказками — 42 секунды. Эти запросы выполняются явно и не запускаются при вводе в редакторе. F11 в `.45` также перезагружает feature на стороне Vanessa; проверка совпадения исходника перед выполнением сохраняется.

В Vanessa `.45` нет отдельного MCP-запроса шагов текущего элемента. `get_form_element_data` читает свойства по имени, но не готовые шаги. `get_form_analysis(format=full)` возвращает шаги текущего элемента вместе с проверкой всей формы; `max_depth` ограничивает только дерево в ответе, а `gherkin=false` убирает и нужные шаги. Поэтому эта команда пока зависит от размера формы. Быстрые локальные подсказки выбранной строки Form Explorer остаются отдельной возможностью. [Предложение узкого API и объединения подключений](../../docs/superpowers/specs/2026-10-21-vanessa-connections-and-current-element.md) описывает следующий этап, а не уже доступный инструмент.

В `.45` после загрузки ещё не запускавшейся feature `get_vanessa_automation_state` возвращает сокращённый ответ без признака записи. Команда Start в Vanessa работает как переключатель. По согласованному поведению «Начать новую запись» KOT сначала выполняет Stop, сохраняет возвращённый непустой текст в памяти и затем начинает новую запись — без дополнительного подтверждения. Сохранённый текст доступен через **Insert captured steps here** / **Copy captured steps** даже после вставки новой записи. Это не гарантирует чтение результата записи, уже остановленной в Vanessa: повторный Stop может вернуть пустой результат. Если он нужен, скопируйте его из Vanessa до новой записи. Запускать feature или служебный шаг для этого не требуется. Уже подтверждённая активная запись не переключается повторным Start.

## Диагностика и проверка работающей Vanessa

**Control Vanessa → Diagnostics** открывает панель с состоянием, версиями окружения, клиентами и результатами. **Manager log** и **Client log** явно добавляют журналы регистрации: последние 100 событий в пределах бюджета чтения 500 событий. Журналы не опрашиваются в фоне. Недоступный инструмент или ошибка отдельного раздела не скрывают остальные результаты. Для журнала менеджера нужны права ЖурналРегистрации; для журнала клиента — подключённый тест-клиент с VAExtension 1.40 или новее.

**Search runtime steps** обращается к каталогу именно работающей Vanessa. **Check feature syntax** проверяет сохранённый feature через её `check_syntax`; Vanessa может открыть или перезагрузить этот файл в своём редакторе, но не запускает шаги. Результат привязан к проверенной версии исходника. Эти команды дополняют существующие Library, IntelliSense и локальную проверку Gherkin; отдельный постоянный каталог не создаётся.

**Screenshot** предлагает окно подключённого тест-клиента и показывает PNG в панели. В `.45` ответ содержит только путь к файлу: для локального endpoint KOT передаёт собственный временный путь, читает только его и удаляет временный файл. Случайный путь из ответа не открывается. Для удалённого endpoint нужны ответы с самим изображением; файловые ответы `.45` требуют работы KOT и Vanessa на одном компьютере.

**Export ZIP** сохраняет локальный `report.json` и, по отдельному выбору, снимки. Стандартные строки с паролями, токенами, строками подключения и дополнительными ключами запуска удаляются из текста; изображение не редактируется. Пакет не отправляется по сети. Закрытие панели, **Clear** или смена сеанса очищают её данные. Отмена диагностического чтения не меняет уже подтверждённый результат выполнения шага.

В Form Explorer при источнике MCP кнопка **Windows** выбирает внутреннее окно текущего тест-клиента. KOT проверяет клиента и выбранное окно до и после активации, затем загружает дерево; статические tooltip/data path из существующего индекса проекта используются и в IntelliSense. Ошибка чтения формы не изменяет результат уже выполненного шага.

Выбор таблицы или поля поддерживает многострочное значение и представление из `get_form_element_data`. Ошибка конкретных подробностей оставляет отдельно подтверждённое дерево и подсказки редактора; ошибка генерации шагов также не очищает всю панель. При смене клиента/окна или неподтверждённой идентичности старые данные убираются, даже если одновременно пришёл некорректный ответ.

Form Explorer покрывает не весь MCP API. Он показывает дерево, доступные состояния и значения элементов, нативные/локальные подсказки и выбор окна. Статические source/tooltip/data path берутся из индекса проекта. Значение таблицы из MCP поддержано как многострочный текст; полный табличный snapshot с теми же возможностями, что в прежнем мосте, интерактивный locator и Focus active через MCP пока не подтверждены. Эти функции не подменяются данными таблиц БД или догадками о текущем элементе.


### Синхронизация редактора и результатов

Перед F11 или установкой точки KOT сверяет сохранённый source с редактором Vanessa. Чистая устаревшая копия перезагружается по команде с сохранением чужих точек; несохранённая копия Vanessa остаётся защищённой. Открытие вкладки VS Code само по себе не сбрасывает текущий прогон.

Остановка записи в самой Vanessa при доступном признаке записи сбрасывает локальное состояние KOT, сохраняя результат в Vanessa. Автоматическая вставка такой записи требует отдельного read-only API, отсутствующего в `.45`; повторный Stop не используется для чтения. До первого выполнения feature признак записи также может отсутствовать.

Подтверждённые результаты отдельных шагов сохраняют цвета нескольких строк. Итоговые строки сопоставляются по точному уникальному тексту; совпадающие имена, пропущенные строки и содержимое docstring не окрашиваются по догадке. Снимок, запрошенный до запуска, не добавляет результаты в новый прогон.

### Form Explorer: расширенные инструменты MCP

Кнопка **MCP form tools** открывает инструменты, объявленные подключённой версией: анализ и поиск элементов, подробности, действия/цепочки действий, окна, командный интерфейс, запись, сохранение табличного документа и связанные чтения данных. Для каждого инструмента доступны типизированные поля из его схемы; **Run form tool** появляется только после заполнения обязательных параметров. Отмена ничего не выполняет. Поля подключения и содержимое результатов не сохраняются в проект; текст результата выводится в **Output → Vanessa form tools**. `get_table_data` читает данные БД, а не все строки UI-таблицы.

В режиме MCP прежние локальные Suggested steps скрыты. **Vanessa steps** получает подсказки автоматически после активации выбранного элемента в тест-клиенте. После смены строки прежний текст сразу скрывается; поздний ответ другого выбора не показывается. Отдельные кнопки получения и включения автоматического режима удалены. Правила очереди и кеша описаны в разделе Form Explorer выше.

Для обычной команды генерации проверок формы KOT компенсирует пропущенный в MCP `.45` вызов перевода: использует только однозначные пары шаблонов выбранного каталога Vanessa. Аргументы, таблицы, docstrings и неизвестные шаги не переводятся. Если однозначного шаблона нет, исходный текст сохраняется с предупреждением. Записанные действия по-прежнему вставляются на языке Vanessa без перевода. Прямой вызов инструмента через **MCP form tools** показывает его исходный ответ.

Это доступ к проверенному API, а не обещание полного соответствия всем командам UI Vanessa: отдельного MCP-эквивалента «получить проверку текущего элемента формы в виде шагов» в `.45` нет. API чтения активного элемента, узких подсказок и полного UI snapshot тоже требует расширения. Причины и отдельные тексты для ручного обращения к разработчикам перечислены в [черновиках issue](../../docs/superpowers/issues/2026-10-21-vanessa-mcp/README.md).
