# Блок: Test Manager

## Задача блока

Test Manager выбирает YAML-сценарии и процессы для компиляции, запускает готовые тесты и показывает их состояние. Самостоятельные feature находятся в отдельной секции и запускаются без компиляции YAML.

## Секции и действия

- **Main scenarios** — главные сценарии с настройками запуска.
- **Processes** — процессы СППР, включая вызовы вложенных процессов.
- **Standalone features** — самостоятельные feature из каталога тестов активного профиля.

В заголовках доступны создание теста или группы, поиск, раскрытие дерева и меню действий. Кнопка `+` группы предлагает главный сценарий или процесс. Создание вложенного и экспортного сценария, самостоятельной feature и пользовательского шага доступно в меню создания. Избранное находится в Library, отдельно от состава сборки.

Чекбоксы сценариев и групп определяют состав компиляции и сохраняются локально по URI. Одноимённые сценарии в разных папках имеют отдельные выбор, результаты и артефакты. Старые `Default` и вкладка Defaults не используются.

## Группы и порядок

Группы общие для Test Manager и Library. Их определения хранятся в `.kot/groups.yml`, принадлежность и порядок тестов — в соседних `*.kot.yml`. Добавьте эти файлы в Git для совместной работы.

По умолчанию группы идут по алфавиту. Перестановка групп перетаскиванием сохраняет только личное представление, отдельно для проекта и секции. Перестановка тестов внутри группы и перенос в другую группу меняют общие метаданные без полного пересканирования YAML.

**Ungrouped / Без группы** не требует создания в каталоге. Для существующего теста выберите **Change group → Ungrouped** в контекстном меню или перетащите его в пустую Ungrouped. Переименование обычной группы обновляет общий каталог, сохраняя её идентификатор.

## Сборка

**Compile** запускает сборку выбранных главных сценариев и процессов. В меню сборки переключается активный профиль Compilation and run parameters; там же доступны дополнительные режимы. FirstLaunch и режим учёта показываются при включённых возможностях Drive.

Перед запуском проверяются обязательные пути, настройки баз, значения параметров и отборы. Части сборки получают отдельные артефакты и поддерживают отмену. При ошибке автоматически открывается **Compiler build report** со ссылками на исходный YAML и строку ошибки.

`SplitFeatureFiles` относится к доработке обработки Drive. Подробности параметров и различий стокового компилятора — в [Parameters Manager](parameters-manager.md) и [параметрах процессов](compiler-process-parameters.md).

## Поиск и связи

Поиск учитывает имена, коды, описания и пути вложений. Фильтры ограничивают список всеми, собранными или запущенными тестами; скрытый тест не меняет сохранённый выбор сборки.

Открытый сценарий и его зависимости подсвечиваются независимо от чекбоксов. Учитываются прямые и транзитивные вызовы, процессы, вложенные и экспортные сценарии, а также самостоятельные feature. Подсветку и режим «Только связанные» можно переключать отдельно от Library.

## Запуск, статусы и файлы

Строка теста предлагает запуск, открытие исходника и действия с артефактами; контекстное меню — **Open test properties**, настройки запуска, built/combined JSON, переименование, смену группы и удаление. Сгенерированный feature и вложения раскрываются под тестом. Для неуспешного шага доступен переход в feature.

- `running` — выполняется тест, доступны прогресс и live-log.
- `passed` / `failed` — сохранён результат выполнения.
- `stale` — связанные исходники изменились после сборки.

Состояние привязано к URI исходника. Артефакты внешней сборки обнаруживаются без Reload Window. Запуск YAML-теста использует отдельный combined JSON; исходный JSON компилятора остаётся доступен для просмотра. Состояние сборки, запуска и операции с базой определяет доступность соответствующих кнопок.

Для самостоятельной feature выбирается существующий JSON либо генерируется новый из профиля. После объединения параметров запуск ограничивается точным выбранным feature-файлом. Подробности — в [самостоятельных feature](standalone-features.md).

Запуск по умолчанию использует подключённый или подготовленный менеджер тестирования Vanessa через MCP и оставляет его открытым после выполнения. Доступны запуск с выбранного шага, пошаговое выполнение, точки останова, остановка и продолжение. Если параметры текущего сеанса отличаются от параметров теста, KOT предлагает выбрать способ запуска. Автоматический запуск отдельным процессом остаётся отдельным режимом настройки. [Управление Vanessa](vanessa-control.md) описывает подготовку, команды и ограничения конкретной версии.

## AI и дополнительные инструменты

Меню **Thinking** сохраняет генерацию и просмотр AI-отчёта по diff конфигурации и AI-ревью изменённых тестов. Анализ учитывает основную ветку и опциональный User Story.

Меню дополнительных действий открывает параметры сборки, платформы 1С и настройки расширения, перезагружает тесты и библиотеку шагов, запускает или отменяет исправление сценариев. Полные Library, Infobase Manager и Form Explorer доступны из соответствующих команд и панелей.

## Связанные настройки

| Настройка | Назначение |
|---|---|
| `kotTestToolkit.phaseSwitcher.highlightAffectedMainScenarios` | Подсветка связанных тестов |
| `kotTestToolkit.phaseSwitcher.autoAddNewScenariosToFavorites` | Добавление новых сценариев в общее избранное Library |
| `kotTestToolkit.assembleScript.showDriveFeatures` | Команды FirstLaunch и режимы Drive |

Свойства и вложения редактируются в [Test Properties](scenario-properties-editor.md); формат общих данных и миграция описаны в [библиотеке проекта](shared-project-library.md).
