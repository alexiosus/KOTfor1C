# Состояния тестов и актуальность сборки

Состояние исходника, состояние компиляции и состояние выполнения не взаимозаменяемы. Один тест может быть сохранён, но его предыдущая сборка уже устарела.

## Когда нужна новая компиляция

KOT помечает результат устаревшим после изменения значимых исходников и зависимостей: текста YAML, парного `scen.feature`, вложенного сценария, экспортной библиотеки или структуры после преобразования.

Общее имя выходной feature не делает её актуальной. Изменение runtime-библиотеки также важно, даже если сам текст собранной feature остался прежним.

| Ситуация | Что делать |
|---|---|
| Исходник не сохранён | Сохранить документы |
| Сборка отсутствует | Скомпилировать главный тест |
| Результат устарел | Пересобрать или осознанно выбрать запуск прежнего результата |
| Компиляция завершилась ошибкой | Открыть отчёт и исправить исходник/профиль |
| Выполнение упало | Посмотреть ошибку строки, контекст клиента и журналы |

Если компилятор объединил несколько сценариев в одну feature, изменение одного источника затрагивает общий результат. Запуск такой строки исполняет общий файл.

## Если список выглядит неверно

Проверьте активный профиль, корни исходников, фильтры и отметки набора. Затем используйте **Обновить**. Перезагрузка окна не должна быть первым способом обновить каталог после обычного сохранения.

Личные фильтры и раскрытие групп могут скрывать существующий тест. Вложенный процесс без настройки запуска не является самостоятельным главным тестом.

Общие группы и описания хранятся в файлах проекта, а кеш и личное представление — отдельно. [Общие данные](shared-project-library.md) · [Техническое устройство](../technical/architecture.md).
