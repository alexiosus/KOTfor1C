# Свойства YAML и feature рядом с редактором

Откройте YAML сценария или процесса обычным способом — из Explorer, Test Manager или Library. Свойства теста появятся справа автоматически; служебные секции исходного YAML сворачиваются при включённом `KOT → Editor: Auto Collapse On Open` (по умолчанию включено). Автоматическое открытие свойств также работает для настроек запуска и соседнего `*.kot.yml`.

Режим включён по умолчанию. Чтобы открывать свойства вручную, отключите `KOT → Editor: Auto Open Test Properties` (`kotTestToolkit.editor.autoOpenTestProperties`). Команда **KOT — Открыть свойства теста**, кнопка с шестерёнкой в заголовке YAML и действие **«Редактировать сценарий и свойства»** над первой строкой (если включены кнопки YAML) доступны. Панель открывается без перевода фокуса из редактора.

В редакторе остаётся исходный YAML. Вся шапка от первой строки до строки перед `ТекстСценария` сворачивается одним диапазоном FoldingRangeProvider; текст остаётся раскрытым. У процесса аналогичная шапка заканчивается перед `ШагиПроцесса`. Служебные разделы после тела сохраняют отдельное сворачивание. Маркеры и комментарии в исходный YAML не добавляются. Любой раздел можно раскрыть обычным способом VS Code; действие **«Свернуть служебные разделы»** в панели сворачивает их снова.

**«Свойства теста»** открываются во вторичной боковой панели справа. При переключении вкладки она показывает свойства активного сценария, процесса или feature. Для настроек запуска и соседнего `*.kot.yml` панель находит исходник и показывает связанные поля. Фокус внутри панели сохраняет текущий тест. Для других файлов показывается предложение открыть сценарий. Кнопка **«Закрепить тест»** позволяет временно отключить следование за вкладками: активное закрепление видно по фону и изменённой иконке.

## Поля панели

- Шапка: имя, код, проект, системная функция и остальные поля. Имя и код меняются в текстовых полях независимо друг от друга, с обновлением ссылок в вызывающих сценариях, процессах и настройках. Изменение имени сохраняет пути. При изменении кода папка отдельного теста и связанные файлы с прежним кодом в имени переименовываются; имена пользовательских вариантов настроек сохраняются. Общие каталоги и корни проекта не переименовываются. Если целевой путь занят, изменение отменяется. Функция системы выбирается из списка; имя и UID сохраняются вместе. Технические UID скрыты в форме и остаются в YAML.
- Параметры сценария: каждый параметр по умолчанию свёрнут. В строке видны имя, значение по умолчанию и число использований; внутри — все редактируемые поля, включая многострочные значения таблиц. Флаги параметров показывают только «Да» и «Нет». Новые параметры предлагают штатные типы компилятора: Строка, Число, Дата, Таблица; существующие пользовательские типы сохраняются. Раскрываемый блок «Варианты сборки» появляется при нескольких сочетаниях. Он учитывает параметры выбранных настроек запуска, их типы и значения, а также недостающие defaults из сценария. Например, `Currency: EUR;USD` и `Amount: 10;20;30` дают шесть вариантов. Таблица остаётся одним значением. При превышении лимита 100 комбинаций предупреждение видно и при свёрнутом превью. Превью не является результатом выполнения; для процессов такой перебор компилятор не реализует.
- Вложенные сценарии: декларации из `ВложенныеСценарии`, число прямых использований в тексте и переход к исходнику. Состав деклараций определяется текстом: при автозаполнении структурные кнопки скрыты, при отключённом автозаполнении доступна одна кнопка «Заполнить из текста». Это относится и к параметрам сценария; их значения и переименование доступны в обоих режимах. Номера строк в параметрах и тегах скрыты, поскольку определяются порядком. Вызовы и аргументы редактируются в `ТекстСценария`; порядок деклараций не меняет выполнение.
- Отдельная вкладка «Настройки запуска»: база и профиль выбираются нативными выпадающими списками. При смене базы вместе обновляются её имя, идентификатор и подходящий профиль. Здесь же находятся параметры запуска, `ПараметрыТеста` и `ТегиТеста`, кнопки открытия YAML настроек и копирования пути. Если настроек несколько, выберите нужный файл прямо в панели. Связь определяется по UID и проверяется перед правкой и сохранением.
- Теги редактируются прямо в строке, без отдельного поля имени и кнопок перемещения. Удаление появляется при наведении или фокусе. У вложенных сценариев переход к исходнику также появляется при наведении, перед счётчиком; длинное название прокручивается при наведении.
- Метаданные KOT: группа и категория выбираются из списков с пунктом «Создать…». Кнопка в заголовке раздела открывает метаданные; рядом с описанием — генерирует его с помощью AI. Группа определяет расположение в Test Manager и Library, категория служит отдельной классификацией и фильтром. Они независимы: смена категории не меняет группу.
- Над шапкой расположены две кнопки: «Открыть YAML» и «Скопировать путь»; сам путь скрыт. Верхний заголовок переносится на несколько строк. Длинные подписи списков, значения параметров и подписи полей показываются с фейдом с обеих сторон и прокручиваются при наведении; до появления hover-кнопок текст занимает их место. Редактирование остаётся в обычных нативных полях.

Для процесса панель показывает **шаги процесса**: сценарии и подпроцессы, исполнителей и параметры шага. Их можно добавлять, удалять и переставлять; порядок шагов влияет на выполнение.

Каждый шаг процесса — свёрнутая группа с `Наименование` в заголовке. Внутри находятся его редактируемые поля и параметры. Порядок меняется перетаскиванием; стрелок вверх/вниз нет. Кнопки открытия и удаления появляются при наведении или клавиатурном фокусе. Сворачивание служебных секций доступно через иконку рядом с булавкой.

Вкладка **«Файлы»** показывает вложения из папки `files` рядом с исходным YAML, включая подпапки. Перетаскивание файла из списка в редактор передаёт только его название, например `Data.csv`; файл остаётся во вложениях. Перетаскивание внешних файлов в любую область панели копирует их во вложения. Поддерживаются системный файловый менеджер и Explorer VS Code; при совпадении имени предлагаются замена, копия или пропуск. Переключение теста отменяет незавершённые загрузки. Вложения можно открыть, переименовать или удалить кнопками при наведении. Поиск в Test Manager и обеих Library учитывает имена и относительные пути вложений, включая ещё не собранные тесты.

В заголовке раздела есть кнопка «Добавить файлы» с обычным выбором файлов; у вложения — «Вставить имя файла» в позицию текущего редактора. Они также позволяют работать при известной [регрессии drag-and-drop между Explorer и webview VS Code](https://github.com/microsoft/vscode/issues/339036). При вставке сохраняются Undo и обычное автосохранение редактора.

Разделы раскрываются плавно; при системной настройке уменьшения движения — сразу. Отступы вкладок одинаковы, вложенные параметры сохраняют дополнительный отступ. Выбранные настройки, введённые поля и состояние разделов следуют за тестом при переименовании папки.

Новые штатные шаблоны и сохранение YAML не добавляют `KOTМетаданные`: эти данные находятся в соседнем `*.kot.yml`. Legacy-блоки импортируются при первом сканировании и удаляются после успешного сохранения метаданных и проверки исходника; несохранённые изменения не очищаются.

## Сохранение

Текст и поля редактируют обычные документы VS Code. Включённое **Auto Save** сохраняет YAML и применённые правки панели штатным способом. Поле панели применяется при завершении ввода или потере фокуса. **Ctrl+S / Cmd+S** сохраняет активный документ; кнопка **«Сохранить тест»** сначала применяет введённые поля, затем сохраняет исходник, изменённые настройки и метаданные текущего теста. Неудачное сохранение оставляет документ несохранённым.

Undo, автодополнение, hover, переходы, вставка из Library и диагностика работают непосредственно в исходном YAML. Комментарии и остальные поля сохраняются. Для конфликтующей или устаревшей правки панель показывает ошибку; сообщение остаётся до закрытия, успешного повторения правки или смены теста. Обычное обновление панели его не убирает. При смене имени или кода сохраняются BOM и переводы строк исходных файлов.

Переименование параметра меняет его объявление и точные ссылки `[Имя]` в теле текущего сценария, включая таблицы и многострочные значения. Комментарии, экранированные скобки и похожие имена сохраняются. Аргументы в вызывающих сценариях и настройках запуска не переименовываются автоматически. Счётчик показывает число ссылок в собственном тексте, без раскрытия вложенных вызовов.

Файлы `.kot/groups.yml`, `.kot/property-catalogs.yml` и соседние `*.kot.yml` передаются через Git; подробности — в [общей библиотеке проекта](./shared-project-library.md). Отмена создания элемента не сохраняет введённые ранее изменения метаданных.

Для размещения во вторичной боковой панели требуется [VS Code 1.106](https://code.visualstudio.com/updates/v1_106#_view-containers-in-secondary-side-bar) или новее.

## Поля СППР

В предоставленной обработке СППР `Проект` связан со справочником проектов, а `ПрофильПользователя` — со справочником профилей пользователей. При сборке из YAML эти поля читаются из шапки как строки; отдельные KOT-справочники с дополнительными UID для них не обязательны. `УровеньОтчета1` и `УровеньОтчета2` передаются в `#report.feature` и `#report.story` — это группировка отчёта, независимая от групп Test Manager.

В полях объектов есть нативный список с пунктом «Создать…». Проекты, уровни отчёта и категории хранятся в общем каталоге `.kot/property-catalogs.yml`; список также учитывает уже использованные значения YAML, метаданных и настройки создания сценариев. В исходный YAML сохраняется обычная строка СППР, без дополнительных UID этих каталогов.

Функции системы тоже хранятся в `.kot/property-catalogs.yml`, в разделе `systemFunctions`: выбирается пара имени и `UIDФункцияСистемы`. Если раздела ещё нет, KOT однократно переносит функции из старой настройки `newScenarioDefaults.systemFunctions`, сохраняя UID. После этого каталог проекта имеет приоритет, а создание, переименование, изменение UID, выбор значения по умолчанию и удаление работают с общим YAML. Параметры создания и менеджер функций используют тот же каталог; первая запись считается значением по умолчанию. Добавьте файл в Git, чтобы другие тестировщики получили эти функции вместе с проектом. Если открытого сценария нет и проектов несколько, менеджер предлагает выбор проекта, включая внешние каталоги тестов.

Базы и профили берутся из файла `ModelDBSettings` текущих настроек сборки (по умолчанию `.vscode/kot-runtime/bases.yaml`). Относительный путь разрешается в рабочей папке, которой принадлежит исходник, в том числе при нескольких папках workspace. В шапке сценария доступны профили всех настроенных баз, в настройках запуска — только выбранной базы. Создание базы или профиля использует обычный мастер KOT; логины и пароли не передаются в панель свойств.

У вложенного сценария собственная шапка: при создании KOT берёт проект, функцию, профиль и уровни отчёта из настроек создания и ответов мастера (`nestedReportLevel2` для второго уровня). Автоматического наследования этих полей от любого вызывающего главного сценария нет — вложенный сценарий может вызываться из нескольких тестов. Заголовок итогового feature и уровни отчёта задаёт верхний сценарий или процесс. Профиль в настройках запуска имеет приоритет над профилем его исходника; шаги процесса могут переключать исполнителя. Указанный профиль должен соответствовать пользователю выбранной эталонной базы.

Переключение вкладки редактора сразу показывает модель её исходного YAML. Поиск связанных настроек и чтение групп выполняются затем; устаревшая загрузка от предыдущего исходника отбрасывается. **Pin test / Закрепить тест** временно отключает следование за вкладками; повторное нажатие возвращает его. Метаданные KOT расположены под шапкой, теги сценария — после вложенных сценариев.

Вкладка **«Файлы»** показывает количество вложений в заголовке. Перетаскивание внешних файлов принимается во всей области панели, независимо от выбранной вкладки; из списка в редактор вставляется только имя файла. Для недостающего поля шапки сценария `НеобратимоМеняетДанные` доступен пустой выбор/Да/Нет: значение «Нет» разрешает компилятору включать сценарий в общий feature при `SeveralScenariosInOneFile`, но не проставляется автоматически. `Ответственный` сценария доступен в шапке. `Выключена` предлагается в настройках сценария; для настроек процесса предоставленная ветка компилятора этот флаг не учитывает.

Открытие YAML и копирование пути не запускают сохранение, не показывают «Применение изменений» и не перезагружают связанные настройки. Переход к уже связанному открытому test.yaml использует загруженную модель; реальные изменения исходников и настроек по-прежнему обновляют её.

Кнопки Open YAML / Copy path и Open folder / Add files на вкладке Files имеют подписи и одинаковое выравнивание. Pin и Fold находятся рядом с Save test, статус — рядом с типом под названием. В текстовых строках левый фейд появляется после начала прокрутки; нативные выпадающие списки используют обычное обрезание. Открытие менеджера баз, Form Explorer или другой редакторной webview очищает незакреплённую панель свойств. Фокус самой боковой панели её не очищает; Pin сохраняет выбранный тест.

В контекстном меню YAML-теста в Test Manager и обеих Library доступно **Open test properties / Открыть свойства теста**. Пункт привязан к выбранному исходнику, даже если другой YAML открыт в редакторе. Для native standalone feature YAML-свойства не предлагаются.

## Feature

Для `.feature` та же панель показывает заголовок, описание, теги и список сценариев. Поля изменяют обычный файл редактора: работают Undo, Save и Auto Save. Кнопка **«+»** в заголовке **Scenarios** предлагает обычный сценарий или структуру сценария, спрашивает название и вставляет блок на языке файла, с курсором на первом шаге. Из списка можно открыть или переименовать сценарий; переименование экспортного сценария обновляет его вызовы штатной командой расширения. Действия добавляют контекст, переменные, импорты, теги, структуру сценария и примеры. Для самостоятельного теста также доступны группа и создание группы. JSON запуска выбирается, создаётся и открывается в отдельной сворачиваемой секции **Vanessa parameters (JSON)**. В шапке кнопки идут в порядке **Save → Run → избранное → булавка**. Действия добавления блоков собраны в секции **Feature blocks**. Для собранного feature панель показывает свойства исходного YAML, если источник однозначно известен.

Звезда рядом с сохранением добавляет тест в общее избранное Library и Test Manager. В файле с несколькими экспортными определениями выбирайте конкретное определение в Library. Булавка закрепляет текущий документ и для feature.

## Команды редактора

Команды контекстного меню собраны в подменю **KOT** с короткими названиями; оно расположено в навигационном блоке перед **Peek** и **Find All References**. Для обычного перехода к определению используйте **F12**. Прежняя команда `KOT - Open scenario` и её сочетание клавиш сохранены для совместимости; в YAML она больше не дублирует F12 в меню. В feature команда открытия охватывающего вложенного сценария также работает на шагах внутри его развёрнутого тела.

Кнопки над строками редактора включаются отдельно: `kotTestToolkit.editor.showYamlActionButtons` и `kotTestToolkit.editor.showFeatureActionButtons`; обе по умолчанию выключены. Команда переключения кнопок меняет настройку для активного формата. Пока отдельное значение не задано, действует прежняя общая `kotTestToolkit.editor.showActionButtons`. Для CodeLens должна быть включена стандартная настройка `editor.codeLens`. Свойства доступны через значок в заголовке редактора и меню **KOT**, независимо от кнопок над строками.
