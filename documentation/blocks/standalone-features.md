# Независимые `.feature`-файлы

Группы хранятся в `.kot/groups.yml`, а принадлежность к группе и порядок — в `<имя>.feature.kot.yml` рядом с feature. Эти файлы [общей библиотеки проекта](./shared-project-library.md) передаются через Git. Выбранные локальные JSON запуска и личное состояние панели сохраняются отдельно в VS Code.

Test Manager и Library показывают самостоятельные feature из настроенного каталога тестов в отдельном разделе. Каталог может находиться вне рабочего пространства. Экспортные библиотеки и связанные с главными сценариями результаты сборки исключаются из этого раздела.

Группы и порядок элементов общие для Test Manager, боковой и полноразмерной Library и сохраняются в файлах проекта. Порядок самих групп — личная настройка; по умолчанию они идут по алфавиту. В обеих библиотеках feature входят в общее дерево, поиск и избранное. Перетаскивайте feature внутри группы или между группами; доступны также команды контекстного меню, `Alt+↑` / `Alt+↓` для порядка и `Ctrl+Shift+M` (`Cmd+Shift+M` на macOS) для выбора группы. Пустые группы сохраняются, а удаление группы возвращает её файлы в «Без группы».

В Test Manager доступны запуск, статус, открытие и просмотр журнала. При запуске предлагается JSON с тем же именем рядом с feature или ранее выбранный JSON; можно выбрать другой файл или сформировать его из профиля. Одноимённые feature в разных папках имеют отдельные результаты и журналы.

Подсветка связей и режим «Только связанные» в Test Manager и боковой Library учитывают самостоятельные feature. Откройте экспортный сценарий, чтобы увидеть вызывающие его фичи и их группы; при открытии фичи в Library подсвечиваются используемые экспортные сценарии. После сохранения изменений в шагах связи обновляются автоматически.

## Переименование

В контекстном меню строки feature доступны два отдельных действия: **Изменить название feature** меняет заголовок `Feature` / `Функционал`, а **Переименовать файл feature** меняет имя `.feature`-файла. Клавиша `F2` открывает изменение названия. Действия доступны в Test Manager и обеих Library. В Library контекстное меню также содержит действия с панели наведения: избранное, копирование и открытие, а у вставляемых шагов и сценариев — вставку в редактор. Кнопка `…` остаётся у групп. При смене имени файла сохраняются группа, порядок и выбранный JSON запуска; существующий файл не перезаписывается.

Для главных, вложенных и экспортных сценариев Library предлагает **Переименовать сценарий** в меню строки и по `F2`. Переименование главного и вложенного сценария использует те же операции, что Test Manager и редактор. У экспортного сценария обновляются объявление, пример вызова и вызовы в feature и YAML текущего проекта и профиля; фактические значения аргументов сохраняются. Имена и порядок параметров экспортного сценария при переименовании менять нельзя. Сохраните открытые изменённые файлы перед операцией. Ошибка поиска ссылок или неоднозначность новых вызовов отменяет операцию до записи файлов.

В обеих Library группы главных сценариев также имеют действие **Переименовать группу** в меню `…`, контекстном меню и по `F2`. Оно использует ту же команду, что Test Manager, и обновляет название общей группы в `.kot/groups.yml`; метаданные тестов продолжают ссылаться на её стабильный UID.

## Создание

Команда создания фичи запрашивает название функционала, название первого сценария и путь сохранения внутри настроенного каталога тестов. Для тегов доступны обычная фича и фича с `@Draft`. Существующий `.feature`-файл команда не перезаписывает. Созданный файл открывается в редакторе.

Язык стандартного шаблона задаётся настройкой `kotTestToolkit.editor.newScenarioLanguage` (`en` или `ru`). Шаблоны повторяют предоставленные образцы Vanessa: `#language`, `@tree`, описание роли и результата, `Background` / `Контекст` с подключением TestClient и первый сценарий. Заполните оставшиеся подсказки `<Role>`, `<functional description>`, `<business effect>` или русские аналоги.

Дополнительные возможности добавляются inline-кнопками CodeLens в редакторе `.feature`. Кнопки работают и в самостоятельных фичах, и в экспортных библиотеках. Кнопки по умолчанию выключены: для отображения включите `kotTestToolkit.editor.showFeatureActionButtons` для feature или `kotTestToolkit.editor.showYamlActionButtons` для YAML и стандартную настройку VS Code `editor.codeLens`.

## Inline-действия в редакторе

- У заголовка фичи: **+ Описание**, **+ Контекст**, **+ Переменные**, **+ Теги**, **+ @tree**. Уже существующие описание и секции повторно не предлагаются. Описание содержит редактируемые поля роли, цели и результата; контекст — шаг подключения TestClient.
- У секции переменных: **+ Переменная / импорт**. Доступны простое значение, вычисление `{выражение}`, вычисление на сервере `{!выражение}`, многострочный текст, таблица переменных и импорт другого `.feature`. После вставки заполните поля и переходите между ними клавишей `Tab`. Названия столбцов таблицы переменных повторяют официальный пример Vanessa.
- У обычного сценария: **Структура сценария** преобразует только выбранный сценарий и добавляет таблицу примеров. Столбцы выводятся из параметров `<Имя>` в его шагах и аргументах. Если параметров ещё нет, вставляется редактируемая заготовка столбца; добавьте соответствующий `<Параметр>` в шаг.
- У структуры сценария: **+ Примеры** добавляет ещё одну таблицу. У любого сценария **+ Теги** добавляет теги именно к нему. Можно использовать собственные теги с точками, двоеточиями и `=`, например `@team.sales @priority:high @issue=123`; повторяющиеся теги не добавляются.
- У самого шага: введите `@` на строке перед ним, чтобы выбрать в IntelliSense `@screenshot`, `@recordvideo`, `@StopRecordVideo` или `@StartRecordVideo`. Можно также вызвать IntelliSense вручную (`Ctrl+Space`) прямо на строке шага: выбранный тег вставится перед ним с тем же отступом, а текст шага сохранится. Уже добавленные к этому шагу теги повторно не предлагаются. Те же действия доступны через лампочку быстрых действий на строке шага; кнопки выбора шага в шапке сценария больше нет.

Вставки сохраняют BOM, окончания строк, соседние сценарии и их теги. Отмена выбора оставляет файл без изменений; при изменении файла во время диалога действие нужно вызвать повторно. Изменения в редакторе можно отменить стандартной командой Undo. Секция переменных, её многострочные значения и теги скриншотов/видео учитываются при проверке синтаксиса Vanessa.

## IntelliSense для тегов и автоинструкций

Подсказки аннотаций работают в `.feature` и в блоке `ТекстСценария` YAML-сценария. Введите `@` перед заголовком или шагом, `#` / `#[` для директив автоинструкции, либо вызовите IntelliSense вручную (`Ctrl+Space`) на нужной строке. Вставка на строке заголовка или шага добавляет аннотацию перед ней и сохраняет исходный текст. Теги, уже прикреплённые к заголовку, шагу или группе, повторно не предлагаются.

| Место | Подсказки |
|---|---|
| Перед заголовком feature | `@tree`, `@ExportScenarios`, `@Draft`, пользовательские теги проекта, `#[autodoc.ignore.featureslide]`, `#[autodoc.ignore.finalslide]` |
| Перед заголовком сценария | `@ExportScenarios`, `@Draft`, пользовательские теги проекта, `#[autodoc.ignore.scenarioslide]` |
| Перед шагом или группой | `@screenshot`, `@recordvideo`, `@StopRecordVideo`, `@StartRecordVideo`, `#[autodoc.ignorestep]`, `#[autodoc.mute]`, `#[autodoc.donotscale]`, `#[autodoc.text]` |
| Перед группой `*` | Дополнительно `#[autodoc.groupsteps]` |
| После заголовка экспортного сценария, до его шагов | `@steptype:`, `@description:`, `@exampleofuse:` и русские варианты `@типшага:`, `@описание:`, `@примериспользования:` |

У директив `autodoc.text`, `autodoc.groupsteps` и метаданных экспорта есть редактируемое поле: после вставки заполните его и нажмите `Tab`. Описания в IntelliSense объясняют назначение аннотаций. `autodoc.ignorestep` сохраняет выполнение шага, но исключает его из автоинструкции; `mute` отключает озвучку, `donotscale` сохраняет исходную длительность, `text` задаёт текст, `groupsteps` объединяет группу в один шаг инструкции. Для использования директив включите соответствующий режим автоинструкций Vanessa.

Пользовательские теги собираются из заголовков feature и сценариев в каталоге самостоятельных фич и настроенных локальных feature-библиотеках. Учитываются несохранённые изменения открытых файлов; комментарии, текстовые блоки, таблицы и метаданные экспорта не превращаются в теги. В YAML подсказки ограничены `ТекстСценария` и не изменяют параметры или служебные поля. Теги скриншотов и видео доступны и через лампочку на строке шага или группы в YAML.

`@Draft` сам по себе не запрещает запуск: добавьте `Draft` в `ignoretags` JSON запуска. Действие пользовательских тегов определяется фильтрами запуска и настройками Vanessa.

## Пользовательский шаблон

`kotTestToolkit.editor.newFeatureTemplatePath` задаёт абсолютный путь или путь относительно рабочего пространства. Поддерживается `${workspaceFolder}`. Пустая настройка использует стандартный шаблон. Ошибка чтения или проверки шаблона показывается до создания файла.

| Плейсхолдер | Значение |
|---|---|
| `{{featureTitle}}` | Введённое название фичи |
| `{{scenarioTitle}}` | Введённое название первого сценария |
| `{{language}}` | Значение `editor.newScenarioLanguage` |

Сохраняется совместимость с оригинальными маркерами Vanessa: `<description features>`, `<description of the scenario>`, `<описание фичи>`, `<описание сценария>`. Маркеры названий должны находиться в объявлениях функционала и сценария. Поддерживаются обычный `Scenario` / `Сценарий` и `Scenario Outline` / `Scenario Template` / `Структура сценария` / `Шаблон сценария`; таблицу `Examples` / `Примеры` задайте в пользовательском шаблоне. Неизвестные плейсхолдеры в двойных фигурных скобках отклоняются. Названия должны быть непустыми и занимать одну строку. Кодировка — UTF-8; BOM и окончания строк пользовательского шаблона сохраняются.

Пример английского шаблона:

```gherkin
#language: en
@tree

Feature: {{featureTitle}}

As <Role>
I want <functional description>
To <business effect>

Background:
    Given I launch TestClient opening script or connect the existing one

Scenario: {{scenarioTitle}}
```

Дополнительное описание, собственные теги, секцию переменных Vanessa и другие поддерживаемые секции Gherkin можно добавить в шаблон. Служебная шапка YAML для независимой фичи не требуется. Тег `@Draft` используется как отметка черновика; исключение таких сценариев зависит от настроенного `ignoretags`.

## Что можно добавить в feature

Это секции и теги Gherkin, а не произвольные поля YAML. В официальных уроках Vanessa описаны следующие варианты:

| Элемент | Назначение |
|---|---|
| `#language: ru` / `en` | Язык ключевых слов |
| Описание после заголовка | Роль, цель и ожидаемый результат |
| `Контекст` / `Background` | Общие подготовительные шаги сценариев |
| `Структура сценария` / `Scenario Outline` и `Примеры` / `Examples` | Повторение сценария с параметрами `<Имя>` из таблицы примеров |
| `Переменные` / `Variables` | Простые, вычисляемые, многострочные и табличные значения; импорт из других файлов |
| `@tree` | Группы шагов |
| `@screenshot` | Снимки перед и после следующего шага при включённой настройке Vanessa |
| `@recordvideo`, `@StopRecordVideo`, `@StartRecordVideo` | Запись видео и управление фрагментами автоинструкции; требуется ffmpeg |
| Собственные теги | Отбор сценариев через JSON запуска |

Возможности и синтаксис описаны в официальных уроках [структуры сценария](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/MainHelp/1.2.043.1/Глава03/КакУстроенFeatureФайлСекцияСтруктураСценария.MD), [переменных](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/MainHelp/1.2.043.1/Глава03/КакУстроенFeatureФайлСекцияПеременныеПростые.MD), [групп шагов](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/MainHelp/1.2.043.1/Глава03/ГруппыШагов.MD), [скриншотов](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/MainHelp/1.2.043.1/Глава03/ТегСнятияСкриншотов.MD) и [видеозаписи](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/MainHelp/1.2.043.1/Глава03/ТегЗаписиВидеоВыполненияСценария.MD). Другие уроки собраны в [официальном оглавлении Vanessa](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/MainHelp/index.MD). Теги отбора задаются через `filtertags` / `ignoretags` в [VAParams.json](https://pr-mex.github.io/vanessa-automation/dev/JsonParams/JsonParamsEN/). `@Draft` сам по себе не исключает фичу из запуска: для этого задайте его в `ignoretags`. Библиотеки с `@ExportScenarios` обслуживаются существующим разделом экспортных сценариев.

## IntelliSense

В любом `.feature`, включая экспортные библиотеки, доступны встроенные шаги Vanessa, пользовательские шаги и экспортные сценарии. YAML-сценарии не предлагаются в обычном или семантическом поиске шагов для `.feature`. В `ТекстСценария` YAML они по-прежнему доступны вместе с параметрами вызова.

Аннотации шагов (`@screenshot`, `@recordvideo`, `#[autodoc.…]`) предлагаются на отдельной строке аннотации или при ручном вызове IntelliSense перед текстом шага — в отступе или у ключевого слова. Внутри текста и аргументов шага они не предлагаются. Через лампочку добавление тегов доступно из любой позиции шага. Это правило действует и для `ТекстСценария` YAML.

В аргументах предлагаются только специальные значения: переменные и параметры, а при доступном снимке Form Explorer — заголовки окон, имена элементов и значения указанного поля или колонки. Для произвольного текста и таймаутов подсказок KOT нет. Обычные словарные предложения VS Code для `feature` и `yaml` по умолчанию отключены (`editor.wordBasedSuggestions: off` в языковых настройках); явная настройка пользователя для соответствующего языка сохраняет приоритет. Значение для `yaml` действует также на обычные YAML-файлы, поскольку сценарии используют тот же языковой режим.

## JSON запуска из профиля

Генерация JSON предлагает сохранённые профили Менеджера параметров и создаёт `<имя-фичи>.json` рядом с фичей. Выбор профиля для этой операции не переключает глобальный активный профиль и каталог тестов.

Переносятся только известные параметры запуска: каталог Vanessa и библиотек, инфобаза TestClient, тип клиента, порт и дополнительные параметры, таймауты и безопасное выполнение шагов, пути логов, скриншотов и отчётов. Относительные пути разрешаются относительно рабочего пространства. `LaunchDBFolder`, `TestClientDBPath`, `InfobasePath` и `TestClientDB` преобразуются в настройки подключения TestClient. Параметры сборки СППР, например `AuthCompile`, `ModelDBSettings` и `ScenarioFolder`, в VAParams не копируются.

Затем применяются «Дополнительные параметры Vanessa» и `GlobalVars` выбранного профиля. Действуют существующие правила алиасов и флажок «Переопределить существующее значение». Неизвестные пользовательские ключи сохраняются. При подтверждённой замене существующего JSON его настройки служат основой; сохраняются пользовательские данные клиентов и дополнительные клиенты. Некорректный существующий JSON не заменяется.

`featurepath` / `КаталогФич` всегда указывает на конкретную фичу; заданный `FeaturesToRun` также сужается до этого файла. Отбор сценариев и тегов (`scenariofilter`, `filtertags`, `ignoretags` и алиасы) сохраняется. Запуск использует временную копию настроек, чтобы выбор инфобазы и путей логов не менял авторский JSON. Поддержка пути к одному файлу и параметры запусков описаны в [VAParams.json](https://pr-mex.github.io/vanessa-automation/dev/JsonParams/JsonParamsEN/).
