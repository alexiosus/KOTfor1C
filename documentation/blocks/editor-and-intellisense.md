# Блок: Editor and IntelliSense

Для работы с текстом без служебного YAML доступен [редактор сценария с панелью свойств](./scenario-properties-editor.md): шапка, параметры, вложенности, настройки теста и метаданные редактируются рядом с текстом.

## Задача блока

Ускорить редактирование сценариев и снизить количество ручных ошибок в YAML и `feature`.

## Что входит в блок

### Автодополнение

- Подсказки шагов Gherkin из версионного каталога Vanessa Automation — в YAML и `feature`.
- Управляющие конструкции `Else`, `ElseIf`, `Try`, `Except` и русские аналоги доступны на новой строке сценария и по частичному вводу. `ElseIf`/`ИначеЕсли` вставляет редактируемое условие и `Then`/`Тогда`, сохраняя отступ строки.
- Закрывающие конструкции `EndIf`, `EndTry`, `EndDo` и русские аналоги предлагаются только внутри YAML-блока `ТекстСценария`. Подсказки шагов с условием или циклом автоматически добавляют закрывающую конструкцию только в YAML; в `feature` используются отступы. Управляющие подсказки не предлагаются внутри комментариев, таблиц, многострочных строк и служебных полей YAML.
- При вставке цикла Vanessa через автодополнение или Library (включая перетаскивание) YAML получает форму, которую принимает компилятор: `Do I repeat "10" times` с `EndDo` или `Цикл я делаю "10" раз` с `КонецЦикла`. Тело цикла вставляется с отступом; формулировка шага и параметры сохраняются. Такие строки распознаются каталогом для hover, поиска ссылок и диагностики. В `feature` вставляется исходный шаг Vanessa.
- В YAML отдельно предлагаются директивы препроцессора `#Если`, `#ИначеЕсли`, `#Иначе`, `#КонецЕсли`. Они работают при сборке; условия проверяются на структуру, а вычисляются внешней обработкой 1С.
- После `Return ` / `Возврат ` предлагаются параметры предыдущего вызова вложенного сценария, после `as ` / `как ` — имена переменных Vanessa. `Result = SavedResult` подставляет имя `SavedResult` вместо `[Result]` внутри вложенного сценария, который сохраняет результат в эту переменную. Родитель читает её через `$SavedResult$`; alias доступен в подсказках по `$` и не добавляется в шапку как YAML-параметр. Для предоставленной версии обработки предпочитайте `Result = SavedResult` или `Возврат Result как SavedResult`: английская форма `Return … as …` содержит ошибку в reader обработки (см. раздел 8 документа «Параметры сценариев»).
- Семантический режим по префиксу `!`:
  - поиск по текстам и описаниям шагов;
  - приоритет языка подсказок шагов определяется тегом `#language:` в текущем сценарии.
- Если активен `KOT Form Explorer`, редактор использует live snapshot текущей формы:
  - внутри кавычек шагов предлагаются заголовки окна/формы, элементы, кнопки, таблицы, колонки и текущие значения;
  - подсказки аргументов учитывают уже выбранные ссылки в шаге, например поле -> его текущее значение или значение -> поля с таким значением.
- Подсказки вызовов вложенных сценариев из кеша проекта — в YAML; экспортных сценариев и пользовательских шагов — в YAML и `feature`.
- Обычные словарные подсказки VS Code (`abc`, слова из открытых файлов) по умолчанию отключены для `yaml` и `feature`, чтобы не смешиваться с подсказками аргументов KOT. Для `yaml` это относится ко всем YAML-файлам, использующим этот языковой режим. При необходимости можно переопределить `editor.wordBasedSuggestions` в настройках `[yaml]` или `[feature]`.
- Подсказки параметров вызова с подстановкой значений по умолчанию.
- Параметры с `ТипПараметра: "Таблица"` вставляются как пустое присвоение и строки таблицы; многострочный default сохраняется. Быстрое редактирование такого default открывает и выделяет значение в YAML.
- Возле `ПараметрыСценария:` отображается число вариантов, если скалярные значения содержат неэкранированные `;`. Наведение показывает первые восемь комбинаций. Табличные значения не разделяются на варианты.
- Подсказки параметров текущего сценария при вводе `[`:
  - список берется из `ПараметрыСценария` текущего YAML;
  - в выдаче показываются конструкции вида `[ParameterName]` и превью дефолтного значения.
- Подсказки переменных при вводе `$` и `$$`:
  - `$SavedVar$` — переменные, сохраненные выше по сценарию;
  - `$$GlobalVar$$` — `GlobalVars` из Менеджера параметров;
  - если начать с `$$`, список сразу фильтруется только по глобальным переменным;
  - доступны в YAML и `feature`.

### Hover-подсказки

- Для шагов: описание шага + пример с фактическими аргументами текущей строки (YAML и `feature`).
- Для вызовов сценариев: описание сценария, число параметров, вложенных вызовов и файлов (YAML и `feature`).
- Для `$SavedVar$` и `$$GlobalVar$$`: текущее значение переменной.
- Для параметров вида `[ParameterName]` в `ТекстСценария`: значение по умолчанию из блока `ПараметрыСценария` и действие быстрого редактирования этого значения.
- Для служебных полей YAML:
  - описания полей шапки `scen.yaml` и `test.yaml`;
  - пояснения для `ПараметрыТеста`, `ПараметрыСценария` и `ВложенныеСценарии`, включая элементы списков;
  - отдельные подсказки для полей `ЭталоннаяБазаИмя`, `ИдентификаторБазы`, `ПрофильПользователя` в `test.yaml`.
- Для упавших строк в `feature` обычный hover шага подавляется, чтобы приоритет имел hover ошибки.

### Подсветка сценария в YAML

- Русские буквы разрешены по умолчанию в Unicode-подсветке для YAML и `feature`, включая Restricted Mode: штатные поля `ТипФайла`, `ДанныеСценария` и `KOTМетаданные` не вызывают предупреждения «not a basic ASCII character». Проверки невидимых символов и остальных неоднозначных Unicode-символов сохраняются. Эти значения можно переопределить через `editor.unicodeHighlight.allowedCharacters` в языковых настройках `[yaml]` или `[feature]`.
- Gherkin-подсветка работает внутри `ТекстСценария`, при этом документ остается в `yaml` language mode.
- Подсвечиваются шаговые ключевые слова, аргументы в кавычках, параметры вида `[ParameterName]`, placeholders `<...>`, таблицы, комментарии и управляющие блоки `If/ElseIf/Else/EndIf`, `Do/EndDo`, `Try/Except/EndTry` и русские аналоги.
- Такое поведение не конфликтует с `editor.formatOnSave` и обычными YAML-инструментами VS Code.

### Автоформат при сохранении

- Замена табуляций пробелами.
- Выравнивание таблиц Gherkin.
- Выравнивание параметров вызовов по `=`.

### Автоподдержка служебных секций

- `ВложенныеСценарии` перезаполняется по фактическим вызовам в тексте.
- `ПараметрыСценария` перезаполняется по фактически используемым параметрам.
- Комментарии `/* … */`, `//` и `#` пропускаются при поиске вызовов и параметров. Возвращаемые параметры и псевдонимы учитываются; тип, исходящий признак и строки таблиц сохраняются при перезаполнении. Подстановки `[Имя]` работают также внутри таблиц и многострочных строк.
- Перезаполнение выполняется только при релевантных изменениях.

## Настройки блока

Кнопки управления в редакторе по умолчанию выключены. Включите **Editor: Show Action Buttons** в настройках VS Code или выполните **KOT - Toggle editor action buttons**, чтобы показать действия CodeLens и управляющие inlay-подсказки. Информационные подсказки сохраняются при выключенных кнопках. Действие добавления блока `ПараметрыСценария` убрано из редактора: этот блок поддерживается автозаполнением; ручное редактирование доступно в панели свойств.

| Настройка | Назначение |
|---|---|
| `kotTestToolkit.editor.showActionButtons` | Кнопки управления в редакторе; по умолчанию выключены |
| `kotTestToolkit.editor.autoCollapseOnOpen` | Сворачивать служебные секции при открытии |
| `kotTestToolkit.editor.autoReplaceTabsWithSpacesOnSave` | Замена табов при save |
| `kotTestToolkit.editor.autoAlignNestedScenarioParametersOnSave` | Выравнивание параметров вызова |
| `kotTestToolkit.editor.autoAlignGherkinTablesOnSave` | Выравнивание таблиц в YAML и feature; для feature также доступен Format Document |
| `kotTestToolkit.editor.autoFillNestedScenariosOnSave` | Автоподдержка `ВложенныеСценарии` |
| `kotTestToolkit.editor.autoFillScenarioParametersOnSave` | Автоподдержка `ПараметрыСценария` |
| `kotTestToolkit.editor.showRefillMessages` | Показывать уведомления о перезаполнении |
| `kotTestToolkit.editor.newScenarioLanguage` | Язык новых сценариев (`#language`) |
| `kotTestToolkit.steps.catalogIndexUrl` | URL индекса версионных каталогов шагов Vanessa Automation |

## Практические советы

- В VS Code 1.140–1.141 перенос из Library в редактор может блокироваться до вызова обработчика расширения: это [регрессия VS Code #339036](https://github.com/microsoft/vscode/issues/339036), связанная с изменением Electron 43.7.0. Она воспроизведена в VS Code 1.141.0 / Electron 43.7.7; Shift не устраняет блокировку. Пока исправление VS Code не выпущено, поставьте курсор на нужную строку сценария и используйте **Insert / Вставить** при наведении на элемент Library или в его контекстном меню. Вставка учитывает формат YAML или `feature`. Перемещение самостоятельных feature между группами внутри Library использует отдельный путь. На 12 октября 2026 года задача VS Code открыта с целью 1.142; наличие исправления нужно проверять по самой задаче.
- Если скобки в тексте — это не параметр, используйте `\[` и `\]`.
- Для подстановки переменной начните ввод с `$`; для списка только глобальных переменных начинайте сразу с `$$`.
- Наведите курсор на `[ParameterName]`, чтобы увидеть значение по умолчанию и открыть быстрое редактирование прямо из hover.
- После обновления Vanessa выполните `KOT - Refresh steps library` (`KOT - Обновить библиотеку шагов`).
- Если обнаружены дубликаты кода сценария (поле `Код` в шапке), используйте соответствующую команду из `KOT - Редактирование`:
  - для главного сценария: `KOT - Изменить имя главного сценария` (для главного сценария имя одновременно синхронизирует и `Код`);
  - для вложенного сценария: `KOT - Изменить код вложенного сценария`.
