# Параметры и теги сценариев и процессов СППР

`ПараметрыСценария` описывают данные самого сценария или процесса. `ПараметрыТеста` задают данные конкретной настройки сборки. `ПараметрыШага` передают данные одному сценарию или подпроцессу внутри процесса. Совпадающие имена сами по себе не передают общий параметр во все шаги: для этого нужна явная ссылка.

Описание проверено по предоставленным исходникам `BuildScenarioBDD/Ext/ObjectModule.bsl` и `BuildScenarioBDD/Forms/Форма/Ext/Form/Module.bsl`. EPF не запускался. У этой версии есть различия между сборкой главного сценария и процесса; ниже они отмечены отдельно.

Над секциями `ПараметрыСценария`, `ПараметрыТеста`, `ТегиСценария`, `ТегиПроцесса` и `ТегиТеста` доступны кнопки добавления записей. Кнопка у `ПараметрыШага` добавляет параметр именно выбранному шагу процесса. Введите имя: KOT вставит запись с правильными отступами, следующим свободным номером и служебными полями. Параметр создаётся с типом `Строка` и пустым значением; заполните значение, тип и способ передачи в YAML перед сборкой. Для тега достаточно имени без `@`. Записи остаются в редакторе до сохранения файла.

| Блок и файл | Назначение | Откуда берётся значение при сборке |
|---|---|---|
| `ПараметрыСценария` в YAML главного сценария | Имена, типы и значения по умолчанию для `[Имя]` в тексте | Значение из `ПараметрыТеста` настройки; при отсутствии одноимённой записи — значение из сценария |
| `ПараметрыТеста` в `test.yaml` главного сценария | Данные конкретного запуска, включая несколько вариантов | Переопределяют одноимённые параметры главного сценария |
| `ПараметрыСценария` в YAML процесса | Общие параметры процесса | При вызове как подпроцесса служат значениями по умолчанию. В верхнем процессе эта версия не добавляет их к `ПараметрыТеста` настройки |
| `ПараметрыТеста` в YAML настройки процесса | Общие данные конкретного запуска процесса | Именно из этого блока берутся общие параметры верхнего процесса |
| `ПараметрыШага` у шага со сценарием | Аргументы одного вызова сценария | Явная передача выигрывает у default сценария; отсутствующие записи дополняются из сценария |
| `ПараметрыШага` у шага с подпроцессом | Аргументы одного вызова подпроцесса | Непустой литерал, затем ссылка на параметр родителя, затем default подпроцесса |
| `ТегиПроцесса` в процессе и `ТегиТеста` в настройке | Метки для отбора и результата компиляции | Добавляются совместно в feature; это не значения параметров |

Примеры ниже — фрагменты существующих файлов. Служебные поля шапки сохраните, а UUID, имена сценариев и идентификатор базы замените своими. Парсер СППР использует свой формат записей: отступы кратны четырём пробелам, скалярные значения заключены в кавычки. Для пустой секции сохраните заголовок без записей, как в шаблонах СППР.

## Главный сценарий и его test.yaml

В файле сценария задаём обычные значения:

```yaml
ПараметрыСценария:
    - ПараметрыСценария1:
        НомерСтроки: "1"
        Имя: "Currency"
        Значение: "USD"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
    - ПараметрыСценария2:
        НомерСтроки: "2"
        Имя: "Amount"
        Значение: "100"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
ТекстСценария: |
    #language: en
    And I input [Currency] text in the field named "Currency"
    And I input [Amount] text in the field named "Amount"
```

В соответствующем `test.yaml` переопределяем только валюту:

```yaml
ПараметрыТеста:
    - ПараметрыТеста1:
        НомерСтроки: "1"
        Имя: "Currency"
        Значение: "EUR"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
ТегиТеста:
    - ТегиТеста1:
        НомерСтроки: "1"
        Имя: "Smoke"
```

Получаем `Currency = EUR`, `Amount = 100`. Чтобы вернуться к default `USD`, удалите запись `Currency` из `ПараметрыТеста`. Пустое значение в существующей записи не означает «взять default»: компилятор дополняет параметры по отсутствию имени, а не по пустоте значения.

У главного сценария строковое `Значение: "EUR;GBP"` создаёт два варианта. Если у `Amount` задать `Значение: "100;200"`, получатся четыре сочетания: `EUR/100`, `EUR/200`, `GBP/100`, `GBP/200`. Такой список можно задать в `ПараметрыТеста` или оставить в default сценария. Разделение строк по `;` выполняется независимо от флага `НесколькоЗначений`; табличный параметр сохраняется одним значением. Для буквальной точки с запятой используйте одинарные кавычки и одну обратную косую черту: `Значение: 'EUR\;GBP'`. Тогда и YAML, и собственный парсер компилятора передадут `EUR;GBP` одним значением. Предел компилятора — 100 сочетаний.

## Общий параметр верхнего процесса

В YAML процесса объявляем общий `Currency`:

```yaml
ПараметрыСценария:
    - ПараметрыСценария1:
        НомерСтроки: "1"
        Имя: "Currency"
        Значение: "USD"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
ТегиПроцесса:
    - ТегиПроцесса1:
        НомерСтроки: "1"
        Имя: "Sales"
```

В YAML настройки процесса явно задаём валюту этого запуска:

```yaml
ТипФайла: "НастройкаПроцесса"
ДанныеТеста:
    UID: "22222222-2222-4222-8222-222222222222"
    Код: "SalesEUR"
    Имя: "Продажи в EUR"
    UIDПроцесса: "33333333-3333-4333-8333-333333333333"
    ПроцессНаименование: "Продажи"
    ИдентификаторБазы: "DriveTest"
    ПрофильПользователя: "Менеджер"
    ПараметрыЗапуска: ""
ПараметрыТеста:
    - ПараметрыТеста1:
        НомерСтроки: "1"
        Имя: "Currency"
        Значение: "EUR"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
ТегиТеста:
    - ТегиТеста1:
        НомерСтроки: "1"
        Имя: "Smoke"
```

Здесь `UIDПроцесса` должен совпадать с `ДанныеПроцесса.UID` файла процесса. Название `test.yaml` само по себе не определяет назначение файла: обработка распознаёт настройку по `ТипФайла` и связывает её с процессом по UID.

**Ограничение этой версии компилятора:** при сборке верхнего процесса общие значения берутся только из `ПараметрыТеста` настройки. Default `Currency = USD` из файла процесса не подхватывается автоматически. Если удалить `Currency` из настройки, шаг со ссылкой на него получит ошибку «Не найден общий параметр процесса». Для запуска в USD запишите `USD` в настройке явно.

## Передача общего значения в сценарий одного шага

В `ШагиПроцесса` передаём валюту сценарию `CreateSalesInvoice`:

```yaml
ШагиПроцесса:
    - ШагиПроцесса1:
        ШагПроцесса: "44444444-4444-4444-8444-444444444444"
        UID: "44444444-4444-4444-8444-444444444444"
        Процесс: "33333333-3333-4333-8333-333333333333"
        Наименование: "Создать накладную"
        Сценарий: "11111111-1111-4111-8111-111111111111"
        СценарийНаименование: "CreateSalesInvoice"
        СценарийКод: "CreateSalesInvoice"
        СценарийUID: "11111111-1111-4111-8111-111111111111"
        ПолныйКод: "Sales.1"
        ИсполнительНаименование: "Менеджер"
        ПараметрыШага:
            - ПараметрыШага1:
                Имя: "Currency"
                ТипПараметра: "Строка"
                ШагПроцессаЗначениеПоСсылке: ""
                ШагПроцессаЗначениеПоСсылкеUID: ""
                ИсходящийПараметр: "Нет"
                ЗначениеПоСсылке: "Общий параметр.Currency"
                ЗначениеПроизвольное: ""
                ИмяПараметраПоСсылке: "Currency"
        ТипШага: "0"
```

`Имя` — параметр принимающего сценария. Суффикс в `Общий параметр.Currency` — имя общего параметра процесса. Поэтому можно передать общий `Currency` в параметр сценария с другим именем, например `InvoiceCurrency`.

Для обычного сценария компилятор извлекает имя из `ЗначениеПоСсылке`; поле `ИмяПараметраПоСсылке` в этом режиме общей ссылки не участвует. Заполняйте его тем же именем: при передаче в подпроцесс используется именно оно.

При настройке из предыдущего примера `CreateSalesInvoice` получает `Currency = EUR`. Если у него есть default `Amount = 100`, а `Amount` отсутствует в `ПараметрыШага`, компилятор дополнит аргументы значением `100`. Самостоятельный `test.yaml` этого сценария при вызове из процесса не используется.

Чтобы в другом шаге зафиксировать валюту `JPY`, замените запись передачи параметра:

```yaml
ПараметрыШага:
    - ПараметрыШага1:
        Имя: "Currency"
        ТипПараметра: "Строка"
        ШагПроцессаЗначениеПоСсылке: ""
        ШагПроцессаЗначениеПоСсылкеUID: ""
        ИсходящийПараметр: "Нет"
        ЗначениеПоСсылке: ""
        ЗначениеПроизвольное: "JPY"
        ИмяПараметраПоСсылке: ""
```

Это передаст `JPY` только данному вызову; общий `Currency = EUR` сохранится. Если удалить всю запись `Currency` из `ПараметрыШага`, сценарий получит свой default `USD`, даже если общий параметр процесса имеет значение `EUR`. Для использования default удаляйте запись, а не оставляйте пустой аргумент.

Для обычного сценария ссылка `Общий параметр.Currency` имеет приоритет перед непустым `ЗначениеПроизвольное`. Выбирайте один способ передачи и очищайте другое поле.

## Вложенный процесс: defaults действительно используются

Допустим, процесс `Оплата` с UID `55555555-5555-4555-8555-555555555555` объявляет в своём `ПараметрыСценария` `Currency = USD`, как в примере выше. Его внутренний шаг передаёт эту валюту своему сценарию через `ЗначениеПоСсылке: "Общий параметр.Currency"`.

В родительском процессе добавляем вызов `Оплаты`:

```yaml
ШагиПроцесса:
    - ШагиПроцесса2:
        ШагПроцесса: "66666666-6666-4666-8666-666666666666"
        UID: "66666666-6666-4666-8666-666666666666"
        Процесс: "33333333-3333-4333-8333-333333333333"
        Наименование: "Оплата накладной"
        ПолныйКод: "Sales.2"
        ИсполнительНаименование: "Менеджер"
        ПараметрыШага:
            - ПараметрыШага1:
                Имя: "Currency"
                ТипПараметра: "Строка"
                ШагПроцессаЗначениеПоСсылке: ""
                ШагПроцессаЗначениеПоСсылкеUID: ""
                ИсходящийПараметр: "Нет"
                ЗначениеПоСсылке: "Общий параметр.Currency"
                ЗначениеПроизвольное: ""
                ИмяПараметраПоСсылке: "Currency"
        ТипШага: "1"
        ВложенныйПроцессНаименование: "Оплата"
        ВложенныйПроцессUID: "55555555-5555-4555-8555-555555555555"
```

Компилятор сначала берёт общие параметры из `ПараметрыСценария` подпроцесса, затем применяет `ПараметрыШага` родительского вызова. Для этого примера результат — `Currency = EUR`. Если убрать запись передачи, подпроцесс использует собственный `USD`. Если очистить ссылку и записать `ЗначениеПроизвольное: "JPY"`, получит `JPY`.

Есть два нюанса именно этой ветки компилятора:

- Переопределяется только параметр, уже объявленный в `ПараметрыСценария` подпроцесса. Лишнее имя в `ПараметрыШага` не добавляет новый общий параметр.
- Для ссылки имя параметра родителя берётся из `ИмяПараметраПоСсылке`. Если такого имени у родителя нет, остаётся default подпроцесса; ошибки отсутствия ссылки в этом месте нет. Непустой литерал имеет приоритет перед ссылкой, поэтому обе формы одновременно задавать не следует.

Отдельная настройка запуска подпроцесса в этот вызов не включается: используются его определение и аргументы родительского шага.

**Несколько значений в процессе:** механизм главного сценария с перебором сочетаний здесь не реализован. Ветка процесса разбирает списки для подсчёта лимита, но не перебирает полученные наборы; общая ссылка возвращает исходную строку, например `EUR;GBP`. Для отдельных запусков процесса используйте отдельные настройки с одним значением каждого параметра.

## Теги и отбор при сборке

В YAML храните `Имя: "Sales"`, без `@`: компилятор добавляет этот символ сам. В примере выше feature процесса получает `@Sales` из `ТегиПроцесса` и `@Smoke` из `ТегиТеста` настройки. У главного сценария в результат добавляются его `ТегиСценария` и `ТегиТеста` соответствующего `test.yaml`. Теги добавляются последовательно; удаления дубликатов в этих ветках нет.

При сборке процесса не происходит автоматического объединения пользовательских тегов всех сценариев и подпроцессов. Для отбора всей цепочки поместите нужный тег в верхний процесс или его настройку.

Параметры обработки сборки можно задать так:

```json
{
    "FilterTags": "Sales;Smoke",
    "ExceptionTags": "Disabled"
}
```

`FilterTags` соответствует `ОтборПоТегамСценариевИлиНастроек`: настройка выбирается, если совпал хотя бы один тег настройки или главного сценария/верхнего процесса. Списки разделены `;`, сравнение без учёта регистра. Здесь также используются имена без `@`. Отбор проверяет теги верхнего объекта и настройки, а не всех вложенных шагов.

`ExceptionTags` соответствует `ИсключениеПоТегамСценариевИлиНастроек` и исключает настройки главных сценариев при совпадении любого тега. **В предоставленной версии ветка сборки процессов из YAML этот параметр не применяет**, хотя форма обработки его принимает. Для процессов нельзя рассчитывать на такой фильтр исключения.

## Явное заполнение defaults процесса

Откройте процесс, затем в правой панели **Test properties → Run settings** выберите YAML настройки. В разделе **Test parameters** нажмите **Fill missing process defaults / Заполнить недостающие значения процесса**. KOT добавит отсутствующие по имени параметры из `ПараметрыСценария` процесса в `ПараметрыТеста` выбранной настройки. Существующее значение, в том числе `""`, остаётся прежним; таблица записывается многострочным блоком с точным маркером `|`. Другие настройки процесса не меняются. После проверки сохраните тест обычным Save test или автосохранением VS Code.

Это явное редактирование YAML: оно не включает автоматическое наследование в обработке и не превращает список `EUR;GBP` в несколько процессных тестов. При сборке KOT предупреждает о пропущенных defaults и таких списках; более 100 рассчитанных комбинаций останавливают сборку до запуска 1С. Таблица остаётся одним значением, а экранированная `\;` не разделяет варианты.

Теги не выполняют шаги и не задают валюту или другие данные. Они маркируют полученный feature и позволяют выбрать настройки на этапе сборки; фильтры запуска Vanessa задаются отдельно.

Подробности передачи `[Параметр]` между сценариями в `ТекстСценария`: [Параметры сценариев](./scenario-parameters.md). Настройки обработки сборки: [Менеджер параметров](./parameters-manager.md).
