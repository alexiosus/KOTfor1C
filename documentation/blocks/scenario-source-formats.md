# Форматы исходного сценария СППР

При создании главного или вложенного сценария мастер предлагает два варианта:

- **scen.yaml** (`legacy`): метаданные и блок `ТекстСценария` находятся в одном YAML.
- **meta.yaml + scen.feature** (`native`): метаданные СППР отделены от исходного текста сценария.

В обычных настройках VS Code откройте **New scenario defaults → Format** (`kotTestToolkit.newScenarioDefaults.format`): **Сценарий YAML (scen.yaml)** или **Feature + метаданные YAML (scen.feature + meta.yaml)**. Настройка определяет первый вариант в мастере. По умолчанию сохранён `legacy`. Настройки запуска, UID, параметры, вложенные сценарии и вложения остаются связанными с тем же тестом. Test Properties редактирует настоящий `meta.yaml`; редактор открывает `scen.feature`. Library и переход к определению открывают исходный `scen.feature`; `meta.yaml` не сворачивается автоматически. При сохранении любого файла пары блоки `ВложенныеСценарии` и `ПараметрыСценария` синхронизируются по текущему тексту скрипта с учётом настроек автозаполнения. Уже несохранённые изменения метаданных автоматически на диск не записываются.

Файл `orig.yaml` с тем же UID рядом с native-парой считается копией экспорта СППР и не создаёт второй тест.

Пара распознаётся как СППР только при наличии обоих файлов и `ТипФайла: Сценарий` в метаданных. Такой `scen.feature` исключается из самостоятельных тестов Vanessa. Он может содержать конструкции СППР и требует обычной сборки; Run ведёт к артефакту исходного теста.

## Преобразование

Откройте `scen.yaml`, `meta.yaml` или парный `scen.feature` и выполните **KOT: Преобразовать формат сценария СППР…** через палитру или подменю KOT редактора. Та же команда доступна в **Properties**, в контекстном меню сценария обеих Library и в подробностях полноценной Library. Команда переключает формат в противоположную сторону. Перед запуском сохраните связанные документы.

После успешного преобразования формата, роли главный ↔ вложенный или вида вложенный ↔ экспортный KOT помечает затронутые сборки устаревшими. Это также относится к тестам, которые вызывают изменённый сценарий через другие вложенные сценарии. Статус обновляется сразу, без повторного сохранения исходника; несвязанные сборки сохраняют своё состояние.

Сохранение исходного `scen.feature` во вложенной паре также помечает вызывающие его тесты устаревшими. Изменения экспортной библиотеки учитываются через ссылки на её сценарии, включая цепочки экспортов и библиотеки вне каталога компилятора. Такая сборка получает признак изменения и в случае, когда экспорт выполняется из библиотеки во время запуска, а текст выходной feature остаётся прежним.

## Вложенный и экспортный сценарий

В выпадающем меню кнопки **Conversions / Преобразования** вложенного сценария выберите **Convert to exported scenario…**. В Properties это одна кнопка рядом с действиями открытия исходника; в её меню находятся также главный ↔ вложенный тест и формат исходника. Для экспортного сценария обратное действие доступно в Library, меню редактора и в меню Conversions рядом со сценарием в Properties. Палитра: **KOT: Convert Nested / Exported Scenario…**.

Название экспортного сценария предзаполняется исходным названием и всеми параметрами в кавычках, например `Open order "Customer" "Count"`. Порядок аргументов можно менять. Удаление, переименование, повторение или добавление неизвестного параметра не позволяет завершить ввод. Для нового вложенного сценария запрашивается название; аргументы заголовка становятся параметрами СППР, пробелы и недопустимые символы их имён заменяются подчёркиваниями.

При обратной конвертации метаданные записываются с отступами СППР по четыре пробела: поля шапки и маркеры записей — четыре, поля параметров и тегов — восемь. Правило применяется к `meta.yaml` и `scen.yaml`; содержимое многострочных значений не переформатируется как структура YAML.

После названия выберите **New feature file / Новый feature-файл** либо **Existing feature file / Существующий feature-файл**. В существующую библиотеку добавляется отдельный сценарий с тегом `@ExportScenarios`; остальные сценарии и их текст сохраняются. Язык Gherkin должен совпадать с исходником, а название сценария не должно повторять уже существующее.

**Existing feature file** показывает QuickPick с feature-файлами настроенных библиотек, включая файлы без экспортных сценариев. Поиск учитывает имя и путь; дубликаты, парные скрипты СППР и известные артефакты сборки исключаются. Пункт **Choose another feature file… / Выбрать другой feature-файл…** открывает обычный файловый диалог, в том числе если список библиотек пуст.

Новый экспортный файл по умолчанию сохраняется в настроенном каталоге **Libraries** либо рядом с исходником, если библиотека ещё не задана. Можно выбрать другую папку или существующую feature: при необходимости KOT автоматически добавляет её папку в **Libraries** активного профиля, а также в приоритетное переопределение `librarycatalogs` / `КаталогиБиблиотек`. При отмене или ошибке конвертации настройки сохраняются прежними. Вложенный сценарий сохраняется в каталоге исходников СППР. Для нового вложенного сценария используются **New scenario defaults**, в том числе формат YAML / feature + meta. При преобразовании существующих вызовов СППР в обоих направлениях сохраняются переданные значения и ссылки вида `[ПараметрРодителя]`, добавляются пропущенные значения по умолчанию и обновляется блок `ВложенныеСценарии`. Собранные feature не редактируются — они обновятся при следующей сборке. Самостоятельная feature Vanessa не может вызывать вложенный сценарий СППР, а шаг процесса — экспортный сценарий: такие зависимости необходимо изменить перед конвертацией.

Рядом с полученной экспортной feature создаётся файл `*.feature.kot-nested.json`: он хранит исходные метаданные, UID, значения по умолчанию, формат и KOT sidecar. Сохраняйте его вместе с feature. Для нескольких преобразованных сценариев общий архив хранит отдельные записи; обратная конвертация удаляет только выбранную запись. Старые архивы одного сценария также поддерживаются. Обратная конвертация использует актуальный текст feature и восстанавливает эти данные; другие сценарии общего экспортного файла сохраняются. При наличии вложений преобразуйте в той же папке: она добавится в Libraries автоматически.

Навигация к экспортным сценариям сохраняет путь настроенного каталога библиотеки. Например, доступный в Windows путь `C:/Mac/Home/...` не заменяется физическим `//mac/Home/...`, который VS Code может блокировать. Эквивалентные URI с разным кодированием символов учитываются при обратной конвертации и подсветке связей.

В `scen.feature` native-пары работают проверки параметров вызванных сценариев, лишних присваиваний, незакрытых блоков и параметров, отсутствующих в `meta.yaml`. Диагностика указывает строки feature; изменения открытого `meta.yaml` обновляют проверку парного скрипта. При конвертации на общих папках Parallels, не поддерживающих жёсткие ссылки, KOT использует исключительное копирование с теми же проверками конфликтов и откатом.

Вызовы вложенных сценариев без параметров раскрываются в текст экспортной feature, включая последовательные вложения; файлы зависимостей сохраняются. Если обратное преобразование использует этот текст, устаревшие объявления вложенных вызовов удаляются из метаданных. Проверка сохранённого текста учитывает BOM и нормализацию переводов строк в VS Code; реальные изменения и несохранённые правки по-прежнему блокируют запись.

Конвертер блокирует конструкции без безопасного эквивалента: исходящие и табличные параметры СППР, управляющие блоки и параметризованные вложенные вызовы, вложенные сценарии с тегами, прикреплёнными файлами или другим языком Gherkin, циклические вызовы, составные строки с `[Параметр]`, подстановки параметров в таблицах/многострочных строках, а также Background, Variables/Rules и Scenario Outline при обратном преобразовании. Причина показывается до изменения файлов. Несохранённые документы, конфликтующие назначения и неоднозначные вызовы также отменяют преобразование; частичная запись откатывается.

Преобразование сохраняет содержимое сценария, окончания строк, UTF-8 BOM, метаданные, UID и настройки. KOT-файл `scen.yaml.kot.yml` переименовывается в `meta.yaml.kot.yml` и обратно. Вложения и настройки запуска остаются на месте.

Команда прекращается при занятых целевых именах, несохранённых документах, неоднозначных метаданных или форме YAML, которую нельзя обратимо преобразовать. Для legacy требуется единственный завершающий блок `ТекстСценария: |` с отступом четыре пробела. Произвольный YAML не нормализуется ценой потери комментариев или текста. При ошибке записи подготовленные изменения откатываются.


## Редактирование и сохранение

Для парного `scen.feature` доступны подсказки шагов Vanessa, экспортных и вложенных сценариев, параметры `[Имя]`, ховеры и подсветка конструкций СППР. Значения параметров читаются из текущего `meta.yaml`, включая несохранённые изменения. Счётчики в Properties учитывают текст парного скрипта. **Open feature** открывает шаги; **Open YAML** — метаданные. Save test сохраняет оба документа пары.

Опция `kotTestToolkit.editor.autoMigrateScenarioYamlOnSave` автоматически преобразует старый `scen.yaml` при сохранении. По умолчанию она выключена и не зависит от формата новых сценариев. Применяются те же проверки целевых файлов и несохранённых документов, что и при ручном преобразовании.
