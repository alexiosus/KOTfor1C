# Блок: Parameters Manager

## Задача блока

Дать единое место для управления параметрами сборки и запуска Vanessa Automation.

Открытие: в панели Менеджера тестов иконка "`{ }`" или команда `KOT - Open Compilation and run parameters` (`KOT - Открыть параметры компиляции и запуска`).

## Вкладки менеджера

## 1) СППР

Используется для параметров, которые обрабатывает `СборкаТекстовСценариев`.

Результат:

- формируется `yaml_parameters.json`;
- эти параметры участвуют в сборке `feature/json`;
- после сборки KOT использует их как основу для built JSON и соседнего `*.combined.json` артефакта Vanessa.

### Минимальный набор для сборки

KOT ориентируется на фактическое поведение `СборкаТекстовСценариев` из СППР.

Для любой сборки нужны `ScenarioFolder` и `FeatureFolder`. При `CreateJson=true` (значение по умолчанию) также нужны каталог Vanessa и база запуска. При `CreateJson=false` можно собрать только feature-файлы без Vanessa и базы запуска.

Новый профиль явно включает `ExternalMode`, `CreateJson`, `CreateJUnit` и `CreateModellingXML`. `AuthCompile` остаётся выключенным. `CreateJUnit` и `CreateModellingXML` относятся к отчётам **сборки**; `JUnitReport` и `SpprReport` управляют отчётами **выполнения** Vanessa.

По умолчанию исходники находятся в `tests/`, процессы используют тот же каталог. При запуске расширения активный профиль задаёт оба каталога до первого сканирования: редактор, Library и Test Manager используют согласованные корни. Для существующего проекта сохраняется его выбранный каталог исходников.

Каталоги диагностики создаются относительно настройки `Runtime: Directory` (по умолчанию `.vscode/kot-runtime`):

| Параметр | Значение внутри runtime |
|---|---|
| `AllureFolder` | `reports/allure` |
| `JUnitFolder` | `reports/junit` |
| `BDDLogFolder` | `logs/errors` |
| `ScreenshotsFolder` | `screenshots` |
| `ModelDBSettings` | `bases.yaml` |

При первом обновлении старого профиля добавляются только отсутствующие параметры диагностики. Явные `false`, пустые значения и пользовательские пути сохраняются. `AllurePath`, `JUnitPath`, `ScreenshotsPath` и `VanessaLibraries` подавляют добавление соответствующего нового параметра. После сохранения обновлённого профиля удалённые необязательные строки больше автоматически не добавляются.

`Libraries` — первоначально пустое поле для **дополнительных** библиотек Vanessa: экспортных `.feature`-сценариев и пользовательских шагов. Несколько каталогов разделяются `|`, например `tests/VanessaLibraries|tools/custom-steps`. Стандартная библиотека `VanessaFolder/features/Libraries` подключается автоматически. YAML-подсценарии СППР ищутся в `ScenarioFolder`; добавлять их в `Libraries` не требуется. Приоритет `Libraries` над `VanessaLibraries` и флага Priority во вкладке Additional учитывается также при поиске определений и переходах в редакторе.

Над таблицей СППР показывается состояние `ModelDBSettings`: доступность файла, корректность YAML, количество баз и профилей, отсутствие выбранного `ModelDBid` или профилей пользователей. Проверка обновляется после изменения пути, переключения профиля и изменения файла. В сообщениях нет логинов и паролей. Предупреждение не блокирует автосохранение; `AuthCompile` остаётся отдельным режимом проверки авторизации при сборке.

| Ключ | Назначение |
|---|---|
| `ScenarioFolder` | Каталог YAML-сценариев; из него KOT сканирует сценарии. |
| `ProcessFolder` | Каталог YAML-процессов. Может находиться отдельно от сценариев; KOT сканирует оба каталога. Если параметр отсутствует, профиль получает тот же каталог, что ScenarioFolder. Явно пустое значение сохраняется. |
| `FeatureFolder` | Каталог результатов компиляции. |
| `VanessaFolder` | Каталог Vanessa для генерации JSON. Импортированный VanessaPath может указывать на EPF; KOT использует его каталог. Приоритет: VanessaPath, VanessaFolder, VanessaDir. |
| `LaunchDBFolder` / `TestClientDBPath` | Каталог файловой базы или строка подключения. LaunchDBFolder имеет приоритет. |
| `TestClientDB` / `InfobasePath` | Полная строка подключения к базе, например `Srvr="server";Ref="base";`. TestClientDB имеет приоритет над InfobasePath; эта группа имеет приоритет над группой каталогов. |
| `ModelDBSettings` | Файл настроек эталонных баз и профилей пользователей. Обязателен при AuthCompile=true. Явно пустое значение не заменяется значением по умолчанию. |
| `Libraries` / `VanessaLibraries` | Дополнительные каталоги библиотек через `|`; при импорте JSON допустим массив. Libraries имеет приоритет. Встроенную библиотеку Vanessa добавляет обработка; повторять её здесь не нужно. |
| `CompileFile` | Путь к объединённому compile.txt — списку настроек, которые обработка пыталась собрать. Это не отчёт о прохождении тестов. |
| `CreateJUnit`, `JUnitFile` | Генерация и путь отчёта JUnit о компиляции. |
| `JUnitPath` | Каталог junit_compile.xml, а также каталог отчётов выполнения, если не указан JUnitFolder. |
| `JUnitReport`, `JUnitFolder` | Генерация и каталог отчётов JUnit о выполнении Vanessa. |

`LaunchDBFolder` и `TestClientDBPath` образуют одну строку с выбором ключа. Полное подключение задаётся отдельной строкой `TestClientDB` или `InfobasePath`. Можно сохранить обе роли одновременно. Сброс ключа каталога использует общий default; сброс строки подключения очищает подключение.

`LogFile`, `ResultFile` и `ErrorFolder` при сборке из Test Manager задаёт KOT: каждой части нужны собственные служебные файлы. Старые значения профиля сохраняются и показываются только для чтения. `CompileFile` и `JUnitFile` используются как пути итоговых объединённых файлов.

`SplitFeatureFiles` — доработка компилятора Drive. Параметр доступен при `assembleScript.showDriveFeatures=true`. При отключении Drive его сохранённое значение остаётся в профиле, но в JSON для стокового компилятора не передаётся.

### Проверка перед сборкой

Известные параметры имеют подсказки типов: Boolean, порт, число секунд, количество попыток/частей и XML dateTime. Например, `DetectionTime` принимает `2026-10-15T12:30:00Z` или полную дату и время без часового пояса. Неверные календарные даты не принимаются. Нестандартные ключи остаются строками; некорректное импортированное значение сохраняется в черновике для исправления и не подменяется автоматически. Экспорт JSON и запуск сборки требуют корректных значений.

Test Manager проверяет параметры, включённые исходники, связанные настройки и зависимости **до подготовки стартовой базы 1С, изоляции выключенных настроек и очистки артефактов**. Несохранённый выбранный YAML нужно сначала сохранить. Дубликаты UID и превышение 100 комбинаций выбранной настройки останавливают сборку; сообщения находятся в выводе KOT. Учитываются отборы профиля, переопределения параметров настройки и отличие верхнего процесса от вложенного. Настройки вложенных определений не считаются отдельными корневыми тестами, если они не включены в Test Manager.

Несовместимый с ограниченным reader формат YAML и ограничения process route выдаются предупреждениями: `ExceptionTags` и `Выключена` не работают для процессов; defaults верхнего процесса не копируются из `ПараметрыСценария`; `;` в параметрах настройки процесса не создаёт отдельные варианты. Подробности и явное заполнение defaults описаны в [параметрах процессов](compiler-process-parameters.md). Исходники при проверке не переписываются.

Нюанс обработки СППР:

- ключи параметров нормализуются;
- обработка игнорирует регистр, пробелы, `-` и `_`;
- поэтому `FeatureFolder`, `feature_folder` и `feature-folder` для нее эквивалентны.

Нюанс KOT:

- `FeatureFolder` управляет именно выходными `feature/json` артефактами СППР;
- настройка расширения `kotTestToolkit.runtime.directory` используется как отдельная служебная runtime-папка KOT для `yaml_parameters.json`, логов и временных файлов сборки; по умолчанию это `.vscode/kot-runtime`;
- это разные роли, и их не стоит смешивать концептуально, даже если физически пути могут быть рядом.

## 2) Дополнительные параметры Vanessa

Используется для VAParams-ключей, которые не покрываются обработкой СППР полностью.

Кнопка **+** открывает поиск по каталогу параметров Vanessa, включая русские/английские имена и вложенные JSON-пути. Выбор **Custom parameter…** позволяет задать свой ключ. Каталог сформирован из `СтруктураОбщихНастроек` модуля объекта и `ИменаКлючейОбщихНастроек` модуля формы официальной Vanessa. Если в настроенном каталоге Vanessa доступна выгрузка исходников, список читается из неё; для EPF без исходников используется встроенный каталог (319 записей). Интернет при открытии списка не требуется.

Для обновления встроенного каталога разработчиком: `node tools/updateVanessaParameterCatalog.cjs <ObjectModule.bsl> <Form/Module.bsl> [JsonParamsRU.md]`. Разбираются объявления настроек, BSL не выполняется. Неизвестные расширению ключи можно добавить вручную.

Типы полей определяются по объявлениям в `СтруктураОбщихНастроек`: логические значения выбираются из `true/false`, числа вводятся в числовом поле, массивы и объекты — в многострочном JSON. Русские и английские имена, вложенные пути и JSON Pointer используют один каталог. Поля без известного типа остаются текстовыми. Справа, как на вкладке СППР, показываются описание выбранного параметра из `docs/JsonParams`, тип и английское имя; ширину области можно менять.

Имя добавленного параметра защищено от произвольного редактирования; выпадающий список позволяет сменить его на эквивалентное русское или английское имя. Значение, JSON-тип и приоритет при этом сохраняются. Уже добавленные параметры, включая их альтернативные имена, скрыты в списке «+». Поиск в таблице работает по обоим именам. Значок информации показывает подсказку параметра, а подсказка Priority объясняет замещение значения в итоговом JSON.

Импорт `VAParams.json` сохраняет исходные JSON-типы, включая `false`, `0`, пустые строки и коллекции. Непустые массивы остаются одним полем JSON, вложенные объекты разворачиваются в параметры. Даже для неизвестного каталогу ключа импортированный тип определяет поле ввода. Строка `"false"` сохраняется строкой, а не превращается в логическое значение. Ошибочные значения не заменяются defaults: они остаются в черновике с подсветкой. Экспорт формирует вложенный JSON с сохранением типов.

При наличии исходников в настроенной папке Vanessa каталог строится из них. Версия читается из `ПолучитьВерсиюОбработки`; известный встроенный параметр, отсутствующий в этих исходниках, помечается предупреждением. Пользовательские ключи не считаются неподдерживаемыми только из-за отсутствия в стандартном каталоге. Строки профиля не удаляются и не исключаются из JSON автоматически. При смене профиля каталог обновляется в фоне; устаревший ответ для предыдущего профиля игнорируется. Для релизной поставки без исходников каталог и описания читаются из локального `docs/JsonParams/JsonParamsRU.md` (либо `JsonParamsEN.md`) рядом с EPF. Набор в списке добавления соответствует этой документации; известные типы и начальные значения берутся из встроенных подсказок KOT, для новых неизвестных ключей остаётся текстовый ввод. Версия документации читается из `docs/Changelog.md`. Если нет ни исходников, ни документации, используется встроенный каталог. Источник каталога показан один раз над таблицей. Документация не подтверждает поддержку внутри конкретного EPF; отсутствие поля в ней не вызывает предупреждения о несовместимости. Пути сборки Windows внутри текущего проекта сопоставляются с локальным проектом тем же способом, что пути артефактов.

В новом профиле включены `ИспользоватьКомпонентуVanessaExt`, `ИспользоватьПарсерGherkinИзКомпонентыVanessaExt` и `ПоискФайловСПомощьюКомпонентыVanessaExt`; `ShowHelperOnFirstLaunch` выключен. У этих четырёх строк включён приоритет над JSON компилятора, чтобы его стандартные значения не отключали выбранные defaults; значения и приоритет можно изменить в профиле. Существующие профили сохраняют свои параметры.

Результат:

- параметры мержатся в `combined JSON` рядом с built JSON;
- исходный built JSON от СППР при этом не переписывается;
- для каждой строки можно включить `Override existing value`, если нужно переопределить одноименный ключ из СППР.

## 3) GlobalVars

Используется для пользовательских глобальных переменных, которые мержатся в итоговый VAParams при запуске.

Фактически эти значения тоже попадают в `combined JSON`, который KOT использует для built-in запуска Vanessa.

Эти переменные также доступны в редакторе через подсказки `$$GlobalVar$$`.

## Профили и autosave

- Менеджер параметров хранит несколько профилей наборов параметров.
- Активный профиль выбирается из шапки панели или из меню кнопки `Build tests` в Менеджере тестов.
- Все изменения сохраняются автоматически.
- В шапке показывается `Updated at`, чтобы было видно, когда последний раз сохранилось текущее состояние.

## Операции в менеджере

- Редактирование ключей, значений и флагов `Override existing value`.
- Поиск по имени параметра на каждой вкладке.
- Для вкладки `СППР`: предпросмотр `yaml_parameters.json`, импортировать JSON, сбросить fixed-значения к default-набору.
- Для вкладки `Дополнительные параметры`: сохранить runtime JSON, импортировать VAParams/JSON, очистить секцию.
- Для вкладки `GlobalVars`: сохранить JSON, импортировать JSON, очистить секцию.

Что дополнительно помогает делать KOT:

- во вкладке `СППР` незаполненные обязательные поля подсвечиваются прямо в таблице;
- базовые строки закреплены вверху; обязательность зависит от CreateJson и AuthCompile;
- каталог базы и полная строка подключения редактируются независимо с указанными выше приоритетами;
- `AuthCompile` остается отдельным режимом строгой валидации, а не источником логинов/паролей;
- если `ModelDBSettings` пустой, KOT явно предупреждает, что СППР не сможет автоматически разрешать логины/пароли `TestClient` по профилю;
- импортированный `TestFolder` имеет приоритет над обоими каталогами: KOT переносит его значение в `ScenarioFolder` и `ProcessFolder`;
- остальные известные ключи СППР можно добавлять через searchable picker с кратким описанием;
- `ScenarioFilter` и `ExceptScenario` не добавляются вручную, потому что KOT формирует их автоматически по выбору чекбоксов в Test Manager;
- для модифицированных обработок можно добавлять и полностью произвольные custom-строки;
- при предпросмотре `yaml_parameters.json` KOT валидирует минимальный набор параметров;
- при автосохранении KOT не показывает отдельный apply-диалог, но все равно помечает обязательные незаполненные поля и сохраняет текущее draft-состояние профиля;
- при автосохранении KOT синхронизирует каталоги сценариев и процессов и пересканирует список тестов.
- URL, версия, ветка, дата, дополнительные аргументы и произвольные значения сохраняются без изменения разделителей; только известные файловые параметры разрешаются относительно проекта.

## Приоритеты и merge-логика

- Значения из СППР считаются базовыми.
- Дополнительные параметры позволяют дополнять `combined JSON` и точечно переопределять одноименные ключи.
- `GlobalVars` тоже умеют точечно перезаписывать существующее значение, если у строки включен `Override existing value`.
- По умолчанию при конфликте одноименного ключа значение из СППР выигрывает.

## Где это особенно полезно

- Нужно добавить параметр VA, который не поддерживается СППР «из коробки».
- Нужны проектные/локальные runtime-ключи без изменения стандартных шаблонов сборки.
- Нужно хранить и переиспользовать наборы GlobalVars.
