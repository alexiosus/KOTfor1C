# Параметры сценариев

Этот документ подробно описывает работу параметров в `ТекстСценария`, их объявление, передачу между вложенными сценариями и использование дефолтов.

## 1) Как объявить параметр

Параметры в тексте сценария задаются через квадратные скобки:

```yaml
ТекстСценария: |
    #language: en

    And I create sales invoice
    And I input [DocumentNumber] text in the field named "Number"
    And I input [Counterparty] text in the field named "Counterparty"
```

Если включено автозаполнение секций при сохранении, расширение автоматически поддерживает блок `ПараметрыСценария`.
При вводе `[` в `ТекстСценария` IntelliSense показывает параметры, уже объявленные в `ПараметрыСценария` текущего YAML-сценария.

## 2) Блок ПараметрыСценария и дефолты

Пример блока с дефолтными значениями:

```yaml
ПараметрыСценария:
    - ПараметрыСценария1:
        НомерСтроки: "1"
        Имя: "DocumentNumber"
        Значение: "000000001"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
    - ПараметрыСценария2:
        НомерСтроки: "2"
        Имя: "Counterparty"
        Значение: "Main Company"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
```

Если при вызове параметр не передан, используется `Значение` из блока `ПараметрыСценария`.
Hover по `[ParameterName]` в `ТекстСценария` показывает это значение и дает быстрое действие для его редактирования через стандартный `InputBox`. Для табличного или многострочного YAML-значения действие открывает и выделяет исходное значение в редакторе.

Многострочный строковый default вложенного сценария сохраняется в его шапке: при вставке вызова KOT оставляет такой параметр без явного присвоения, и компилятор использует исходный default. Это сохраняет переносы строк. Многострочное значение родительского параметра передаётся ссылкой `[Имя]`.

## 3) Передача параметров во вложенный сценарий

```yaml
ТекстСценария: |
    #language: en

    And Create sales invoice
        DocumentNumber = "000000123"
        Counterparty   = [Counterparty]
```

Поддерживается:

- строки в двойных кавычках;
- строки в одинарных кавычках;
- ссылка на параметр текущего контекста через `[ParamName]`.

## 4) Сквозная передача через несколько уровней

```yaml
# Главный сценарий вызывает Create sales invoice
And Create sales invoice
    DocumentNumber = "000000123"
    Counterparty   = "John Doe"

    # Внутри происходит вызов Prepare sale document
    And Prepare sale document
        DocNo = [DocumentNumber]

        # Внутри происходит вызов Fill document header
        And Fill document header
            Number = [DocNo]

            # Событие внутри Fill document header
            And I input [Number] text in the field named "Number"
```

В этом примере значение `DocumentNumber` проходит вниз по цепочке вызовов до шага ввода.

## 5) Quick Fix и диагностика

1. Если у вызова не хватает параметров, показывается предупреждение `Missing parameters`.
2. Quick fix может добавить отсутствующие параметры прямо в вызов.
3. Для добавляемых параметров берутся дефолты из `ПараметрыСценария` вызываемого сценария (если они есть).

## 6) Переменные `$...$` и `$$...$$`

При вводе `$` в блоке `ТекстСценария` доступны подсказки:

1. `$SavedVar$` — переменные, сохраненные выше по текущему тексту сценария.
2. `$$GlobalVar$$` — переменные из вкладки `GlobalVars` в Менеджере параметров.

Если начать сразу с `$$`, список будет отфильтрован только по `GlobalVars`.

Сохраненные переменные извлекаются из типовых RU/EN шагов `save/store/remember/read/create/...`, включая глобальные варианты (`globally`, `глобально`).

## 7) Важные правила

1. Имена параметров при вызове должны совпадать с именами в вызываемом сценарии.
2. Если квадратные скобки нужны как обычный текст, экранируйте их: `\[` и `\]`.
3. Один и тот же вложенный сценарий можно вызывать много раз с разными параметрами.

## 8) Возврат результата

Возвратный параметр задаёт имя выходной переменной Vanessa. Например, `Result = SavedResult` подставляет строку `SavedResult` вместо параметра `[Result]` во вложенном сценарии. Значение в эту переменную сохраняет шаг вложенного сценария при выполнении теста.

Пример вложенного сценария `CalculateTotal` (служебные метаданные опущены):

```yaml
ПараметрыСценария:
    - ПараметрыСценария1:
        НомерСтроки: "1"
        Имя: "Result"
        Значение: "Result"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Да"
ТекстСценария: |
    And I save "40+2" in [Result] variable
```

В родительском сценарии:

```yaml
ТекстСценария: |
    And CalculateTotal
        Result = SavedResult
    And I input "$SavedResult$" text in the field named "Amount"
```

После раскрытия вложенного сценария получится по смыслу:

```gherkin
And I save "40+2" in 'SavedResult' variable
And I input "$SavedResult$" text in the field named "Amount"
```

Первый шаг сохраняет `42` в переменную `SavedResult`, второй вводит `42` в поле `Amount`. `SavedResult` можно выбрать произвольно; объявлять его в родительском `ПараметрыСценария` не требуется. `[Result]` — подстановка при сборке, `$SavedResult$` — чтение переменной при выполнении. Сам `Return` ничего не вычисляет и не записывает: вложенный сценарий должен содержать шаг сохранения.

После `Return ` подсказка предлагает параметры вложенного сценария; после `as ` — имена уже известных переменных Vanessa. После вызова имя результата также доступно в подсказках по `$`. При автозаполнении шапки alias не добавляется как YAML-параметр. Объявления с `ИсходящийПараметр: "Да"` сохраняются даже для default, который не используется через `[Result]` в теле.

Равнозначная форма: `Возврат Result как SavedResult`. `Return Result` / `Возврат Result` передаст во вложенный сценарий имя `Result`, и переменную можно будет читать как `$Result$`.

Английская форма с alias по назначению записывается `Return Result as SavedResult`, но в предоставленной выгрузке `BuildScenarioBDD/Ext/ObjectModule.bsl:5750` есть ошибка: извлечение имени начинается с восьмого символа вместо седьмого, и `Result` превращается в `esult`. Для этой версии обработки используйте `Result = SavedResult` или `Возврат Result как SavedResult`.

## 9) Табличные параметры

В шапке вложенного сценария можно задать табличный default:

```yaml
ПараметрыСценария:
    - ПараметрыСценария1:
        НомерСтроки: "1"
        Имя: "Rows"
        Значение: |
            | Name | Amount |
            | Item | 100    |
        ТипПараметра: "Таблица"
        ИсходящийПараметр: "Нет"
```

Вставка вызова через подсказки или Library сохраняет таблицу:

```yaml
ТекстСценария: |
    And ProcessRows
        Rows =
            | Name | Amount |
            | Item | 100    |
        Currency = "USD"
```

`ProcessRows` в этом примере — ваш сценарий с параметрами `Rows` и `Currency`. В его теле `[Rows]` ставится отдельной строкой под шагом, принимающим таблицу. Например:

```yaml
ТекстСценария: |
    And "ItemList" table contains lines
        [Rows]
```

При передаче данных из примера выше компилятор раскроет это в:

```gherkin
And "ItemList" table contains lines
    | Name | Amount |
    | Item | 100    |
```

Здесь один шаг проверяет строки таблицы формы `ItemList`; имена колонок нужно заменить на колонки вашей формы. Назначение переданных данных определяется шагом Vanessa: проверка, заполнение или другое действие с таблицей.

Следующие за таблицей параметры разбираются и выравниваются как обычно. Объявленную в родительском сценарии таблицу можно передать ссылкой `Rows = [Rows]`. Если параметр не передан при вызове, используется табличный default вложенного сценария. Перезаполнение шапки сохраняет таблицу, тип и исходящий признак.

## 10) Несколько вариантов значений

Скалярный default `Значение: "USD;EUR"` у параметра главного теста даёт два варианта. Если другой параметр имеет `Значение: "100;200"`, компилятор создаст четыре сочетания:

```yaml
ПараметрыСценария:
    - ПараметрыСценария1:
        НомерСтроки: "1"
        Имя: "Currency"
        Значение: "USD;EUR"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
    - ПараметрыСценария2:
        НомерСтроки: "2"
        Имя: "Amount"
        Значение: "100;200"
        ТипПараметра: "Строка"
        ИсходящийПараметр: "Нет"
ТекстСценария: |
    And CreateInvoice
        Currency = [Currency]
        Amount = [Amount]
```

`CreateInvoice` — ваш вложенный сценарий создания документа. Для каждой комбинации компилятор создаёт отдельный текст теста с подставленными значениями:

| Currency | Amount |
|---|---|
| USD | 100 |
| USD | 200 |
| EUR | 100 |
| EUR | 200 |

Первый вариант вызовет `CreateInvoice` с `Currency = "USD"`, `Amount = "100"`; второй — с `USD` и `200`, далее — два варианта с `EUR`. При запуске полученных тестов создание документа выполнится для каждого набора данных. Два списка по два значения дают четыре теста. В предоставленном компиляторе действует предел в 100 сочетаний.

Возле строки `ПараметрыСценария:` KOT покажет `Вариантов: 4`; наведением можно увидеть первые восемь комбинаций. Число рассчитывается без построения всех сочетаний. Пустые варианты (`"a;;b"`) тоже учитываются.

Чтобы передать обычную точку с запятой, используйте экранирование: `Значение: 'a\;b;c'` даёт значения `a;b` и `c`. В двойных YAML-кавычках обратный слеш нужно удвоить: `Значение: "a\\;b;c"`. Значения типа `Таблица` по `;` не разделяются.

## 11) Препроцессор, блоки и комментарии

```yaml
ТекстСценария: |
    /* Этот фрагмент пропускается при сборке и автозаполнении:
       And InactiveScenario
    */
    #Если Истина Тогда
        And PrepareData
    #Иначе
        And PrepareFallback
    #КонецЕсли
```

`PrepareData` и `PrepareFallback` — имена ваших вложенных сценариев. Начните ввод с `#`, чтобы выбрать директиву. В отличие от runtime-конструкции `If … Then`, `#Если` выбирает ветку во время сборки. KOT проверяет вложенность, скобки и кавычки; BSL-выражение вычисляет внешняя обработка 1С.

Закрывайте каждый блок на том же языке: `Do` → `EndDo`, `Цикл` → `КонецЦикла`, `If` → `EndIf`, `Если` → `КонецЕсли`. Runtime-условия и препроцессор имеют разные закрывающие слова. Отступы помогают читать YAML, но компилятору всё равно нужны явные границы блоков.

## 12) Вставка цикла из Vanessa

Откройте `scen.yaml`, поставьте курсор внутри `ТекстСценария` и выберите в автодополнении шаг `I repeat "…" times`. Через Library можно вставить или перетащить тот же шаг. KOT добавит границы цикла; после заполнения количества повторений нажмите `Tab`, чтобы перейти к его телу:

```yaml
ТекстСценария: |
    #language: en
    Do I repeat "10" times
        And I close all client application windows
    EndDo
    And Delay "1"
```

Закрытие клиентских окон здесь выполняется десять раз, а задержка после `EndDo` — один раз. `EndDo` уже входит во вставленный шаблон. Для русских шагов аналогично добавляются `Цикл` и `КонецЦикла`. Для существующих YAML-сценариев замените начальное `And` у такого цикла на `Do` и добавьте `EndDo` после его тела.
