# 2. Попробуйте редактор

Для этого урока достаточно VS Code и KOT. Сохраните учебный проект в удобном месте или работайте в его копии.

## Подключите учебную библиотеку

Откройте **Параметры компиляции и запуска**. На вкладке СППР установите `Libraries = libraries`. Так KOT узнает, где искать [экспортный сценарий](../libraries/workshop.feature) и [исходник пользовательского шага](../libraries/user-steps/WorkshopSteps.bsl). Это не путь к встроенным шагам самой Vanessa: они доступны из её каталога.

Можно вместо ручного заполнения загрузить на вкладке СППР [config/sppr-build.json](../config/sppr-build.json) кнопкой импорта JSON. Этот профиль специально отключает создание JSON запуска при компиляции: для знакомства с исходниками готовая база не нужна.

## Подсказки и переходы

1. В [первом feature](../tests/vanessa/01-first-steps.feature) добавьте пустую строку и начните `And I save`. Вызовите подсказки `Ctrl+Space`. Подсказка шага объяснит его назначение.
2. Откройте [главный сценарий СППР](../tests/sppr/01-first-scenario/scen.yaml). Поставьте курсор на `I prepare workshop customer` и нажмите **F12**. Откроется вложенный сценарий.
3. Наведите указатель на вызов, параметр `[Customer]` и имя переменной. Затем попробуйте **Найти все ссылки** для сценария.
4. В Библиотеке найдите `I remember workshop message` и откройте его определение. В [третьем feature](../tests/vanessa/03-export-call.feature) вызывается именно этот экспортный сценарий.
5. Для поиска по смыслу попробуйте префикс `!` в начале новой строки шага. Результат зависит от загруженного каталога шагов.

## Почему пользовательский шаг виден в KOT, но не выполняется

Учебный `WorkshopSteps.bsl` показывает, как KOT находит шаг по исходнику. Готовой EPF-библиотеки для него в демо нет. KOT показывает его в Библиотеке как **Только исходник**, но не предлагает в IntelliSense и не позволяет вставлять или копировать до сборки. Выберите **Создать EPF-библиотеку…** в действиях шага; порядок подготовки описан [рядом с исходником](../libraries/user-steps/README.md). Если добавить такой вызов вручную без подключения EPF, Vanessa сообщит **«шаг не найден»**.

Отдельно проверьте язык Gherkin. В мастерской используется `en`, поэтому строки начинаются с `And`, `Given`, `When` или `Then`. Русский текст после ключевого слова допустим: `And я показываю учебное сообщение`. Для русского префикса `И` нужна feature с языком `ru`. Комментарий `#language: ru` внутри вложенного сценария не переключает язык собранной feature; не смешивайте префиксы разных языков в одном тесте.

## Параметры и таблицы

В СППР `[Customer]` — параметр, который подставляется при компиляции. В Vanessa `$WorkshopCustomer$` — значение переменной во время выполнения. Кавычки в вызове экспортного сценария задают аргумент вызова.

В [feature с примерами](../tests/vanessa/02-examples-table.feature) измените ширину колонок таблицы `Examples`, затем сохраните файл. KOT выравнивает таблицу, если включено выравнивание таблиц Gherkin при сохранении.

В свойствах [вложенного сценария](../tests/sppr/03-reusable-customer/scen.yaml) поменяйте значение `Customer` по умолчанию и сохраните. Главный сценарий может переопределить его при вызове. Верните учебное значение после упражнения.

## Диагностика без испорченного демо

Откройте [строки для упражнения](../exercises/diagnostics.txt). Вставьте один пример в копию главного сценария, посмотрите подсветку ошибки, наведите указатель и вызовите **Быстрое исправление**. Первый пример содержит неизвестный аргумент, второй — необъявленный параметр. После проверки отмените правку.

KOT также поддерживает списки параметров и вложенных сценариев по тексту. Попробуйте добавить корректный вызов в раздельный [scen.feature](../tests/sppr/02-feature-and-metadata/scen.feature), сохранить и посмотреть изменения соседнего [meta.yaml](../tests/sppr/02-feature-and-metadata/meta.yaml). Функции автозаполнения можно отключить в настройках редактора.
