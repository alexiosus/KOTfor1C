В процессе раскройте `ШагиПроцесса`: у каждого шага есть собственные параметры. Общее имя параметра само по себе не передаёт значение во все шаги — используйте явную передачу.

## Передайте параметр во вложенный сценарий

В первых примерах главный сценарий передаёт покупателя во вложенный:

```gherkin
And I prepare workshop customer
    Customer = [Customer]
```

Имя слева — параметр вложенного сценария, `[Customer]` справа — значение из текущего. В этой строке квадратные скобки пишутся **без кавычек**. Запись `Customer = "[Customer]"` передаст текст `[Customer]` буквально. В обычном шаге строковый аргумент по-прежнему может выглядеть как `And I save "[Customer]" in "WorkshopCustomer" variable`: это другой контекст.

После сборки откройте feature и найдите вложенный шаг сохранения: вместо `[Customer]` там должно стоять конкретное имя покупателя. В двух настройках примера «Заявка с вариантами данных» ожидаются соответственно «Первый покупатель» и «Второй покупатель» — в обоих шагах сохранения.

## Подготовьте компиляцию

1. Установите платформу 1С на Windows и укажите обработку **СборкаТекстовСценариев.epf** из СППР в настройках KOT. [Подробная настройка](../../../docs/SETUP.md) описывает подготовку служебной базы.
2. На вкладке СППР в **Параметрах сборки и запуска** проверьте профиль **KOT Workshop**: `ScenarioFolder`, `ProcessFolder`, `FeatureFolder` и `Libraries` уже заполнены относительно открытой папки мастерской. Если вы меняли значения, восстановить эту часть можно импортом [sppr-build.json](../config/sppr-build.json).
3. В Менеджере тестов отметьте один главный сценарий и нажмите **Собрать**. Отметки означают включение в компиляцию, а не выбор открытого файла.
4. Посмотрите созданный feature и отчёт компилятора. Перейдите по ссылке на исходник. Успешная компиляция проверяет подготовку теста, но не прохождение его шагов.
5. Измените строку во вложенном сценарии и сохраните. Зависимая сборка станет устаревшей. Повторите с экспортным сценарием: он читается из библиотеки при выполнении, поэтому текст собранной feature может остаться прежним, но KOT всё равно отмечает изменение зависимости.

Посмотрите [пример отчёта о сборке](../../../docs/guides/build-and-vanessa-run.md#разобрать-результат-компиляции): у одного теста создан результат, а у другого ссылка ведёт к ошибке в `scen.feature`. [Меню профилей](../../../docs/guides/parameters-manager.md#профили-принадлежат-проекту) показывает, как выбрать, создать или импортировать профиль проекта.

Учебный профиль имеет `CreateJson = false`: он предназначен для просмотра результатов компиляции. Для полного запуска включите `CreateJson`, заполните `VanessaFolder`, `LaunchDBFolder`, каталог эталонных баз и реальные данные окружения. Пустой путь выгрузки в учебном [bases.yaml](../config/bases.yaml) необходимо заменить своим, если используется восстановление эталонной базы.

## Создайте и преобразуйте свой сценарий

Нажмите **+** в Менеджере тестов или Библиотеке. Мастер предлагает главный или вложенный сценарий, процесс и самостоятельный feature. Для нового сценария выберите автора серии, имя, формат и остальные поля. Учебная серия `900001` уже имеет несколько занятых номеров; следующий код выдаёт KOT.

В свойствах или контекстном меню откройте **Преобразования…**. В копии примера попробуйте:

- один YAML ↔ текст feature + метаданные YAML;
- главный ↔ вложенный сценарий или процесс;
- вложенный ↔ экспортный сценарий.

При создании экспортного сценария все параметры должны присутствовать в названии аргументами. Можно выбрать отдельный feature-файл или существующий файл библиотеки. KOT обновляет поддерживаемые вызовы; после операции проверьте список ссылок, параметры и результат компиляции. Исходящие и табличные параметры могут ограничивать преобразование: сообщение KOT объяснит причину.
