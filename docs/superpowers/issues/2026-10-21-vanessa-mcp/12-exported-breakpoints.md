# [MCP] Проверить остановку на точке внутри вызова экспортного сценария

Тип: **Требует подтверждения разработчиком / возможная ошибка**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

При живой проверке .45 точка внутри экспортного вызова была пропущена, хотя обычная точка в основном сценарии и цикле работала. При пошаговой отладке через MCP нужно иметь возможность остановиться внутри библиотечного сценария, проверить переменные и продолжить выполнение. Важен также случай, когда один экспортный сценарий вызывается несколько раз из разных мест.

## Воспроизведение

1. Создать минимальную feature с вызовом экспортного сценария из библиотеки.
2. Поставить через manage_breakpoints точку на исполняемом шаге внутри экспортного сценария и проверить list.
3. Запустить вызывающий сценарий через MCP.
4. Сравнить с точкой на обычном шаге вызывающего сценария и с поведением UI Vanessa.

Перед публикацией нужно приложить минимальное воспроизведение из двух самодостаточных feature: вызывающего сценария и библиотеки. Пока это наблюдение из контрольного прогона и план повторной проверки, а не доказательство общей невозможности точек во всех экспортных сценариях.

## Ожидаемое и фактическое поведение

Ожидается остановка перед выбранным шагом конкретного вхождения вызова либо явный unsupported-ответ. При проверке точка была пропущена. Нужна также документированная семантика точки в библиотеке, вызванной несколько раз.

## Предложение

Проверить, относится ли поведение к исполнителю или MCP-синхронизации точек. Если режим не поддержан, явно сообщать ограничение. В MCP-ответе полезно возвращать идентификатор конкретного вызова и исходную позицию текущего шага внутри экспортного сценария, чтобы различать повторные вызовы одной библиотеки.
