# [MCP] Возвращать состояние записи до первого запуска feature

Тип: **Ошибка / неполный ответ состояния**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

После загрузки feature, которая ещё не запускалась, `get_vanessa_automation_state` возвращает краткий текст о загруженном файле без признака записи. MCP-клиент не может определить, идёт ли запись и требуется ли отправлять Start или Stop. Start в этой версии переключает запись, поэтому повторный вызов без чтения состояния может дать противоположный результат.

## Воспроизведение

1. Открыть feature через MCP, не выполнять ни одного шага.
2. Запросить `get_vanessa_automation_state`.
3. Начать/остановить запись через UI Vanessa и повторить чтение состояния, по-прежнему не запуская feature.

## Ожидаемое и фактическое поведение

Признак записи должен возвращаться независимо от наличия истории исполнения feature. Сейчас краткая ветка ответа не содержит флаг, хотя в обычном состоянии он есть.

## Предложение

Сделать `recording` обязательным полем состояния либо добавить read-only status в `user_actions_recording`. Желательно сделать Start/Stop идемпотентными или документировать переключающий характер Start. Не требовать запуска сценария ради чтения записи.
