# [MCP] Структурированные состояния, результаты и стабильные идентификаторы шагов

Тип: **Расширение API / надёжность интеграций**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

При автоматическом чтении состояния и результатов выполнения MCP-клиенту нужно однозначно различать поля ответа, пользовательский текст и отдельные выполнения шагов. Проверенные инструменты возвращают Markdown, в который встроены пользовательские названия и сообщения ошибок. Эти значения могут содержать переносы и `##`, совпадающие с заголовками ответа. Кроме того, одинаковый текст шага может встречаться в разных сценариях, циклах и вызовах библиотечного сценария.

## Воспроизведение

1. Выполнить сценарий с двумя одинаковыми текстами шагов в разных местах/вложенных вызовах.
2. Получить `get_test_results` и `get_vanessa_automation_state`.
3. Проверить возможность однозначно связать каждый результат с исходной строкой.
4. Отдельно получить ошибку с многострочным текстом, содержащим Markdown-заголовок `##`, и проверить структуру state-ответа.

## Ожидаемое и фактическое поведение

**Ожидается:** состояние и результаты можно прочитать программно без разбора оформления Markdown. Каждый результат связан с конкретным запуском и выполнением шага, а сообщение ошибки передаётся отдельным полем.

**Фактически:** произвольные значения смешиваются с текстовым оформлением, а в части результатов отсутствует достаточная идентичность шага для однозначного сопоставления. Совпадение текста шага не позволяет различить повторные вызовы и строки с одинаковыми именами.

## Предложение

Предоставить structuredContent или `format=json` без удаления текстового представления: protocolVersion, runId, feature URI/revision, scenario/call ID, step ID, line, status, error/message и current/next step. Не включать секреты автоматически. Ошибка шага должна отличаться от ошибки самого MCP транспорта.
