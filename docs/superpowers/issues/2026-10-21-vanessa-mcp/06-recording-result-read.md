# [MCP] Читать результат записи без повторного Stop и потери текста

Тип: **Расширение API**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

Если пользователь завершил запись кнопкой в Vanessa, MCP-клиент при доступном полном ответе состояния видит recording=false, но не имеет отдельной операции чтения уже сформированного текста. На собственной .45 проверено: первый Stop вернул примерно 300 символов, второй — пустой результат. Получение текста через второй Stop поэтому непригодно.

## Воспроизведение

1. Начать запись, выполнить несколько действий в собственном тест-клиенте.
2. Остановить запись кнопкой Vanessa.
3. Попытаться получить сформированные шаги через MCP.
4. Вызвать `user_actions_recording {"action":"stop"}` повторно и сравнить сохранённый текст.

## Ожидаемое и фактическое поведение

Нужен read-only способ получить последний завершённый буфер, который не останавливает новую запись и не перезаписывает старую. Сейчас в проверенной схеме есть Start/Stop, но нет get-result; повторный Stop может заменить результат пустым.

## Предложение

Добавить `status` и `get_result` с capture ID/version, флагом завершения и текстом; повторное чтение не изменяет буфер. Полезен явный acknowledge/clear по ID. Это позволит получать и сохранять результат записи после остановки пользователем, не вмешиваясь в новую запись и не изменяя уже сформированный буфер.
