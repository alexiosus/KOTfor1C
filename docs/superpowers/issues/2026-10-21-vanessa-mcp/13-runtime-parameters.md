# [MCP] Читать и применять настройки VAParams в уже работающем сеансе Vanessa

Тип: **Расширение API / надёжность интеграций**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Наличие такого API в текущем develop не проверялось; перед публикацией нужно сверить актуальный `tools/list`.

## Задача

Нужно запускать разные feature в одном работающем менеджере тестирования, применяя настройки их запуска из VAParams.json. Повторный запуск менеджера ради смены настроек занимает время и прерывает удобный интерактивный сеанс. Запуск следующего feature со старыми настройками тоже неприемлем: выбранные клиенты, язык, переменные и другие параметры могут отличаться.

В проверенной схеме MCP есть открытие feature, запуск и отдельные операции с профилями клиентов/переменными, но нет операции чтения и применения полного набора параметров запуска. Открытие другого feature само по себе не подтверждает, что его VAParams были загружены. Изменение файла VAParams.json на диске также не даёт такого подтверждения.

## Воспроизведение ограничения

1. Подготовить два набора настроек запуска A и B с заметным различием, например языком генератора Gherkin или набором профилей тест-клиентов.
2. Открыть Vanessa с MCP и настройками A.
3. Через `tools/list` проверить доступные операции управления настройками.
4. Открыть и выполнить второй feature через MCP. Попытаться сначала применить B и прочитать подтверждение его применения, не перезапуская менеджер.

В `.45` такого публичного контракта не найдено. Можно отдельно управлять некоторыми клиентами и переменными, но это не эквивалент загрузки полного VAParams.

## Ожидаемая возможность

Добавить MCP-операции для безопасного чтения описания активного набора и явной загрузки нового. Возможные имена ниже — предложение, а не существующий API:

- `get_runtime_parameters`: идентификатор/ревизия набора, перечень применённых ключей и исходный файл; секретные значения должны скрываться.
- `apply_runtime_parameters`: загрузить объект или JSON-файл на машине сервера с указанной базой разрешения относительных путей, проверить его и применить через штатный механизм Vanessa.

Применение настроек не должно автоматически выполнять сценарий или подключать/закрывать тест-клиентов. Для несовместимых изменений при запущенном сценарии, записи или подключённых клиентах нужен определённый контракт: отказ с причиной либо явная политика вызывающей стороны.

В результате полезны новая ревизия, успешно применённые ключи, неподдерживаемые параметры и изменения, требующие переподключения клиента или перезапуска менеджера. Частичное применение должно быть явно отличимо от полного успеха. При невозможности атомарного применения это нужно сообщать до запуска следующего feature. Строки подключения, пароли и токены не должны попадать в общую диагностику ответа.

## Почему отдельных операций недостаточно

Открытие feature меняет исходник сценария, а не весь контекст запуска. Управление профилями клиентов и переменными покрывает только часть VAParams. Без подтверждаемой ревизии вызывающая сторона не может отличить активные настройки от содержимого старого файла на диске или настроек, изменённых вручную в интерфейсе.

## Частный случай: временный журнал выполнения

Внешнему клиенту также нужно прочитать, временно задать и затем восстановить `ИмяФайлаЛогВыполненияСценариев` / `textlogname` у уже работающего менеджера. Это позволяет получать полную последовательность шагов в существующем сеансе, когда `get_test_results` возвращает только последний сценарий. Желательно подтверждение фактически применённого пути и безопасная область действия на один запуск. Изменять JSON на диске недостаточно: менеджер может уже загрузить настройки и продолжить писать в прежний файл.
