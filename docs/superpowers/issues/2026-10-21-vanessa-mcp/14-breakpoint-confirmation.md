# [MCP] manage_breakpoints подтверждает переключение, но list не отражает изменение

Тип: **Ошибка, воспроизведённая в проверенном сеансе; причина внутри редактора требует диагностики**.

Проверено 28 октября 2026 года: **Vanessa Automation 1.2.043.45**, Windows 11 в Parallels, тонкий клиент **1С 8.5.1.1522**. Актуальный develop и другие версии платформы не проверены.

Дополнение: пользователь сообщил, что после перезапуска сеанса точки снова устанавливаются. Следовательно, наблюдение относится к периодическому сбою состояния сеанса, а не к постоянной недоступности операции в `.45`. Действие, вызывающее этот сбой, пока не установлено. Отдельно замечен сброс уже установленных точек после `execute_feature_step`; его нельзя автоматически считать той же причиной.

Для отдельного случая после выполнения шага установлен конкретный механизм: [разный регистр пути создаёт вторую вкладку того же файла](15-editor-path-aliases.md). Точки остаются в прежней вкладке, а список читается у новой. Это объясняет проверенное расхождение после шага, но не доказывает причину первоначального отказа `toggle` до выполнения шага.

## Проблема

В открытой сохранённой feature команда `manage_breakpoints` с действием `toggle` отвечает успешным сообщением, однако последующие вызовы `list` продолжают сообщать об отсутствии точек. Проверялся обычный исполняемый шаг основного сценария, а не только вызов экспортного сценария.

Перед переключением через `get_editor_state(includeContent=true)` проверены активный файл, отсутствие несохранённых изменений и совпадение текста с файлом на диске с учётом окончаний строк. Сеанс не выполнял тест.

## Последовательность фактической проверки

1. Вызвать `get_editor_state` и убедиться, что активна нужная сохранённая feature.
2. Вызвать `manage_breakpoints` с `{"action":"list"}`. Получено: точек останова нет.
3. Один раз вызвать `manage_breakpoints` с `{"action":"toggle","line":28}`. На строке 28 находился обычный шаг `And In the command interface I select "Sales" "Customers"`.
4. Получен ответ без `isError`:

   ```text
   # Брейкпоинт переключён

   - Строка: 28
   ```

5. Читать `list`, не повторяя `toggle`. Через 0, 206, 585, 1120, 1977, 3201 и 5253 мс список оставался пустым. Ответ содержал также подсказку «Файлы не открыты», хотя `get_editor_state` возвращал активную вкладку и её содержимое.

Проверка через `select_step(lineNumber=30)` подтвердила выбор строки 30 в `get_editor_state`. Затем `manage_breakpoints(action="toggle", line=0)` также вернул успех, но последующие чтения в течение двух секунд оставались пустыми. Это диагностическая проверка обхода, а не требование поддерживать нулевой номер строки.

Вызов без `line` возвращал `ACTION_FAILED: Ошибка: Преобразование значения к типу Число не может быть выполнено`. В журнале регистрации менеджера за соответствующий период ошибок не найдено.

## Ожидаемое поведение

После успешного переключения `list` возвращает новый набор точек. Если применение асинхронное, нужен способ дождаться подтверждения либо явный ответ о том, что изменение ещё не применено. Если редактор недоступен или операция не поддерживается, инструмент должен вернуть ошибку вместо подтверждения успеха.

## Что пока не установлено

- Произойдёт ли фактическая остановка при запуске: в этой проверке тест не выполнялся.
- Относится ли проблема к передаче команды в редактор, обработке события `UPDATE_BREAKPOINTS` или чтению сохранённого списка.
- Воспроизводится ли тот же эффект при ручной установке мышью в Vanessa: надёжно подтвердить эту часть через удалённое управление не удалось.
- Воспроизводится ли проблема в минимальном новом файле и на других версиях платформы. Для повторной проверки подойдёт самостоятельная feature с несколькими шагами `And Delay 1`.

Это отдельная проблема от [точек внутри экспортных сценариев](12-exported-breakpoints.md): здесь расходятся подтверждение изменения и последующее чтение списка ещё до выполнения теста.

## Предложение

Проверить цепочку `toggleBreakpoint` → `UPDATE_BREAKPOINTS` → `БрейкпоинтыVanessaEditor`. Подтверждать изменение после обновления данных редактора и возвращать фактические файл, строку и состояние точки. Для интеграций полезны идемпотентные действия `set` / `remove`: повторять `toggle` при неизвестном результате нельзя, поскольку повторный вызов может снять уже установленную точку.

Исходники проверенной версии: [MCPVA](https://github.com/Pr-Mex/vanessa-automation/blob/a9625b83adfe0612da2adf750d82ca7993d73a70/VanessaAutomation/Forms/MCPVA/Ext/Form/Module.bsl), [РедакторТекста](https://github.com/Pr-Mex/vanessa-automation/blob/a9625b83adfe0612da2adf750d82ca7993d73a70/VanessaAutomation/Forms/РедакторТекста/Ext/Form/Module.bsl).

Черновик для ручной публикации. Пути рабочих проектов, строки подключения и данные пользователей исключены.
