# [MCP] Разный регистр пути создаёт две вкладки одной feature и неоднозначное состояние редактора

Тип: **Ошибка, воспроизведённая 28 октября 2026 года**.

Окружение: **Vanessa Automation 1.2.043.45**, Windows 11 в Parallels, тонкий клиент **1С 8.5.1.1522**. Актуальный develop не проверен.

## Проблема

При выполнении шага через `execute_feature_step` Vanessa открывает вторую вкладку того же физического файла, если регистр буквы диска в `filePath` отличается от уже открытой вкладки. Точки остаются в прежней вкладке, а новый активный экземпляр их не содержит.

В `get_editor_state` обе вкладки помечаются как активные. Потребитель ответа не может однозначно определить, к какому экземпляру относятся содержимое и список точек.

## Фактическая проверка

1. В Vanessa открыта сохранённая feature с путём, начинающимся с `c:\`.
2. Через `manage_breakpoints` установлена и подтверждена точка на строке 28.
3. Вызван `execute_feature_step` для другого шага — сохранения значения в переменную на строке 26. В `filePath` передан тот же путь с буквой диска `C:`.
4. После вызова появились две вкладки одной feature, а `manage_breakpoints(action="list")` вернул пустой список для нового активного экземпляра.
5. `get_editor_state` вернул две строки с маркером `**→**`. Пути отличаются только регистром буквы диска. Несохранённых изменений не было.
6. После закрытия второй чистой вкладки исходная снова вернула ранее установленную точку на строке 28.

Обезличенный фрагмент фактического ответа; рабочий путь заменён примером:

```text
## Открытые вкладки
Количество: 3

- memory:welcome
- **→** c:\Tests\example.feature
- **→** C:\Tests\example.feature
```

## Ожидаемое поведение

На Windows оба написания пути должны активировать одну вкладку существующего файла. В ответе о состоянии редактора должен быть один активный экземпляр. Его точки должны сохраняться при выполнении другого шага.

Сравнение путей следует выполнять с учётом платформы: нельзя безусловно приводить пути к нижнему регистру на системах с чувствительной к регистру файловой системой.

## Контрольный обход

Если передавать в `execute_feature_step` точное написание пути из единственной открытой вкладки, новая вкладка не появляется. В повторной живой проверке список точек до и после шага совпал: `[28, 29]`.

Связанные ограничения: [повторная загрузка при одном шаге](07-step-without-reload.md), [неподтверждённое переключение точки](14-breakpoint-confirmation.md). Последнее наблюдалось отдельно; тождество его причины этой ошибке не доказано.

Черновик для ручной публикации. Шаг работал только с переменной и не изменял данные прикладной базы. Рабочие пути и данные пользователей исключены.
