# [MCP] Выполнять шаг уже загруженной feature без повторной загрузки

Тип: **Расширение API / производительность**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

Пошаговое выполнение через MCP-инструмент `execute_feature_step` заметно медленнее шага из UI Vanessa. В собственных Delay-only проверках вызов занимал 3,5–5,0 с; соседние служебные RPC — десятки/сотни миллисекунд. Внутренний путь повторно загружает feature, даже если она уже открыта.

## Воспроизведение

1. Загрузить небольшую сохранённую feature с простыми шагами и открыть её в редакторе Vanessa.
2. Выполнить соседние строки через `execute_feature_step` с тем же filePath.
3. Сравнить время с пошаговым выполнением уже загруженной feature в UI.
4. Повторить после смены файла и без неё; записать время загрузки отдельно от выполнения.

## Ожидаемое и фактическое поведение

Желателен режим шага по уже подтверждённому содержимому редактора, без повторной загрузки feature и библиотек при каждом пошаговом запросе. Сохранность переменных, выбранного клиента и точек должна быть явной частью контракта.

## Предложение

Добавить режим loaded/current с проверкой feature ID/content revision. При несовпадении revision возвращать source_changed вместо молчаливого выполнения устаревшего текста. Оставить текущий reload-режим для совместимости. В ответе полезны executed line ID и actual next line ID.
