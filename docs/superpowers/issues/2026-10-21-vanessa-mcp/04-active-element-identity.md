# [MCP] Возвращать идентичность активного элемента тест-клиента

Тип: **Расширение API**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

Через MCP можно прочитать дерево формы и свойства элемента по имени, но в проверенном API не найден способ определить активный элемент в модели TestClient. Например, после перехода пользователя между двумя полями одного окна нужно узнать, какое поле теперь имеет фокус, и запросить именно его свойства или связать с ним сгенерированные шаги. Заголовок окна и имя формы при этом не меняются.

## Воспроизведение

1. Прочитать `get_form_analysis {"format":"elements","compact":false}`.
2. Перевести фокус в клиенте между двумя полями одной формы.
3. Запросить `get_active_window_data` для доступных `type`; сравнить ответы.
4. В схеме доступны свойства окна/формы, но нет имени активного элемента тестируемой формы.

## Ожидаемое и фактическое поведение

Ожидается отдельный read-only ответ: клиент, окно, форма, имя/ID активного элемента, для таблицы — таблица/колонка и при возможности текущая строка. Сейчас идентичность окна не различает смену поля. `manage_uiautomation get_active` — другой, OS/UIA-уровень и не является переносимой идентичностью элемента модели TestClient.

## Предложение

Расширить `get_active_window_data` либо добавить `get_active_form_element`. Стабильные ID желательно использовать также в дереве/подробностях; для отсутствующего фокуса возвращать явное пустое состояние. Read-only запрос должен работать без перемещения фокуса и без запуска интерактивного режима выбора элемента. Такой запрос позволит отслеживать смену активного поля независимо от смены окна.
