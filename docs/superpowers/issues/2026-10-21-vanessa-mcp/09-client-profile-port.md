# [MCP] Добавить чтение и изменение порта в профилях тест-клиентов

Тип: **Расширение API**.

Проверенная версия: **Vanessa Automation 1.2.043.45**, исходники commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Новейший develop в рамках этого черновика не проверен; перед публикацией стоит проверить воспроизведение на актуальной версии.

## Задача

При управлении тест-клиентами через MCP нужна возможность полностью настроить профиль подключения, включая порт. Например, на одном компьютере могут использоваться несколько клиентов с разными портами, либо клиент должен подключаться через заранее выбранный нестандартный порт.

Сейчас `manage_test_client_profiles` позволяет задать базу, тип клиента, компьютер и дополнительные параметры, но в проверенной схеме нет отдельного поля порта. Поэтому настройку такого подключения нельзя завершить и проверить только через этот инструмент: приходится дополнительно использовать интерфейс Vanessa или параметры запуска.

## Воспроизведение

1. Запустить Vanessa с MCP.
2. Подготовить профиль тест-клиента, для которого требуется порт `1540`.
3. Запросить `tools/list` и проверить схему `manage_test_client_profiles`.
4. Попытаться создать профиль действием `add` либо изменить его действием `edit`, указав этот порт. Сравнить доступные поля с настройками подключения в интерфейсе Vanessa.
5. Запросить профили действием `get_list` и проверить, можно ли прочитать и подтвердить установленный порт.

## Ожидаемое и фактическое поведение

**Ожидается:** порт можно задать при создании профиля, изменить у существующего профиля и прочитать вместе с остальными настройками подключения.

**Фактически:** проверенный контракт `add/edit/get_list` не предоставляет полного эквивалента этого поля. Передача неописанного параметра `port` не является поддерживаемым способом настройки и не позволяет считать изменение подтверждённым.

## Предложение

Добавить необязательный параметр `port` в действия `add` и `edit`, а также возвращать фактический порт в `get_list`.

- Проверять тип и допустимый диапазон порта, возвращать понятную ошибку при некорректном значении.
- При отсутствии `port` сохранить совместимое поведение: для `edit` не менять текущий порт, для `add` использовать штатное значение по умолчанию.
- Не менять остальные поля профиля при редактировании только порта.
- Если изменение требует переподключения или перезапуска уже работающего клиента, явно сообщать об этом в результате операции.
