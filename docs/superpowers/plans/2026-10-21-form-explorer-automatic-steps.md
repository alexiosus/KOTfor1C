# Automatic Form Explorer steps implementation plan

**Goal:** full form checks in Current form, automatic native steps for the selected client element, latest-selection queue and bounded state-validated in-memory cache.

**Approved behavior:** selecting a KOT element may transfer focus to that element in the test client (explicit user answer). No click/value edit is substituted for focus. Existing repository/TypeScript/webview and session serialization are retained; current dirty feature branch is reused.

**Constraints:** .45 has no confirmed cooperative cancellation of form analysis, cheap whole-form revision, portable active-element getter or current-element checks endpoint. Client HTTP abort must not release the session lock while the old Vanessa analysis can still finish. Obsolete replies and remaining RPCs are cancelled logically; last selection runs after the old call settles. Cache must check fresh reported form state and selected-element properties; missing/ambiguous state means no cache reuse. Native suggestions and actual current-element checks remain distinct.
