# Возможности KOT и ограничения MCP Vanessa

Состояние реализации на 2026-10-23. Проверяемый upstream-контракт — Vanessa Automation **1.2.043.45**, commit `a9625b83adfe0612da2adf750d82ca7993d73a70`, локальные исходники `Forms/MCPVA`, `Forms/ИсследовательФормы`, `Forms/КлиентТестирования`; отмена задач дополнительно сверена с client-mcp-devkit 0.6.6. Это не утверждение о текущем develop или произвольном выбранном EPF. Инструменты доступны только при подходящей объявленной схеме текущего MCP-сеанса.

## Реализовано

| Область | Что доступно | Граница |
|---|---|---|
| Подключения и клиенты | Connect/Control, общий список сохранённых и живых профилей, действия каждой строки, пользователь/пароль рядом, Connection details, статусы и явная замена конфликта; боковой список раскрывает клиентов баз | Порт не применяется через profiles API `.45`; Disconnect только для единственного подтверждённого клиента. Отсутствующие сохранённые профили добавляются автоматически (можно отключить), без Connect и замены конфликтов. Автотесты и webview-предпросмотр не заменяют живую приёмку |
| Выполнение | F11, выделенные обычные шаги, YAML до сборки, запуск с выбранного шага, полный запуск, Stop и продолжение после подтверждённой точки | Сложные конструкции СППР требуют сборки/карты; Stop не сохраняет произвольный BSL-стек |
| Состояния | Цвет строки, подтверждённый результат, текст ошибки в hover, состояние подключения/запроса | Повторы сопоставляются только при однозначном порядке. Новые сеансы KOT получают отдельный журнал, привязанный к подключению; для уже работающего сеанса можно выбрать фактический журнал через Execution log. Во время Run он читается с текущего конца файла, включая предыдущие сценарии; непроверенный путь из другого JSON не используется. `get_test_results` без scenarioId возвращает последний сценарий; результат известного ID можно запросить отдельно, но полного списка ID прошедших сценариев ответ не даёт. Опрос состояния пропускает быстрые шаги. Без подтверждения строка не окрашивается в успешную |
| Запись | Start/Stop, прямая вставка у каретки, один Undo, повторная запись без обязательной промежуточной вкладки | После внешнего Stop текст остаётся в Vanessa, отдельного безопасного чтения нет |
| Переменные и диагностика | Авточтение переменных, строковое изменение, локальное удаление; журналы, скриншоты, локальный ZIP | Типы и корректное глобальное удаление недоступны в проверенном API |
| Form Explorer | Дерево групп/колонок, фильтры и поиск, детали, выбор окна, общий кеш с IntelliSense и обогащение статическими метаданными | Встроенные формы рабочего стола разделяются по подтверждённому активному имени; ошибка первого чтения видна без snapshot. После временного отказа чтение повторяется автоматически через 5 секунд; самопроизвольная смена структуры в той же форме требует Refresh |
| Vanessa steps | Автоматический перенос фокуса на выбранный элемент, debounce 350 мс, очередь последнего выбора, устаревшие ответы не публикуются | Группы/скрытые/неоднозначные элементы не активируются. Это нативные подсказки активного элемента, не отдельная штатная команда проверок текущего элемента |
| Кеш нативных шагов | До 64 элементов одной формы/сеанса/языка, только память; при возврате текст показывается сразу, а актуальность подтверждается в фоне по свежим данным элемента и сообщённому Gherkin-состоянию. Сворачивание блока не вызывает запросов | Предпросмотр из кеша не считается подтверждением свежести. Отсутствие/неоднозначность состояния запрещает reuse анализа; это не дешёвая и не полная ревизия всех UI-данных |
| Вывод шагов | Readonly-текстовое поле со свободным выделением нужных строк; Insert full form checks в Current form | Полные проверки используют прежний нижний Output и явную вставку; обычное выделение текста ничего не вставляет |
| Остальные инструменты формы | Типизированное меню **MCP form tools** для 13 проверенных имён инструментов: поиск, действия с элементами, окнами/командным интерфейсом, запись, выгрузка табличного документа, атрибуты объекта и данные БД | Наличие универсального меню не означает готовый специализированный интерфейс каждой операции. Действия с данными вызываются явно |

**Живая проверка 2026-10-22:** после разрешённого Reload Window подтверждены Run собранного устаревшего теста из Properties в текущем MCP-сеансе и повторный запуск с группы `*And KOT mapped nested` через первый вложенный шаг. Состояние вернулось в Ready, все повторяющиеся шаги последнего сценария окрашены. Первый сценарий полного прогона остаётся без полной истории, если фактический журнал активного менеджера отличается от журнала артефакта. Боковой список базы показывает сохранённого и живого клиента отдельными строками. Form Explorer на домашней странице показал активную CommonForm.GettingStarted и 20 элементов с вложенностью; прежний отказ вызван объединением нескольких встроенных форм с одинаковыми именами контролов. Предыдущий отказ в старом сеансе сохраняется как наблюдение, причина не доказана.

## Существующий API: что готово и что дальше

| Задача | Статус на 2026-10-22 | Следующий шаг |
|---|---|---|
| База → пользователи → профили клиентов | Реализованы общий список живых и сохранённых профилей, отдельные действия, автоматическое добавление отсутствующих профилей, сверка переименований и частичные отказы. Неизменный опрос не перестраивает DOM. Живой список двух клиентов одной базы подтверждён | Дополнительная приёмка нескольких баз, изменений в самой Vanessa и повторного открытия панели |
| Контекстные шаги формы и IntelliSense | Реализованы общий кеш, иерархия, автоматическое чтение нативных подсказок, перенос фокуса, восстановление после временного отказа | Живая матрица больших форм, таблиц и смены окна во время запроса |
| 13 MCP-инструментов формы | Доступны через типизированное меню MCP form tools | Специализированные элементы управления для поиска/перехода, ввода/выбора, окон, командного интерфейса и экспорта табличного документа ещё не реализованы |
| Атрибуты объекта и выбранные строки таблицы | Типизированные вызовы доступны | Удобный отдельный просмотр ещё не реализован. Selected rows не равны всей UI-таблице |
| Выполнение и результаты | Реализованы Run, запуск с шага, F11, подтверждённые цвета/ошибки; Run из Properties и редактора использует тот же маршрут, что Test Manager. Живые Run, повторный запуск группы и быстрые шаги последнего сценария подтверждены | Можно дополнительно собирать наблюдаемые scenarioId и запрашивать их результаты. Это не гарантирует всю историю: короткие сценарии могут целиком пройти между опросами; для сессий с журналом реализовано живое отслеживание всего прогона; без журнала требуется upstream-перечисление результатов |
| Матрица живой приёмки | Тесты транспорта, преобразований и webview есть | Отдельные приёмочные прогоны в 1С остаются обязательными; они не заменяются количеством unit-тестов |

Приоритет дальнейшей работы в KOT: живая приёмка Run и Form Explorer, затем специализированные действия инструментов формы и просмотр атрибутов/выбранных строк. Для этих интерфейсов новые API Vanessa не требуются.

## Что требует изменения или подтверждения со стороны Vanessa

| Потребность | Ограничение `.45` | Текущий обход / issue |
|---|---|---|
| Быстро получить шаги одного элемента | `full` обходит форму целиком; `max_depth` сокращает вывод, не работу | Автоматическая очередь и кеш; [02](../issues/2026-10-21-vanessa-mcp/02-element-steps.md) |
| Штатная проверка только текущего элемента | UI-команда есть, в MCP `get_form_analysis` не выставляет её флаг | Не подменяется подсказками или проверкой всей формы; [02](../issues/2026-10-21-vanessa-mcp/02-element-steps.md) |
| Фактически прервать анализ и немедленно начать следующий | Отмена devkit фиксирует отметку; кооперативная проверка внутри анализа `.45` не подтверждена | Логическая отмена, серверные операции последовательно. Прерывание HTTP не считается остановкой BSL |
| Кеш без затрат на проверку и без риска пропущенных изменений | Нет дешёвой полной ревизии формы/значений | Проверяется только сообщённое Gherkin-состояние и детали выбранного элемента |
| Надёжно следить за текущим фокусом клиента | Нет переносимого отдельного ID активного элемента | Фокус на выбранный элемент задаётся явно; его независимая смена пользователем во время запроса не полностью наблюдаема; [04](../issues/2026-10-21-vanessa-mcp/04-active-element-identity.md) |
| Язык штатных проверок формы | MCP-генератор не применяет тот же перевод, что UI | Однозначный парный каталог с сохранением непереведённых шагов; [01](../issues/2026-10-21-vanessa-mcp/01-form-checks-language.md) |
| Автовставка после внешнего Stop записи | Нет read-only чтения буфера, повторный Stop может очистить текст; флаг записи до выполнения feature может отсутствовать | Безопасный явный Stop в KOT, отсутствие подтверждения не маскируется; [05](../issues/2026-10-21-vanessa-mcp/05-recording-state-before-run.md), [06](../issues/2026-10-21-vanessa-mcp/06-recording-result-read.md) |
| F11 со скоростью нативного шага уже загруженной feature | Upstream-вызов повторно загружает feature/библиотеки | KOT избегает своих лишних загрузок; нужен отдельный upstream-путь; [07](../issues/2026-10-21-vanessa-mcp/07-step-without-reload.md) |
| Все строки UI-таблицы и замена locator | DB-данные и selected rows не равны всей текущей UI-таблице; эквивалент locator не подтверждён | Snapshot-мост сохраняется; [10](../issues/2026-10-21-vanessa-mcp/10-ui-table-snapshot.md) |
| Полностью структурированные статусы/результаты и глубинные точки | API возвращает текст без стабильной полной модели; точка внутри экспортного вызова требует отдельного воспроизведения | Строгая проверка текущего формата, дополнение настроенным run-log конкретного артефакта; [11](../issues/2026-10-21-vanessa-mcp/11-structured-state-results.md), [12](../issues/2026-10-21-vanessa-mcp/12-exported-breakpoints.md) |

| Применение полного VAParams в активном менеджере | Нет чтения и атомарного применения полного JSON запуска | При несовпадении/неизвестном наборе предлагается текущий сеанс либо отдельный менеджер; [13](../issues/2026-10-21-vanessa-mcp/13-runtime-parameters.md) |

Русские [черновики issue](../issues/2026-10-21-vanessa-mcp/README.md) предназначены для ручной публикации пользователем. Ничего не отправлено разработчикам автоматически.

## Проверка исправлений 2026-10-23

Исправлены колонки индикатора/стрелки и расположение чипов Infobases, зарезервированы места для Connect/Disconnect и дополнительных действий. В предпросмотре production-webview на синтетических данных Connect и Disconnect имеют одинаковые x/ширину; появление действий их не перемещает. Боковая панель имеет раздельные области стрелки (до 33 px), индикатора (36–42 px) и подписи (от 45 px), кнопку клиентов при любом количестве строк.

Native СППР: навигация к парному скрипту, диагностика фрагмента со служебными конструкциями СППР, синхронизация метаданных после сохранения, отсутствие автосворачивания meta.yaml и доступный конвертер проверены целевыми тестами. Новая привязка журнала к сеансу проверена тестами запуска и отслеживания.

В повторной живой проверке DevHost 2026-10-23 подтверждены запуск собственной feature из Properties в активной MCP-сессии, доступный конвертер, исчезновение прежних native-feature диагностик и исправленный отступ индикатора боковой панели. Прогон двух сценариев выявил пропущенные флаги записи журнала и шагов; оба включены во временном MCP-overlay, регрессионные тесты и полная проверка прошли (2433 успешны, 2 пропущены). Создание журнала с записями сценариев проверено в 1С. Финальная живая проверка подсветки с обоими флагами ещё нужна: ввод Parallels прервался, затем проверка действий стала недоступна из-за лимита использования. Собственная fixture восстановлена.
