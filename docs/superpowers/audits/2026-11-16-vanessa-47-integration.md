## Границы

- `manage_va_settings` не применяет профили клиентов, GlobalVars и lifecycle-команды как обычные настройки. Предварительный и фактический отчёты сохраняют `errors`, `warnings`, `ignored`, `out_of_scope`. Полный успех всех ключей JSON не предполагается.
- `get_test_results` по-прежнему не предоставляет документированное перечисление всех результатов прогона. JSON улучшает идентичность и разбор ответа, но не заменяет фактический журнал для пропущенных опросом сценариев.
- Для проверки элемента действуют ограничения сервера: платформа 8.3.25+, не web-клиент, проверка кнопок и групп не поддержана v1. Недоступность операции не подменяется проверкой всей формы.
- Кеш нативных шагов `.45` сохраняется. На `.47` выбранный элемент запрашивается напрямую; прежний тяжёлый анализ и активация не выполняются.
- Исправления точек внутри экспортных вызовов и запуска без VanessaExt внесены upstream. Их наличие не означает завершённую живую матрицу для любой платформы. Старый обход поиска файлов при подготовке KOT сохраняется.

## Проверка

Статические схемы взяты из регистрации инструментов тега `.47`; синтетические ответы отделены от живых fixture `.45` и `.47`. Проверяются отдельные возможности, несовместимая новая обязательная опция, неполные/неизвестные JSON-ответы, одинаковые шаги на разных строках, чтение внешне завершённой записи по ID без остановки новой записи, старый и новый форматы профилей, прямые шаги и смена фокуса в одной форме, автономная генерация и отсутствие сетевых запросов.

Живая локальная проверка: официальный обычный ZIP `.47`, `locales/Steps.epf`, платформа Windows 8.3.27.2074, новая временная пустая ИБ. Выгрузка в XML и генерация дали **1208 определений шагов**. Рабочие информационные базы не использовались.

Живая проверка KOT → менеджер `.47`: отдельная временная ИБ из штатного KOTStartupTemplate, client_mcp 0.6.6, платформа Windows 8.3.27.2074. Подключение завершилось состоянием `ready`, получены 54 инструмента и 356 настроек. Все возможности KOT совместимы с реальными входными схемами. Диалог помощника после `DisableFirstRunHelper` не повторился. Fixture `tools.live.json` и `state.before-run.live.json` сохранены для регрессий.

Применение настроек, запись, операции форм и точки внутри экспортного вызова в живой клиентской базе остаются отдельной приёмкой. Наличие модульных тестов не подменяет её. GitHub issue в рамках этой работы автоматически не закрываются.

Итог проверок на Windows с Node 24.11.1: 106 целевых тестов прошли; TypeScript, ESLint, локализация, документация и сборка прошли. Полный набор: 2831 тест, 2717 успешны, 110 ошибок, 4 пропущены. Список всех 110 падающих тестов совпадает с отдельно проверенным исходным HEAD; среди причин — предположения о POSIX-путях, file URI и символьных ссылках в тестах. Новых падающих тестов нет.

Локальный VSIX собран из минифицированного bundle через `vsce.pack` после отдельных проверок. Штатный `vscode:prepublish` не изменён; его полный набор тестов на этой Windows-среде остаётся красным по перечисленным причинам. В ZIP нет `docs/assets/**`.

Дополнительная проверка 17 ноября: в работающем сеансе `.47` обнаружены отличия `подключён/подключен`, заголовки состояния с уточнением «по данным прогона» и новый формат пустого списка точек останова. Разбор исправлен; чтение JSON и Markdown-состояния, двух профилей, переменных, 356 настроек и статуса записи проверено повторно. Пустой ответ результатов до первого прогона не считается успешным выполнением; ответ редактора без позиции не считается выбранным шагом.

Разбор профилей допускает перестановку строк, новые справочные поля и оформление таблицы. Текст подсказок после закрытия клиента и после списка точек останова не участвует в подтверждении результата. Дополнительные тесты проверяют необязательные расширения API, противоречивые данные и работоспособность других операций после несовместимого ответа профилей. 220 целевых тестов, TypeScript, ESLint и сборка прошли. Приёмка действий на подключённом клиенте по-прежнему требуется; эта проверка использовала только чтение.

Панель клиентов: состояние подключения отделено от совпадения настроек. В текущем сеансе сохранённые порты `1538–1540` отличаются от портов профилей `48000–48002`; панель показывает оба значения. Параметры авторизации с пробелом после `/N` и `/P` сопоставляются с записью без пробела. Ответы об ошибках сохраняются отдельно от локализованного сообщения; пароли удаляются перед выводом. 290 целевых тестов, проверка типов, ESLint и локализация прошли.

Ограничение `manage_test_client` в `.47`: `ПодключитьПрофильTestClientПоИмени` при отказе получает только булев результат. Причина, например сообщение об истечении SMUA, выводится через `СообщитьПользователю` в окне VA, а ответ MCP содержит общий статус и возможные причины. KOT показывает полученный ответ и направляет к сообщениям VA; точная причина в этом маршруте требует изменения ответа Vanessa.
