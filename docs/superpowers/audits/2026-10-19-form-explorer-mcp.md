# Form Explorer: соответствие snapshot и MCP

Проверяемая версия: Vanessa Automation 1.2.043.45, commit `a9625b83adfe0612da2adf750d82ca7993d73a70`. Контракты взяты из реального `tools/list`; формат ответов сверяется с `Forms/MCPVA/Ext/Form/Module.bsl` и `Forms/ИсследовательФормы/Ext/Form/Module.bsl` этой версии. Схемы не подтверждают поддержку другой выбранной обработки.

| Возможность текущей панели | MCP .45 | Реализация и граница |
|---|---|---|
| Заголовок окна и имя формы | `get_active_window_data` | Повторная проверка до и после чтения |
| Дерево, группы, поля, кнопки, таблицы, колонки | `get_form_analysis`, `format=elements`, `compact=false`, `only_visible=false` | Общая модель панели и кэш редактора; без предположений об отсутствующих значениях |
| Скрытые элементы | То же дерево | Признак видимости сохраняется, фильтрация остаётся в панели |
| Значение, доступность, read-only выбранного поля | `get_form_element_data` | Чтение по уникальному имени; текстовое представление без определения типа по значению |
| Подсказки шагов | `manage_form_elements`, `get_form_element_data`, `get_form_analysis format=full/gherkin` | В MCP выбор доступного элемента переводит фокус в клиенте и автоматически читает нативные шаги. В snapshot остаются локальные подсказки. Устаревшие запросы отменяются логически, результаты проверяются по свежему сообщённому состоянию формы. Ввод текста в редакторе не вызывает сеть |
| Исходный XML, tooltip, data path | Статические метаданные проекта | MCP дерево обогащается через существующий `forms-index.json`; панель и IntelliSense используют один результат. Фоновая проверка той же формы сохраняет кэш |
| Все строки таблицы формы | Нет проверенного эквивалента snapshot capture | `get_table_data` читает БД, а `get_selected_rows` — выбранные строки; не подменять ими весь UI snapshot |
| Интерактивный locator | Нет проверенного эквивалента | Сохраняется в прежнем snapshot-мосте |
| Переключение окна | `get_window_list_testclient`, `window_management` | Кнопка Windows: список внутренних окон текущего клиента, точная активация и проверка клиента/окна до и после нового дерева. Wildcard не принимается |

Источник выбирается в панели и настройке `kotTestToolkit.formExplorer.source`: автоматический, MCP, snapshot. Ошибка MCP не переключает панель на snapshot другого клиента. Сеанс и единственный подключённый клиент привязываются к результату; при смене клиента, окна, поколения или источника запоздавший ответ отбрасывается. Сырые значения формы не записываются в проект, настройки или общие логи. Кэш редактора живёт до смены сеанса, готовности или формы; сеть вызывается панелью, ввод в редакторе её не вызывает.

Неизвестный формат, неоднозначные имена, нарушенная структура, слишком большой или обрезанный ответ дают отказ, а не частичную догадку. Неудачное чтение не запускает бесконечные повторы: требуется явное обновление или новый сеанс.

Живая проверка: отдельная копия служебной ИБ KOT, клиент `KOT_FORM_PROBE`, официальная Vanessa открыта в нём как тестовая форма. Прочитано дерево из 1680 узлов (включая невидимые элементы); сохранён небольшой обезличенный ответ checkbox в test fixtures. Бизнес-базы и их клиенты не использовались. Полная parity-проверка и удаление прежнего моста ещё не выполнены.

Проверка задержек на большой форме выявила два независимых источника нагрузки. На искусственном дереве из 1000 полей отрисовка с прежним обработчиком фейда занимала 2,84–2,94 с, без него — 42–47 мс. Обработчик теперь измеряет только видимые надписи и разделяет чтение геометрии и запись стилей: в том же локальном браузере повторная отрисовка с фейдом занимает 77–127 мс (это контрольный замер, не универсальный норматив).

В отдельном клиенте `KOT_FORM_PROBE` запрос `get_form_analysis` для 1680 узлов занял 10,7 с; чтение выбранного поля — 89 мс, отдельные запросы идентичности — 23–68 мс. Живая проверка нового фонового пути заняла 147 и 186 мс; дерево не перечитывалось. Поэтому фоновое обновление повторно проверяет только клиента, заголовок окна и имя формы. Совпавшая форма сохраняет дерево и выбранные подробности без повторной отправки в webview. При смене формы выполняется полное чтение; явный **Refresh** перечитывает структуру внутри того же окна. Изменения состава элементов внутри одной формы требуют Refresh. Проверки ошибок и смены сеанса остаются обязательными.

Проверка 2026-10-20: production adapter получил два внутренних окна собственного `KOT_FORM_PROBE`, активировал выбранное окно Vanessa и повторно подтвердил его идентичность. OS-окна из дополнительной секции не смешиваются с внутренними окнами. Неудачное чтение Form Explorer не сбрасывает подтверждённый результат последнего F11.

Дополнение 2026-10-21: автоматическое получение нативных шагов, очередь последнего выбора и кеш со сверкой состояния реализованы отдельно от прежних живых замеров. `.45` не подтверждает кооперативное прерывание анализа: HTTP abort не используется для запуска следующего анализа параллельно. Отдельное readonly-поле позволяет свободно выделять часть шагов; повторная отправка идентичной разметки не пересоздаёт поле. Полные проверки перенесены в Current form. Новая автоматическая последовательность проверяется тестами адаптера/панели и локальным webview-предпросмотром; прежние живые измерения не выдаются за измерения нового пути.
