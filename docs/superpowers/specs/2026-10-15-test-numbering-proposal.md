Полный код процесса отражает иерархию СППР. Группы библиотеки KOT — отдельная организация файлов; перестановка таких групп не должна перенумеровывать тесты. СППР использует отдельные справочники и области кодов; общее пространство кодов сценариев и процессов — ограничение текущего KOT, а не правило СППР.

`Ответственный` в СППР — ссылка на пользователя СППР; при создании сценария назначается авторизованный пользователь (`СценарииРаботыПользователей/Ext/ObjectModule.bsl:43–50`, Git-форма:76). Генератор Git-кода от ответственного не зависит. Общий `responsibles` в KOT хранит имена, не создаёт пользователей СППР и не подменяет их UID.

Имена путей в таблице приведены в нормализации NFC для чтения; в предоставленной выгрузке часть имён файлов использует NFD.

## Правило для Drive с учётом исторических серий

Пользователь уточнил, что в Drive коды исторически закреплены за тестировщиками: `000012xxx` — Василий, `000013xxx` — Николай; последние три цифры отражают последовательность создания тестов. Это правило проекта следует сохранить. Случайный способ СППР остаётся справочной информацией и возможным режимом для других проектов; для Drive он не рекомендуется.

| Серия | Автор в примере пользователя | Пример последовательности |
|---|---|---|
| `000012` | Василий | `000012001`, `000012002`, … |
| `000013` | Николай | `000013001`, `000013002`, … |

Имена и распределение в таблице — иллюстрация из сообщения пользователя, не фактически настроенный каталог участников Drive.

- Код состоит из шестизначного префикса серии и трёхзначного номера; хранится строкой, ведущие нули сохраняются. Существующие коды, включая окончания `000`, не меняются.
- Следующий номер идёт после максимального ранее выданного в выбранной серии. Пропуски между существующими кодами не заполняются. Хранится последнее выданное значение серии; при выдаче берётся максимум этого значения и найденных кодов, затем прибавляется единица. Это уточняет прежнее предложение вычислять номер только по существующим файлам.
- При исчерпании трёхзначного номера нельзя автоматически перейти в соседнюю серию: она может принадлежать другому человеку. Новая серия назначается явно.
- Связь серии с автором и последнее выданное значение хранятся в общем `.kot/test-numbering.yml`. Выбранная пользователем серия по умолчанию хранится локально. Новые реальные серии не назначаются по примерам имён из обсуждения.
- В мастере код подставляется в существующее поле и остаётся редактируемым. Перед записью повторно проверяются занятость кода и свободный путь. Текущая проверка KOT учитывает коды главных/вложенных сценариев и процессов; это строже раздельных областей СППР.
- Серия означает автора создания, а поле `Ответственный` — текущего сопровождающего. При первоначальном создании можно предложить автора серии ответственным, но последующая смена ответственного не меняет код и серию.
- Код присваивается один раз. Сортировка, перемещение между группами, смена имени и ответственного не меняют номер. Папка следует коду; существующие тесты автоматически не перенумеровываются.
- При сортировке по коду тесты одной серии идут от меньшего номера к большему. Общую хронологию разных авторов код не задаёт.
- UID остаётся идентичностью объекта. Связь настройки запуска со сценарием/процессом задаётся UID владельца. У существующих `test.yaml` собственный код сохраняется; совпадение с кодом сценария не нужно навязывать. Настройки запуска не расходуют номера авторских серий определений.

## Параллельные ветки

Выделенные серии разделяют номера разных авторов, но один автор может получить одинаковый следующий номер в двух ветках. Хранимое последнее значение серии помогает не переиспользовать удалённые номера, но не является межветочной блокировкой. Проверка при создании выполняется под блокировкой проекта; для CI доступен `npm run check:test-codes -- --project-root PROJECT YAML_ROOT...`. Конфликт решается явной сменой кода одного нового теста с уже существующим переносом папки и обновлением связанных файлов и последним выданным значением серии. Гарантировать общий порядок выдачи номеров в независимых рабочих копиях без координации с общим сервисом нельзя.

## Поля мастера

Ответственный выбирается в обоих режимах мастера. По уточнению пользователя сохранены короткий режим со значениями по умолчанию и полный режим. В полном режиме проект и уровни отчёта выбираются из общего каталога с созданием новых значений; остальные поля сценария и настройки базы сохраняют существующие действия. У процесса собственный набор полей шапки.
