# Подготовленный DT служебной базы

Это инструкция для сопровождающего расширение, а не настройка рабочей базы пользователя. Release-артефакты находятся в `tools/startup-infobase/KOTStartupTemplate.dt` и соседнем manifest `.dt.json`.

## Назначение

Шаблон нужен для служебных запусков компилятора и Vanessa. Он является технической ИБ с минимальной конфигурацией, а не выгрузкой проверяемого приложения. Пользователь `KOTStartupService` и его роли/параметры предназначены только для этой служебной базы.

База должна поддерживать русский язык, стандартную аутентификацию служебного пользователя и требуемые административные действия. Параметры безопасного режима для MCP относятся к подготовленному компоненту в служебной ИБ; не переносите их автоматически в рабочие базы.

Для управляемого запуска добавляется отдельное официальное расширение `client_mcp` поддерживаемой версии. Сервер запускается по явному `runMcp`; обычная компиляция не должна поднимать его просто из-за наличия CFE.

## Воспроизводимая подготовка на Windows

Проверьте исходный чистый технический DT, официальный CFE и разрешения распространения. Пример команды из корня репозитория:

```powershell
node tools/buildStartupTemplate.cjs 'C:\Program Files\1cv8\8.3.24.1738\bin\1cv8.exe' 'C:\Build\source.dt' 'C:\Build\client_mcp.cfe' 'C:\Build\prepared.dt'
```

Версия платформы в примере — путь, который следует заменить доступной совместимой установкой. Выбирайте минимальную поддерживаемую платформу, чтобы случайно не повысить требования DT.

Скрипт создаёт отдельную временную базу, восстанавливает DT, проверяет SHA-256 CFE, устанавливает расширение, проверяет его выгрузку и создаёт `prepared.dt` с manifest. Существующий результат не перезаписывается. Скрипт и точные проверки находятся в [buildStartupTemplate.cjs](../../tools/buildStartupTemplate.cjs).

После проверки нового восстановления обновите **оба** release-файла. Manifest связывает точный хеш DT с включённым расширением. Смена файла поставки не означает автоматическое пересоздание прежней служебной базы пользователя: для неё существует отдельный маршрут обновления компонентов.

## Обновление devkit

Согласованно обновляйте поддерживаемый pin подготовки, сборщик DT, соответствующие исходники и notices. Сам devkit можно заменить стандартными средствами Конфигуратора независимо от TypeScript, но управляемая подготовка KOT проверяет поддерживаемый pin.

Devkit включает нативную часть WebTransport. DT устраняет повторную загрузку расширения в базу, но не гарантирует отсутствие системного диалога установки компоненты на новом компьютере. Только успешный handshake подтверждает готовность.
