# Каталоги шагов и определений

KOT использует два связанных слоя: встроенные шаги Vanessa выбранной версии и определения конкретного проекта. Оба слоя используются редактором и Библиотекой, чтобы не давать разные ответы для одного вызова.

## Версия Vanessa

Точная версия может быть задана настройкой `kotTestToolkit.steps.vanessaVersion`. При пустом значении KOT ищет сведения рядом с выбранной поставкой Vanessa, в частности `docs/Changelog.md`.

Версионный каталог содержит фразы, параметры, языки, категории и известные алиасы. Проверяются формат и digest ревизии; предусмотрены кеш и резервный встроенный/локальный источник. Обновление каталога не является обновлением самой Vanessa.

При генерации используются исходные `Template.xml` и поддерживаемые статические регистрации BSL. Бинарная EPF без доступных исходников не даёт эквивалентной информации. Публикация каталогов может происходить независимо от выпуска VSIX.

## Автоматическое обновление каталога

[Workflow Publish Vanessa step catalogs](https://github.com/alexiosus/KOTfor1C/blob/main/.github/workflows/publish-step-catalogs.yml) запускается по понедельникам в **03:17 UTC**. Он находит последний стабильный релиз Vanessa Automation, проверяет генератор и публикует каталог в отдельной ветке `step-catalogs`. Перед записью проверяются контрольная сумма, версия, число шагов и отчёт генерации. Если каталог не изменился, новый коммит не создаётся; опубликованные версии сохраняются.

Для обновления без ожидания расписания откройте **Actions → Publish Vanessa step catalogs → Run workflow**. Пустое поле `version` выбирает последний стабильный релиз, заполненное — конкретный тег Vanessa. Изменять VSIX или выпускать новую версию KOT для этого не требуется. Работающее расширение получает каталоги через индекс `step-catalogs/index.json`; способ выбора версии описан выше.

## Локальный каталог без интернета

В настройках KOT → **Редактор и подсказки** выберите **Режим каталога шагов → Офлайн**. Такой же переключатель есть на шаге **Подготовить редактор** в мастере первой настройки. При отсутствии каталога KOT автоматически создаёт его из указанной поставки Vanessa, без диалогов генерации и без доступа к интернету. Готовый файл используется повторно; после его удаления создаётся заново. Для возврата к сетевым каталогам выберите **Онлайн**.

Для обычной поставки с `locales/Steps.epf` потребуется установленная платформа 1С: KOT использует первую настроенную либо найденную платформу, создаёт временную пустую ИБ, выгружает EPF в XML и удаляет временные файлы после обработки. Рабочие ИБ не используются. Если уже есть `locales/Steps/Templates/en/Ext/Template.xml`, платформа для генерации не нужна. Каталог по умолчанию сохраняется в `.kot/step-catalogs/<версия>.json`.

В дополнительных настройках можно указать готовый JSON через `kotTestToolkit.steps.localCatalogPath`. Для ручного пересоздания доступна команда **KOT: Сгенерировать локальный каталог шагов Vanessa** в меню **…** Библиотеки и Менеджера тестов и в палитре команд. Она включает офлайн-режим для выбранной папки проекта. Библиотека, диагностика и IntelliSense используют локальный файл без загрузки сетевого индекса. Некорректный или несовместимый файл не заменяется сетевым каталогом автоматически.

Каталог содержит русские/английские варианты и описания из локальной поставки. Категории извлекаются из модулей библиотек (BSL или EPF) по тем же правилам, что и в онлайн-каталоге. Происхождение помечено как локальное с хешем содержимого, без вымышленного Git commit.

## Определения проекта

| Источник | Что индексируется |
|---|---|
| Сценарии СППР | Имя, UID, параметры и поддерживаемые вызовы |
| Процессы | Ссылки на сценарии/подпроцессы и параметры |
| Экспортные feature | Сценарии, аргументы, язык и метаданные экспорта |
| BSL-исходники шагов | Поддерживаемые регистрации пользовательских шагов |

Корни берутся из активного профиля и подключённых библиотек. Снимки определений учитывают ресурс, владельца проекта и доступные URI. Одинаковое имя не должно приводить к случайному выбору первой строки.

Изменения обновляют зависимые представления. Переименование/преобразование штатной командой может обновить поддерживаемые вызовы; неоднозначные случаи требуют решения до записи.

## Что проверить при отсутствии подсказки

Убедитесь в доступности исходника, корня библиотеки, языка, версии каталога и контекста каретки. Внутри аргумента ожидаются данные аргумента, а не все определения. Наличие шага в исходном BSL-каталоге не гарантирует, что его EPF собрана и загружена в Vanessa.
