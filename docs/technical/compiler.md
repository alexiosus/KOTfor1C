# Контракт компилятора и запуска

KOT вызывает внешнюю обработку `СборкаТекстовСценариев`. Она не включена в расширение; контракт зависит от конфигурации СППР и её доработок. Точкой проверки служат поддерживаемые шаблоны, параметры и тесты KOT, а не произвольный набор ключей VAParams.

## Каталоги и алиасы

| Ключ | Смысл |
|---|---|
| `ScenarioFolder` | Корень сценариев СППР |
| `ProcessFolder` | Отдельный корень процессов |
| `TestFolder` | Приоритетный общий корень для сценариев и процессов |
| `FeatureFolder` | Выходные feature/JSON и сопровождающие результаты |
| `ModelDBSettings` | Файл настроек эталонных баз |
| `Libraries` / `VanessaLibraries` | Дополнительные библиотеки; несколько путей разделяются `|` |
| `VanessaFolder` и поддерживаемые алиасы | Каталог поставки Vanessa; путь EPF нормализуется к каталогу |

Нормализация сохраняет явные значения и пустые поля, различает роли подключения и каталога базы. `TestFolder` имеет приоритет, поэтому при раздельных корнях не следует добавлять его случайно. Клон профиля мастера сохраняет раздельный `ProcessFolder`.

Фактические правила: [compilerBuildParameters.ts](../../src/compilerBuildParameters.ts), [проверки значений](../../src/compilerBuildValueValidation.ts), [менеджер профилей](../../src/yamlParametersManager.ts).

## Параметры СППР

Объявления сценариев, процессов, шагов и настроек запуска являются отдельными уровнями. Переопределения варианта запуска и конкретного вызова не должны подменяться изменением общих defaults.

KOT поддерживает диагностику обязательных присваиваний, ссылки `[Параметр]`, исходящие значения (`Return … as …`), таблицы и комбинации значений в рамках проверенного контракта. Сложные конструкции требуют компиляции. Готовые связные примеры находятся в [учебной мастерской](../../examples/kot-workshop/tests/sppr), а пользовательская последовательность — в [руководстве по процессам](../guides/compiler-process-parameters.md).

Фильтры и теги компилятора применяются после выбора набора в KOT. Отметка в UI не отменяет выключение настройки запуска. `SplitFeatureFiles` относится к доработке Drive и не объявляется универсальной функцией СППР.

## Формирование JSON Vanessa

JSON запуска использует ключи настроек Vanessa Automation, описанные в справочнике `VAParams.json`. Вкладка дополнительных параметров позволяет импортировать эти настройки из Vanessa и задать значения для объединения с результатом компилятора.

1. Компилятор формирует исходный JSON.
2. Дополнительный параметр сохраняет существующее значение, пока не включено **Override existing value**.
3. Для переопределения учитывается заявленный тип и известный RU/EN-эквивалент ключа; произвольные пользовательские ключи также поддерживаются.
4. GlobalVars объединяются по соответствующему правилу приоритета.
5. Маршрут запуска выставляет свои обязательные поля. Для самостоятельной feature выбранный файл задаётся после наложений, чтобы не запустить другой набор.

Трансформации реализованы в [vanessaLaunchJson.ts](../../src/vanessaLaunchJson.ts). Параметры JSON не равны API изменения работающего сеанса: `.45` не позволяет применить весь файл через MCP к уже открытому менеджеру.

## Артефакты и диагностика

KOT использует feature, JSON, карты `.str`, `compile.txt`, JUnit и XML ошибок. Отчёт объединяет результаты и разрешает исходные пути относительно текущего checkout, когда это возможно. URI, UID, зависимости и манифесты предотвращают смешивание одинаковых имён из разных каталогов.

`SeveralScenariosInOneFile` может объединить несколько тестов в общий feature; его запуск выполняет весь файл. `CreateJson=false` не мешает открыть feature, но штатный маршрут, требующий JSON, не получает его автоматически.

Части сборки изолируются; параллельность ограничена. Отмена и неуспешная сборка не должны подменять состояние последней подтверждённой успешной сборки. Изменение зависимостей и преобразования помечают результаты устаревшими.
