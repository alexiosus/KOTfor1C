# Поля исходника СППР и настройки запуска

Это справочник для чтения и сопровождения исходников. Создавать их удобнее [мастером KOT](../guides/scenario-creation.md). Имена полей сохраняются в формате компилятора СППР.

## Сценарий

В едином формате поля находятся в `scen.yaml`. В парном формате шапка, параметры и связи находятся в `meta.yaml`, шаги — в `scen.feature`.

| Поле | Назначение |
|---|---|
| `ТипФайла: Сценарий` | Классификация документа |
| `ДанныеСценария.UID` | Устойчивая идентичность сценария для ссылок |
| `Имя` | Человекочитаемое имя и текст поддерживаемых вызовов |
| `Код` | Код сценария для идентификации в результатах и диагностике |
| `Проект` | Контекст проекта СППР |
| `ФункцияСистемы` и `UIDФункцияСистемы` | Согласованное имя функции и её идентификатор |
| `РазрешеноИспользоватьВДругихФункциях` | Разрешение вызовов между функциями системы по правилам компилятора |
| `ПрофильПользователя` | Профиль для разрешения пользователя тестового клиента |
| `УровеньОтчета1` | Источник `#report.feature` |
| `УровеньОтчета2` | Источник `#report.story` |
| `ПараметрыСценария` | Имя, default, тип, исходящий/многозначный признак параметров |
| `ВложенныеСценарии` | Объявления связей с вызываемыми сценариями |
| `ТекстСценария` | Gherkin в едином YAML; в парном формате текст вынесен в отдельный файл |

Поля от `Имя` до `УровеньОтчета2` в таблице относятся к `ДанныеСценария`. Группа KOT и функция системы СППР имеют разные назначения. Каталог функций в KOT помогает выбрать согласованную пару имени/UID; его первая/default-запись используется при создании по умолчанию.

## Настройка самостоятельного запуска

Файл в `test/` связывает самостоятельный тест с исходником. Один сценарий может иметь несколько настроек с разными вариантами.

| Поле | Назначение |
|---|---|
| `ТипФайла: НастройкаТеста` | Классификация настройки |
| `ДанныеТеста.UID` | Собственный UID **настройки**, не UID сценария |
| `UIDСценария` | Ссылка на `ДанныеСценария.UID` |
| `Имя`, `Код`, `СценарийНаименование` | Поля выбранного сценария и отображения варианта запуска |
| `ЭталоннаяБазаИмя` | Отображаемое имя эталона |
| `ИдентификаторБазы` | Идентификатор записи `ModelDBSettings`, по которому разрешается эталон |
| `ПрофильПользователя` | Профиль пользователя выбранного эталона |
| `ПараметрыЗапуска`, `ПараметрыТеста` | Настройки и переопределения конкретного запуска |

Все поля после первой строки относятся к `ДанныеТеста`. У настроек процесса используется соответствующая ссылка на процесс; не подменяйте её UID сценария. Точные состав и расширения формата зависят от вашей обработки СППР.

Карандаши у эталона/идентификатора обновляют связанную пару, у профиля выбирают пользователя этого эталона. У полей связи доступно [Change linked scenario](../guides/scenario-creation.md#изменить-связанный-сценарий-настройки-запуска). Случайная смена только одного UID может оторвать настройку от исходника.

## Сведения KOT

Описание, группа, порядок и категория в 3.0.0 хранятся в соседнем `*.kot.yml` и общих каталогах `.kot`. Прежние `KOTМетаданные.Описание` и `PhaseSwitcher.Tab/OrderOnTab/Default` относятся к совместимости со старым хранением. Они не заменяют поля компилятора СППР.
