# Архитектура KOT

KOT — расширение VS Code с провайдерами редактора, общими индексами, host-сервисами и webview-интерфейсами. UI не должен самостоятельно выбирать произвольную команду или записывать файл вне проверенного действия.

## Ответственность подсистем

| Подсистема | Основные модули |
|---|---|
| Активация и интеграция | `extension.ts`, отложенная регистрация команд/сервисов |
| Каталог исходников | `workspaceScanner.ts`, `scenarioCatalog.ts`, `scenarioDescriptor.ts` |
| Общие определения | `projectDefinitionIndexService.ts`, `stepCatalogService.ts` |
| YAML и редактирование | `scenarioYamlDocument.ts`, команды сценариев и процессы |
| Свойства и Библиотека | `scenarioProperties*`, `stepLibrary*` |
| Организация проекта | `projectLibraryStore.ts`, каталоги свойств и нумерация |
| Компиляция | `compilerBuild*`, `yamlParametersManager.ts`, `phaseSwitcher.ts` |
| Runtime Vanessa | `vanessaControl*`, транспорт и протокол MCP |
| Формы и клиенты | `formExplorer*`, `vanessaInfobaseClients.ts` |
| Мастер и настройки | `kotWorkspacePanel.ts`, `kotSettingsSession.ts`, `kotProjectSetup.ts` |

Полный список файлов доступен в [src](../../src). Таблица задаёт точки входа, а не утверждает, что каждый большой модуль уже полностью разделён.

## Потоки

**Редактирование:** документ → разбор/идентичность → общие определения → completion/hover/diagnostics → версионная правка документа.

Подробная [последовательность сохранения и обработки очереди](contributing-workflows.md#сохранение-исходника) объясняет отдельные маршруты единого YAML и пары feature + meta.

**Компиляция:** выбранные главные тесты + профиль → preflight → изолированные задания компилятора → отчёты/карты/манифест → состояние артефактов и их зависимостей.

**Выполнение:** источник/feature + сеанс → сверка готовности → команда MCP → подтверждённый результат и фактический журнал → сопоставленные строки редактора.

**Настройки:** manifest → локализованная модель → черновик webview → проверка типов/области/базового токена → запись VS Code configuration. Секретные значения не включаются в обычный снимок UI.

**Мастер:** ограниченное чтение проекта → явный план → проверка неизменности и доверия → создание только новых файлов/настройки/профиль → готовность редактора и отдельно выполнения.

## Инварианты

- Важны UID и URI, а не только имя сценария.
- Скрытый preview-документ не следует переводить на другой язык как видимый редактор.
- Устаревший ответ не обновляет новый выбор/сеанс.
- Отсутствие ошибки транспорта не равно успешному шагу.
- Общие метаданные и личное состояние имеют разных владельцев.
- Автоматическая миграция и явная пользовательская запись — разные действия.
- Секреты не должны попадать в стандартные диагностические сообщения.
