# AI: контекст запросов и отчёты

AI-клиент использует заданный пользователем OpenAI-совместимый endpoint и выбранный режим API. Работа с MCP Vanessa не требует этого клиента.

## Какие данные могут передаваться

| Задача | Контекст |
|---|---|
| Описание сценария | Текст, параметры, найденные подстановки и вложенные вызовы |
| Анализ конфигурации | Git diff файловой выгрузки относительно главной ветки, доступный контекст и введённая User Story |
| Ревью тестов | Изменения тестов и конфигурации, актуальные фрагменты исходников и необязательная User Story |

Адрес API определяет получателя этих данных. Ключ API хранится как настройка пользователя; страница KOT не возвращает сохранённое значение в обычном снимке. Экспорт настройки или ручная публикация JSON требует отдельной проверки пользователем.

## Результаты

Описание сохраняется как поддерживаемое описание KOT. Отчёты конфигурации и тестового ревью создаются локально в соответствующих каталогах runtime, по умолчанию под `.vscode/kot-runtime`. Их можно открыть повторно для текущей ветки.

Каталоги: `configuration-diff-ai-reports` и `test-review-ai-reports`. Имена файлов формируются из имени текущей ветки с нормализацией для файловой системы. В качестве главной ветки ищется доступный ref `origin/main`, `origin/master`, `main` или `master`. Отсутствие подходящего ref — ошибка подготовки контекста, а не ошибка модели.

Без соответствующих изменений новый анализ не отправляется: для первого отчёта нужен diff конфигурации, для второго — diff тестов. Ревью тестов может выполняться при пустом diff конфигурации. Объём входных данных ограничивается реализацией; отчёт не гарантирует чтение каждого файла проекта целиком.

Транспорт KOT добавляет к `baseUrl` путь выбранного API и, при непустом `apiVersion`, `?api-version=…`. Авторизация всегда Bearer, ответ ожидается обычным JSON без streaming. Токены сервисов автоматически не обновляются. [Проверенные схемы подключения](../guides/ai-connections.md).

Не отправляйте диагностический пакет или отчёт автоматически. Проверяйте выводы модели: источник является основанием для гипотезы, а фактическое выполнение — отдельной проверкой.
