# Эталонные базы

Эталонное состояние задаёт, откуда подготовить тестовую базу и какие профили пользователей использовать. Каталог помогает повторять прогоны в одинаковом окружении.

Не путайте его со списком установленных баз. **Информационные базы** показывают доступные подключения и запуски; **эталонный каталог** описывает исходные состояния и связанные профили.

## Подготовить каталог

Откройте менеджер эталонных баз из KOT или полного менеджера баз. Укажите файл `bases.yaml`, используемый параметром `ModelDBSettings` вашего профиля компиляции.

Запись может содержать идентификатор базы, источники подготовки и профили пользователей. Поля должны соответствовать вашему компилятору СППР. Создание главного сценария и редактор настройки запуска используют этот каталог для выбора базы и пользователя.

Учебный пример — [config/bases.yaml](../../examples/kot-workshop/config/bases.yaml). Пути в нём демонстрационные; перед запуском замените их своими.

<a id="где-хранится-каталог"></a>

## Как разрешаются пути

Если `ModelDBSettings` не задан, используется `.vscode/kot-runtime/bases.yaml`. Относительный путь самого `bases.yaml` отсчитывается от корня проекта. Относительный путь DT **внутри** каталога — от папки, в которой лежит `bases.yaml`.

Например, при `ModelDBSettings = config/bases.yaml` значение `../dumps/clean.dt` указывает на `dumps/clean.dt` проекта. Абсолютные пути используются как заданы. Перенос одного `bases.yaml` в другую папку может изменить смысл относительных путей DT — проверьте их перед восстановлением.

## Редактировать и перенести каталог

1. Откройте **Управление эталонными базами** или **Reference infobases / Etalon bases** в полном менеджере баз.
2. Добавьте запись: понятное имя, `ИдентификаторБазы`, путь к DT.
3. Добавьте профили пользователей с именем профиля, логином и необходимыми данными подключения. Такой профиль описывает существующего пользователя, а не создаёт его в 1С.
4. При создании главного теста выберите эталон, затем его профиль. В настройку запуска попадут связанные значения.
5. Для переноса используйте импорт/экспорт `bases.yaml`; открыть текущий файл можно из того же менеджера. Перед экспортом проверьте, содержит ли он реальные пароли.

Имя эталона предназначено для выбора человеком. По `ИдентификаторБазы` компилятор разрешает эталон и его DT, а по `ПрофильПользователя` — учётные данные. Если каталог ещё пуст, сценарий можно создать и заполнить настройку запуска позднее. При `AuthCompile=true` корректный `ModelDBSettings` обязателен.

## Подготовить тестовую базу

Различайте действия: сохранить текущее содержимое, создать заново, восстановить DT, обновить конфигурацию. У каждого действия разные последствия. Подтверждение должно показывать целевой каталог и выбранный источник.

Клиент с нужным пользователем выбирается в профиле подключения Vanessa. Наличие имени в каталоге эталонов ещё не создаёт пользователя внутри самой конфигурации.

Избегайте общих файлов с реальными паролями. Чувствительные данные подключения и общие описания окружения храните раздельно.
