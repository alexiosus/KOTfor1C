# Диагностика и исправление ошибок

KOT проверяет исходники ещё до выполнения, а после подключения Vanessa показывает подтверждённые результаты шагов. Ошибка синтаксиса, ошибка компилятора и падение шага — разные этапы.

## До запуска

Проверки обнаруживают неизвестные или неоднозначные определения, отсутствующие параметры, лишние присваивания, проблемы структуры YAML/Gherkin, незакрытые конструкции и неподдерживаемые отступы.

Наведите на подчёркнутый фрагмент или откройте **Problems / Проблемы**. Действие **Quick Fix** предлагает исправление, когда оно может быть выполнено однозначно, например добавить отсутствующие параметры вызова или заменить табы.

Для парного исходника диагностика относится к тексту `scen.feature` и использует объявления из `meta.yaml`. Изменение метаданных обновляет проверки текста.

## Частые сообщения и действия

![Опечатка в шаге, Problems и реальные предложения Replace with](../assets/diagnostics-quick-fix.png)

Учебная опечатка `I sav` подчёркнута как неизвестный шаг. `Replace with: And I save…` исправляет вызов; создание пользовательского шага для такой опечатки не требуется. На снимке Problems отфильтрованы по демонстрационному файлу.

| Ситуация | Что проверить | Доступное исправление |
|---|---|---|
| Неизвестный шаг / Unknown Gherkin step | Текст, язык и подключённую библиотеку | `Replace with…` / варианты `Maybe you meant`, если найдены подходящие определения |
| Неизвестный вложенный сценарий | Имя, корень исходников и доступность определения | Выбрать корректный вызов; при неоднозначности уточнить определение |
| `Missing parameters` | Объявления вызываемого сценария | Добавить один недостающий параметр или все; подставляются доступные defaults |
| Лишнее присваивание у вызова | Имя параметра и выбранное определение | Убрать или переименовать лишнее присваивание после проверки |
| Незакрытые кавычки / вероятно пропущенные кавычки | Границы аргументов строки | Исправить текст; предложение замены зависит от найденного определения |
| Незакрытый блок | Парность If/Else/EndIf, Do/EndDo, Try/Except/EndTry и RU-аналогов | Добавить/исправить соответствующую границу блока |
| Дублируется код сценария | Другие исходники с тем же `ДанныеСценария.Код` | Штатная смена кода/имени соответствующего типа; не только замена текста вызова |
| Неполные секции параметров или вложенных вызовов | Фактическое использование в тексте | Заполнение секции из меню KOT либо исправление всего файла |
| Пустое или шаблонное описание | Описание KOT текущего объекта | Написать его вручную или использовать AI с последующей проверкой |

Цвет подчёркивания и severity определяются конкретным правилом; предупреждение о параметрах не равнозначно падению теста. Некоторые проверки можно отключить по коду в настройках, но это не меняет исходник и контракт компилятора.

**Fix scenario issues / Исправить проблемы сценария** объединяет поддерживаемую нормализацию: замену табов, выравнивание таблиц и присваиваний, заполнение служебных секций. Оно не исправляет произвольно смысл теста. После операции проверьте документ и оставшиеся Problems; правки доступны через Undo.

![Примеры диагностики: неизвестные шаги и вложенные сценарии, недостающие и лишние параметры, кавычки и Quick Fix](../assets/diagnostics-examples.png)

Коллаж показывает связь между сообщением в Problems, подчёркиванием в тексте, пояснением при наведении и предложенным исправлением. Для недостающих параметров можно добавить один параметр или весь набор.

## При компиляции

Откройте **Отчёт компилятора** и перейдите по ссылке к исходной строке. Если отчёт был создан на другом компьютере, KOT пытается привязать путь к текущему проекту. Ошибка здесь ещё не означает, что Vanessa начала выполнение.

## Во время выполнения

Строки окрашиваются по подтверждённым данным MCP и/или фактического журнала. Ошибка в hover показывает полученную причину. Если два повторяющихся шага нельзя однозначно сопоставить, KOT не должен помечать оба успешными по догадке.

Пропавшая подсветка не равна успешному тесту. Проверьте состояние Vanessa, выбранную feature и источник журнала. История всех сценариев ограничена API `.45`; опрос может пропускать быстрые переходы.

![Отслеживание прогона по журналу: выполняемые строки, упавший шаг и просмотр причины ошибки](../assets/run-log-results.gif)

В анимации показано наблюдение за прогоном по журналу: цвет строк меняется по мере выполнения, а наведение на упавший шаг открывает причину и ссылки на журнал и вложенный сценарий. [Как привязать журнал](vanessa-control.md#привязать-внешний-прогон-по-журналу).

## Настроить объём проверок

Режим и отключённые проверки находятся на странице настроек. Отдельные проверки выбираются списком. Отключайте конкретное правило по понятной причине, а не всю диагностику из-за одного ложного срабатывания.

Для обращения с ошибкой подготовьте минимальный исходник, версии KOT/VS Code/Vanessa, способ запуска и текст ошибки. Диагностический ZIP создаётся локально; перед публикацией проверьте его содержимое, особенно скриншоты.

## Проверить и обслужить набор файлов

**Сканирование диагностики по проекту** ищет проблемы шире активной вкладки. В меню **Обслуживание** Менеджера тестов доступны пакет изменённых сценариев, обработка всего исходного каталога и отмена операции. Диагностика и исправление — разные действия: пакетное исправление может записывать поддерживаемые изменения файлов. После него просмотрите отчёт и Git diff. [Практический порядок](../everyday-workflows.md#проверить-проект-а-не-только-открытый-файл).
