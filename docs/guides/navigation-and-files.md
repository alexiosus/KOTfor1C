## Открыть определение

**F12** на строке вложенного или экспортного вызова открывает найденный исходник: каретка может стоять на имени, ключевом слове или отступе. Если у шага есть собственное определение, например BSL-реализация, переход ведёт к нему. Иначе в сохранённой собранной feature KOT ищет конкретную строку исходника по карте компилятора `.str`. Если карты или соответствия нет, открывается исходник ближайшего окружающего блока `*And …`.

Отдельный пункт **Open enclosing nested scenario** убран из контекстного меню. Команда сохранена для прежних привязок клавиш и случаев, когда нужно явно открыть окружающий сценарий. Hover показывает доступную информацию. Команда **Найти вызовы текущего сценария** полезна перед изменением имени или удалением.

Связи в Менеджере тестов и Библиотеке могут подсвечиваться или использоваться как фильтр. Если определений несколько, KOT сообщает о неоднозначности: одинаковое имя не является достаточной идентичностью.

Для перехода к окружающему сценарию карта сборки не нужна. При несохранённых изменениях feature переход по сохранённым номерам строк пропускается. Наличие старой карты ещё не делает шаг безопасным для выполнения YAML.

## Прикрепить файлы

Откройте вкладку **Файлы** свойств теста. Вложения в `files/` доступны до компиляции; после сборки результат и собранные файлы показываются отдельно.

В Библиотеке и Менеджере тестов узел **Собранные файлы** показывает вложения из `<имя feature>/Файлы/` и файлы рядом с собранной feature. Поддерживается и смешанное размещение. Сама feature, её карта `.str`, JSON запуска и служебные файлы компилятора в этот список не входят; JSON с тестовыми данными отображается.

- **Добавить файлы** выбирает внешние файлы.
- Перетаскивание в панель принимает вложения и предлагает действия при конфликте имён.
- Вставка в редактор передаёт имя файла для аргумента шага.
- Можно открыть, переименовать или удалить вложение с подтверждением.

Если перетаскивание в редактор не работает в вашей версии VS Code, используйте явную вставку или файловый диалог. При смене исходника незавершённое добавление не должно переноситься в другой тест.

## Другие переходы

При открытии файла по выделенному имени KOT сначала проверяет `files/` текущего сценария, затем `files/` вызываемых вложенных сценариев. Запасной поиск ориентирован на `tests/**`. Поэтому одинаковые имена могут разрешаться в локальное вложение, а файл вне этого дерева может не найтись автоматически. В таком случае откройте его явно через вкладку файлов или Проводник.

Для MXL установите [1С:Предприятие — работа с файлами](https://v8.1c.ru/static/1s-predpriyatie-rabota-s-faylami/) и проверьте `kotTestToolkit.paths.fileWorkshopExe`: нужен исполняемый файл `1cv8fv.exe`. Затем выделите имя MXL в сценарии и вызовите **KOT → Работа с файлами → Открыть MXL**. Команда также доступна у самого MXL в Проводнике. Локальный запуск программы рассчитан на Windows.

Контекстное меню позволяет открыть папку теста, `files/`, каталог сборки и расположение в системном проводнике. MXL открывается через установленную программу работы с файлами 1С.

Удаление локального объекта выполняйте штатной командой KOT: она проверяет вызовы и связанные файлы. Файлы могут перемещаться в корзину; у экспортного сценария удаляется только его блок из общей feature. Сохраните несохранённые изменения до такой операции.

## Переименование вместо замены текста

Перед изменением имени найдите вызовы и при необходимости включите фильтр связей. Используйте действие KOT для нужного определения: оно проверяет выбранный объект и обновляет поддерживаемые вызовы. Имя сценария, его код и имя экспортного объявления — отдельные сущности. Обычная замена текста в одной строке не выполняет всю операцию. [Контекстные действия](../context-menus.md).
