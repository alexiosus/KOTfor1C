# Параметры сборки и запуска

Этот менеджер задаёт, **как** KOT собирает и запускает тесты. Параметры отдельного сценария задают, **какие данные** он проверяет. Это разные настройки.

Откройте менеджер из меню KOT. Профили позволяют хранить несколько окружений и выбирать нужное перед сборкой; переключение профиля не требует переписывать исходники.

## Профили принадлежат проекту

У каждого проекта свой список профилей и свой последний выбранный профиль. Открытие другой папки, в том числе мастерской, не переключает и не перезаписывает профили вашего рабочего проекта. При возвращении восстанавливается его выбор. Имя проекта показано в шапке менеджера.

Папка, открытая напрямую или через `.code-workspace`, использует один и тот же набор. В рабочей области с несколькими корнями профили относятся к первой папке, как и текущая компиляция KOT; это не отдельный набор для каждой вкладки редактора.

После обновления прежние общие профили доступны в меню выбора профиля → **Импортировать прежний общий профиль**. Выберите нужный: KOT скопирует все три части в текущий проект и активирует копию. Оригинал сохраняется; изменения копии не затрагивают другие проекты. Новый профиль мастера начинается со стандартных параметров Vanessa и пустых GlobalVars. Для намеренного копирования текущих значений используйте **Дублировать профиль**.

Проект может поставлять начальный набор в [`.kot/parameter-profiles.json`](../technical/project-files.md#начальные-профили-проекта). Он применяется при отсутствии локально сохранённых профилей. Поэтому мастерская сразу получает `KOT Workshop` с учебной библиотекой и значениями; ваши последующие изменения сохраняются отдельно и имеют приоритет.

![Профиль компиляции с отключённым созданием JSON запуска](../assets/parameters-manager.png)

На снимке активен учебный профиль **KOT Workshop**: `CreateJson=false`, поэтому launch-база может быть пустой. Это профиль знакомства с исходниками, а не готовое подключение к вашей 1С.

![Управление профилями проекта: текущий KOT Workshop, создание, дублирование, переименование и импорт прежнего общего профиля](../assets/project-profiles.png)

Нажмите имя профиля в шапке, чтобы открыть это меню. Пункт импорта копирует прежний общий профиль в текущий проект; его не нужно создавать заново вручную.

## Три части профиля

| Часть | Что задаёт |
|---|---|
| Параметры СППР | Каталоги сценариев/процессов, результат сборки, каталог эталонных баз, фильтры и режимы компилятора |
| Дополнительные параметры Vanessa | Настройки самой Vanessa Automation, как в `VAParams.json`: библиотеки, язык генератора, отчёты и другие параметры выполнения |
| Глобальные переменные | Начальные значения глобальных переменных Vanessa (`GlobalVars`, обращения `$$Имя$$`) |

Изменения профиля сохраняются автоматически. Это отдельное автосохранение: кнопка **Применить** на общей странице настроек KOT не управляет черновиком профиля. Перед редактированием проверьте его имя; смена корней влияет и на поиск тестов.

Мастер настройки сохраняет пути внутри проекта относительно его корня; внешние пути остаются абсолютными. Установленная платформа, компилятор и Vanessa продолжают использовать существующие настройки компьютера. Переключение профиля KOT не перегружает библиотеки уже работающего сеанса Vanessa — при необходимости запустите менеджер с параметрами этого профиля.

Вкладка **Глобальные переменные** задаёт начальные значения для JSON запуска, а панель **Переменные Vanessa** справа показывает текущие значения подключённого сеанса. В терминах Vanessa локальные переменные (`$Имя$`, объект `Контекст`) очищаются перед началом сценария; глобальные (`$$Имя$$`, объект `КонтекстСохраняемый`) сохраняются между сценариями, пока работает Vanessa. Изменение профиля не заменяет текущие значения в уже запущенном сеансе. Подробнее: [переменные в MCP](https://pr-mex.github.io/vanessa-automation/dev/AI/) и [GlobalVars в параметрах запуска](https://pr-mex.github.io/vanessa-automation/dev/JsonParams/JsonParamsRU/).

<a id="минимальный-набор-для-сборки"></a>

## Минимальная проверка СППР

| Параметр | Когда заполнять | Что указать |
|---|---|---|
| `ScenarioFolder` или `TestFolder` | Всегда | Корень исходников СППР |
| `ProcessFolder` | Если процессы лежат отдельно | Их собственный корень |
| `FeatureFolder` | Всегда | Каталог результата компиляции |
| `VanessaFolder` | При `CreateJson=true` | Каталог распакованной Vanessa; обычно определяется из пути к её EPF |
| `LaunchDBFolder` / `TestClientDBPath` / `InfobasePath` / `TestClientDB` | При `CreateJson=true` | Папка файловой базы либо строка подключения, соответствующая выбранному ключу |
| `ModelDBSettings` | Обязательно при `AuthCompile=true`; полезно и без строгой проверки | Путь к `bases.yaml` для эталонов и разрешения профилей пользователей |

`AuthCompile` включает строгую проверку авторизации СППР. Сам по себе этот флаг не задаёт логин и пароль: сведения берутся из `ModelDBSettings`. При пустом каталоге эталонов и `AuthCompile=false` компиляция возможна, но автоматическое разрешение учётных данных по профилю недоступно.

При `CreateJson=false` требования KOT к `VanessaFolder` и launch-базе снимаются. Это подходит для проверки компиляции исходников; JSON запуска при этом не появится. Внешняя доработанная обработка СППР может предъявлять свои дополнительные требования.

`TestFolder` — поддерживаемый общий алиас с приоритетом для обоих корней. Не добавляйте его, если намеренно используете разные каталоги сценариев и процессов.

Для launch-базы различайте папку (`LaunchDBFolder`, `TestClientDBPath`) и полную строку подключения (`InfobasePath`, `TestClientDB`). Например, строка серверной базы имеет вид `Srvr="server";Ref="test-base";`. Полная строка имеет приоритет над папкой; `TestClientDB` — над `InfobasePath`. Не задавайте несколько противоречащих друг другу значений. Выбранная перед запуском база может заменить целевое подключение.

Имена параметров компилятора сравниваются без учёта регистра, пробелов, `-` и `_`: `FeatureFolder` и `feature_folder` распознаются как один ключ. При этом значения сохраняют свой тип и смысл. Корень `FeatureFolder` относится к результату СППР, а `runtime.directory` — к служебным файлам KOT; это разные настройки.

Обязательные строки закреплены в таблице. Остальные известные ключи выбираются поиском с описаниями; для модифицированного компилятора можно добавить собственную строку. `ScenarioFilter` и `ExceptScenario` KOT формирует по набору компиляции — ручной фильтр не должен незаметно отменять этот выбор.

Перед первой сборкой проверьте подсветку обязательных полей и откройте предпросмотр `yaml_parameters.json`. Число ошибок валидации должно быть устранено до экспорта. Полезные источники: [параметры компилятора на ИТС](https://its.1c.ru/db/sppr2doc#content:124:hdoc) и [JSON-параметры Vanessa](https://pr-mex.github.io/vanessa-automation/dev/JsonParams/JsonParamsRU/).

<a id="2-дополнительные-параметры-vanessa"></a>

## Дополнительные параметры Vanessa

Это **настройки самой Vanessa Automation** с теми же ключами, которые используются в [`VAParams.json`](https://pr-mex.github.io/vanessa-automation/dev/JsonParams/JsonParamsRU/). Например, `gherkinlanguage` задаёт язык генератора шагов, а параметры библиотек и отчётов управляют соответствующими возможностями Vanessa.

Сюда можно импортировать JSON настроек, выгруженный из Vanessa. KOT хранит значения в профиле и объединяет их с JSON запуска выбранного теста по правилам приоритета. Имя файла JSON может отличаться от `VAParams.json`.

Ключи выбираются из каталога с описаниями, значения имеют ожидаемый тип. Список добавления не предлагает уже добавленные параметры. Поддерживаются известные русские/английские эквиваленты и собственные ключи.

Кнопки импорта/экспорта помогают перенести JSON. Важна разница между числом, логическим значением и строкой: `false` не равно строке `"false"`.

`Libraries` компилятора использует разделитель `|`; собственная библиотека Vanessa добавляется автоматически. Пользовательские библиотеки подключайте явно. Обнаружение параметров по исходникам выбранной Vanessa точнее встроенного резервного каталога.

<a id="приоритеты-и-merge-логика"></a>

## Приоритеты

Компиляция создаёт исходный JSON. KOT формирует итоговые параметры с учётом дополнительных значений, их приоритета и служебных полей выбранного способа запуска. В активном MCP-сеансе не все эти значения можно применить заново.

Если результат отличается от ожидаемого, откройте исходный и итоговый JSON через действия теста и сравните нужный ключ. Точные правила — [справочник компилятора и запуска](../technical/compiler.md).

## Проверить итоговые параметры перед запуском

В контекстном меню собранного теста **Open JSON** разделяет исходный JSON компилятора и итоговый вариант с дополнительными параметрами Vanessa и GlobalVars. Сравнивайте их, если значение получилось неожиданным. [Пример задачи](../everyday-workflows.md#сравнить-json-компилятора-с-фактическим-запуском).
