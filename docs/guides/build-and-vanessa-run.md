# Компиляция и выполнение теста

Для СППР это два этапа: компилятор создаёт feature и сопровождающие файлы, затем Vanessa выполняет полученные шаги. Самостоятельная feature начинает со второго этапа.

## Подготовить сборку СППР

Проверьте платформу 1С, путь к компилятору и активный профиль в **Параметрах сборки и запуска**. Обязательные значения проверяются перед запуском. Отметьте нужные главные сценарии или процессы в Менеджере тестов.

При наличии нескольких настроек запуска у одного сценария они задают варианты теста. Настройки и фильтры профиля могут ограничить то, что действительно попадёт в результат.

## Разобрать результат компиляции

После сборки доступны feature, JSON запуска, вложения и отчёты. **Отчёт о сборке / Build report** показывает общий итог, ошибки с переходом к исходной строке и таблицу результатов по настройкам запуска.

Одинаковые сообщения из JUnit и XML СППР объединяются в одну ошибку. Полный текст, стек вызовов, журналы и файлы компилятора доступны в раскрываемых блоках. Если часть результатов недоступна, отчёт явно сообщает об этом. Он описывает компиляцию; результат выполнения теста появляется при запуске в Vanessa.

KOT поддерживает отдельные части сборки, ограниченную параллельность и отмену. Состояние артефакта привязано к исходнику и зависимостям. Изменения вложенного или экспортного сценария могут сделать тест устаревшим, даже если имя выходной feature не изменилось.

Не редактируйте собранный файл как основной исходник: следующая компиляция создаст его заново. [Состояния сборки](metadata-and-cache.md).

![Отчёт о сборке: один тест собран, у второго показана ошибка со ссылкой на scen.feature:8; слева видны feature и Собранные файлы](../assets/build-results.png)

На примере собран один тест, а второй содержит намеренную ошибку. Ссылка `scen.feature:8` ведёт к строке исходника; технические подробности и файлы компилятора раскрываются отдельно. Слева **Собранные файлы** относятся к результату компиляции, а не к вложениям исходника.

## Запустить feature

Нажмите **Run** в Менеджере тестов или свойствах. Для самостоятельной feature выберите/создайте JSON запуска. При подключённой Vanessa используется общий маршрут управления сеансом.

Активный менеджер уже имеет свои параметры и клиентов. Если они отличаются от профиля теста, KOT предупреждает о различиях. Проверенный API `.45` не умеет загрузить весь JSON в уже работающий менеджер; согласие на использование активного сеанса не означает, что все параметры JSON применены.

Если JSON не создавался (`CreateJson=false`), feature можно открыть; built-in запуск, которому нужен JSON, потребует включить его создание или настроить собственную команду запуска.

## Во время выполнения

В редакторе отображаются подтверждённые состояния строк. Hover на ошибке показывает причину, если она получена от Vanessa. Постоянный журнал управляемого сеанса дополняет MCP там, где опрос пропускает быстрые шаги.

**Остановить** завершает выполнение по доступному API. Продолжение рассчитано на подтверждённую точку останова; оно не восстанавливает произвольное место внутри BSL.

## Архив FirstLaunch

Для проектов с подготовленным каталогом первоначального запуска есть команда **Собрать архив FirstLaunch**. Она читает версию из `cf/Configuration.xml`, собирает выбранную папку и подставляет версию в поддерживаемые XML внутри ZIP. Каталог задаётся настройкой `paths.firstLaunchFolder`; это отдельный сценарий доставки, а не обязательный этап каждого теста. Исходные XML не заменяются содержимым архива.

## Своя команда запуска

`runVanessa.commandTemplate` позволяет использовать корпоративный launch-скрипт. Если он задан, он имеет приоритет перед обычным маршрутом Run. Пустое значение оставляет управление KOT; настройка `executionMode` выбирает MCP или отдельный процесс без собственной команды.

| Подстановка | Содержимое |
|---|---|
| `${scenarioName}` / `${scenarioNameQuoted}` | Имя выбранного теста |
| `${featurePath}` / `${featurePathQuoted}` | Абсолютный путь к собранной feature |
| `${jsonPath}` / `${jsonPathQuoted}` | JSON, выбранный для запуска, включая итоговый combined-вариант, если он используется |
| `${workspaceRoot}` / `${workspaceRootQuoted}` | Корень открытого проекта |

В аргументах shell используйте `*Quoted`, чтобы корректно передать пробелы и специальные символы; не добавляйте поверх них собственную пару кавычек без проверки вашего shell. Настройка шаблона не превращает внешнюю команду в MCP-сеанс: для наблюдения за внешним прогоном можно [привязать его журнал](vanessa-control.md#привязать-внешний-прогон-по-журналу).

Автоматическое обнаружение свежих журналов также имеет отдельные настройки минимального числа стартовых обновлений и таймаута неактивности. Старый файл на диске не считается доказательством активного прогона. При явной привязке выбирайте фактический файл нужной попытки; остановка наблюдения не останавливает процесс 1С.
