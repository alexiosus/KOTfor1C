# ИИ-инструменты для тестировщика

В KOT 3.1.0 прямое подключение к OpenAI-совместимому API удалено. Описание сценариев, анализ изменений конфигурации и ревью тестов выполняются через [ИИ-оператора тестирования](ai-agent.md) в подключённом MCP-клиенте.

В настройках KOT нажмите **Подключить ИИ** или выберите одноимённую команду в меню **ИИ** Менеджера тестов. Мастер помогает подключить выбранный клиент к инструментам KOT; для Codex и Claude Code также устанавливает навык проекта. Другие MCP-клиенты получают актуальные инструкции через `kot_workflow`. Модель и её подключение настраиваются в самом ИИ-клиенте.

Примеры запросов:

- «Объясни, что проверяет этот сценарий: изучи его исходник, параметры и вложенные вызовы».
- «Изучи сценарий `0031_Purchases_reverse_charge` и вложенные вызовы. Сформируй описание назначения, предусловий, основных действий и ожидаемых результатов и сохрани его в KOT».
- «По стори и изменениям конфигурации подготовь тест-план; укажи основания для каждой проверки».
- «Проведи ревью изменённых тестов: проверь ожидаемое поведение, покрытие стори и пропущенные проверки».

Для сохранения агент использует `kot_scenario_description`: сначала `action: read` с путём исходника, затем `action: set` с текстом `description`, полученной `expectedRevision` и новым `requestKey`. Инструмент заполняет то же поле **Описание**, что и ручное редактирование свойств. В KOT 3.1.0 используется соседний `.kot.yml`; в старом формате — `KOTМетаданные.Описание`. Для native-сценария можно передать `meta.yaml` или `scen.feature`: описание относится к паре файлов. В самостоятельной feature меняется текст описания после заголовка `Feature` / `Функционал`; он должен быть обычным текстом без строк-комментариев, тегов и заголовков Gherkin.

Изменения исходника, native-скрипта или описания после чтения ревизии требуют повторного чтения. Несохранённые правки в редакторе и режим **Только анализ** блокируют запись. Исполнение тестов для заполнения описания не требуется. Сохранение описания не подтверждает прохождение теста.

Сохранённые описания доступны в свойствах и по-прежнему редактируются вручную. Старые отчёты открываются через **ИИ → Открыть сохранённый отчёт по изменениям конфигурации** и **Открыть сохранённое ревью тестов**. Команды выбирают файл для текущей Git-ветки и не создают новый анализ.

При создании сценариев агентом по workflow `generate` описание входит в результат создания. Оно заполняется для каждого нового главного/вложенного сценария, процесса и самостоятельной feature и проверяется до финальной сборки и прогона. Если исправления изменили сценарий, агент актуализирует описание перед окончательной проверкой. Это правило процесса агента; ручной мастер создания KOT сам модель не запускает.
