# AI-инструменты для тестировщика

KOT предоставляет три отдельные AI-задачи. Они используют настроенный OpenAI-совместимый API и не требуются для редактора, компиляции или MCP-кнопок Vanessa.

| Инструмент | Когда использовать | Результат |
|---|---|---|
| Описание сценария | Нужно быстро объяснить проверку человеку | Структурированное описание текущего сценария |
| Отчёт по изменениям конфигурации | Нужно определить область ручного и автоматического тестирования | Markdown-отчёт по diff конфигурации, при необходимости с User Story |
| Ревью изменённых тестов | Нужно сопоставить тесты и изменения продукта | Отчёт о покрытии, пропусках и хрупких проверках |

## Подключить

На странице настроек откройте **AI**. Укажите адрес сервиса, модель, формат API и непустой ключ. Для локального сервера без авторизации подходит условное значение `local`. [Готовые примеры LM Studio, Ollama, OpenAI, Gemini и Azure](ai-connections.md) показывают согласованные настройки и разбор ошибок.

Перед отправкой проверьте, кому принадлежит сервис и допускается ли передача исходников проекта. В AI-запрос может входить текст сценария, параметры, вложенные вызовы, diff конфигурации и тестов, а также введённая User Story. Выбор локального или облачного сервиса остаётся за вами.

## Описать сценарий

Выберите **Описать с помощью ИИ** для текущего сценария. Просмотрите результат: что проверяется, какой процесс проходит тест, какие параметры и развилки влияют на поведение. Описание должно помогать чтению, а не заменять сами проверки.

## Подготовить отчёт

В меню AI/Thinking Менеджера тестов выберите анализ конфигурации или ревью тестов. Для конфигурации укажите её файловую выгрузку в настройках проекта. По желанию добавьте User Story.

Отчёт сохраняется локально и может быть открыт повторно. Проверьте выводы модели по исходникам: предложенная проверка или предполагаемый риск ещё не подтверждены фактическим выполнением.

| Задача | Что подготовить | Где результат и как открыть снова |
|---|---|---|
| Описание | Открытый сценарий и AI-подключение | Описание KOT текущего объекта, доступное в свойствах |
| Анализ конфигурации | Git-ветку с изменением файловой выгрузки; `configurationSourceDirectory`; при необходимости User Story | `configuration-diff-ai-reports/` внутри runtime; **Open AI diff report** |
| Ревью тестов | Изменения тестов относительно главной ветки, выгрузку для контекста конфигурации; при необходимости User Story | `test-review-ai-reports/` внутри runtime; **Open AI test review** |

По умолчанию runtime — `.vscode/kot-runtime`; другое место задаёт `runtime.directory`. Файл отчёта выбирается для текущей ветки. При отсутствии diff конфигурации анализ конфигурации не создаёт новый отчёт; при отсутствии изменений тестов не запускается их ревью. Старый сохранённый отчёт при этом не становится доказательством нового анализа.

В конфигурационном отчёте ищите пользовательский эффект, приоритетные проверки, роли/данные и соседние риски. В ревью тестов — соответствие изменениям продукта, пробелы покрытия и хрупкие проверки. Если изменений конфигурации нет, ревью может оценивать изменённые тесты и User Story без выдуманного diff продукта.

## Как читать результат

Ниже — **составленный учебный пример**, не ответ реального сервиса и не результат приёмки:

```markdown
Проверяется: выбор покупателя в учебной заявке.
Процесс: создать заявку, заполнить шапку и проверить сохранённое значение.
Параметры и развилки: Customer задаётся сценарием или настройкой запуска.

Что проверить дополнительно:
- покупатель недоступен выбранному пользователю;
- значение очищено перед сохранением.
```

Первые три строки показывают назначение описания, последний список — возможные рекомендации отчёта. Названия и полнота разделов зависят от задачи и ответа модели. Сопоставьте каждую рекомендацию с исходниками и реальным поведением.
