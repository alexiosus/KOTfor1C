# Общие данные проекта

Команда должна видеть одинаковые группы и описания тестов, но не обязана делить личное избранное, открытые панели и подключения. KOT разделяет эти сведения.

## Что передавать через Git

| Данные | Файлы |
|---|---|
| Исходники и настройки запуска | YAML, feature, `test/` и необходимые JSON |
| Формат ветки после явного перехода | `.kot/project.yml` (`version: 3`) |
| Общие группы | `.kot/groups/<id>.yml` |
| Маркер импорта прежних метаданных KOT | `.kot/imports.yml`, если создан |
| История явного удаления метаданных | `.kot/history/*.yml`, если создана |
| Каталоги свойств и функций системы | `.kot/property-catalogs.yml` |
| Авторские серии и счётчики номеров | `.kot/test-numbering.yml` |
| Группа, описание и категория объекта | Соседний `*.kot.yml` |
| Данные обратной конвертации экспорта | `*.feature.kot-nested.json`, если создан |
| Вложения и исходники библиотек | `files/`, feature и BSL-исходники |

Избранное, раскрытие, личный порядок показа групп и элементов, выбор строк и привязки сеанса остаются локальными. Пароли не относятся к общим каталогам.

## Работать с группами

Создавайте и переименовывайте группу из Менеджера тестов или Библиотеки. Принадлежность элемента общая для команды. Порядок показа синхронизирован между панелями этого рабочего пространства, но не передаётся через Git. Перенос внутри группы не меняет файлы; перенос в другую группу меняет только метаданные переносимого теста. Пустые группы могут сохраняться; **Без группы** остаётся доступной целью переноса.

Каталоги проектов, ответственных, уровней отчёта, категорий и функций используются мастерами и свойствами. Добавление значения из поля не требует ручного редактирования всех тестов.

## Перейти со старых данных

Прежние встроенные `KOTМетаданные` и локальные сведения могут переноситься в общий формат. Мастер показывает план; автоматическая миграция ожидает его применения, но явное редактирование групп и свойств доступно и без завершения мастера.

После переноса просмотрите Git diff и сохраните новые файлы рядом с исходниками. Не удаляйте sidecar, считая его одноразовым кешем. UID и неизвестные поля не следует исправлять массовой заменой.

## Нумерация и функции системы

Команда **KOT — Нумерация тестов** управляет авторскими сериями и счётчиками. Они используются при создании исходников; это не только поле имени текущего теста. Команда **KOT — Управление функциями системы** открывает общий каталог функций и их идентификаторов. Другие справочники доступны из полей свойств и метаданных проекта.

Изменения общих каталогов просматривайте в Git вместе с тестами. Пример практического маршрута — [привести имена и номера к правилам команды](../everyday-workflows.md#привести-имена-и-номера-к-правилам-команды).

## Если Git сообщил о конфликте

В меню **Обслуживание** Менеджера тестов или палитре команд выберите **KOT: Разрешить конфликты метаданных KOT…**. Выберите файл, решите спорные поля и просмотрите предложенные изменения. Кнопка **Применить проверенное решение** запишет результат; добавление файла в индекс и коммит остаются обычными действиями в Source Control. Можно отменить любой шаг.

Разные правки описания и группы объединяются. Если оба автора изменили одно имя, нужно выбрать вариант. Для нумерации сохраняется больший счётчик; это не устраняет случайно выданные одинаковые коды тестов. После применения KOT проверяет ссылки на группы, повторные UID метаданных и коды исходников и показывает найденные проблемы.

Если файл уже исправлен вручную, сохраните и добавьте своё решение в Git. KOT не заменяет вручную разрешённый файл и не применяет предложение, если после просмотра изменились файл, индекс или несохранённые данные редактора. Слияние поддерживается для групп, метаданных объектов, каталогов свойств, нумерации и истории переноса.

При отставании регионального CI оставьте его ветки без `.kot/project.yml` версии 3. Обновление плагина не меняет эту договорённость. В Core метка появляется только в подготовленной ветке; её появление при слиянии означает, что вместе с ней должны прийти совместимые CI-скрипты. Настройка окружения без флажка перехода сохраняет прежний формат.
