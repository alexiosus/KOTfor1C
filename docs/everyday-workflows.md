# Полезные действия, которые легко не заметить

Здесь собраны возможности, которые не всегда видны на первой панели. Сначала описано действие и результат; точные параметры остаются в связанных руководствах.

## Найти шаг, не помня его начало

На новой строке введите `!` и несколько слов о нужном действии, например:

```gherkin
!click button
```

Можно оставить ключевое слово перед запросом: `And !click button`. KOT ищет по тексту и описанию доступных определений и ранжирует совпадения. Выбор заменяет запрос настоящим шагом; `!` не остаётся в сценарии. Это локальный поиск, он не требует AI-ключа или подключения к Vanessa. Формулировка не обязана совпадать с началом шага, но совпадение не гарантируется для любого произвольного описания.

В СППР можно найти вложенный вызов, а в самостоятельной feature предлагаются допустимые для неё определения. Язык результата определяется контекстом сценария. [Работа в редакторе](guides/editor-and-intellisense.md).

## Заменить аргумент именем с живой формы

Подключите клиент и откройте его форму. Вставьте обычный шаг, например нажатие кнопки. Внутри кавычек нажмите `Ctrl+Space` или начните ввод: список содержит подходящие подписи или технические имена. В шаге `button named` подставляется техническое имя; у шага по подписи — подпись.

Выделенное значение аргумента из шаблона предназначено для замены. Случайные шаги и теги сюда не подмешиваются. Имена полей, колонки и текущие значения зависят от формы и конкретного места аргумента; для произвольного текста или числа секунд списка элементов не будет. [Form Explorer](guides/form-explorer.md).

## Переименовать и посмотреть, кого затронет изменение

1. Откройте сценарий и выполните **Найти вызовы текущего сценария**.
2. Включите подсветку связей или фильтр связанных определений в Менеджере тестов/Библиотеке.
3. Выполните штатное переименование из свойств, действий определения или меню KOT.
4. Просмотрите изменения вызовов и Git diff.

Для экспортного сценария важно менять объявление, а не текст одного вызова. Конвертация формата и изменение роли находятся в **Преобразования…**. [Навигация](guides/navigation-and-files.md) · [Преобразования](guides/scenario-source-formats.md).

## Восстановить служебные секции СППР по тексту

В **KOT → Редактирование** доступны заполнение `ВложенныеСценарии` и `ПараметрыСценария`. Они помогают согласовать объявления с уже написанными вызовами и подстановками. Автоматическая синхронизация включается отдельно.

В feature + meta исходный текст остаётся в `scen.feature`, а объявления — в `meta.yaml`. Если определение неоднозначно, сначала устраните неоднозначность; заполнение не заменяет проверку компилятора. [Параметры](guides/scenario-parameters.md).

## Проверить проект, а не только открытый файл

**KOT — Выполнить сканирование диагностики по проекту** запускает проверки исходников. В **Обслуживании** Менеджера тестов доступны безопасный пакет изменённых файлов, обработка всего каталога и отмена.

Это разные операции: диагностика сообщает о проблемах; пакетное исправление может менять поддерживаемые секции файлов. Полная обработка большого каталога создаёт заметную нагрузку. Просматривайте результат и Git diff. [Диагностика](guides/diagnostics-and-quick-fix.md).

## Сравнить JSON компилятора с фактическим запуском

У собранного теста откройте контекстное меню → **Open JSON**. Исходный вариант показывает результат СППР; итоговый — результат объединения с дополнительными параметрами Vanessa и GlobalVars.

Так проще понять, почему параметр не совпал с ожиданием. Подтверждённый запуск в уже открытом MCP-менеджере использует возможности и текущую конфигурацию именно этого менеджера; наличие итогового JSON ещё не означает атомарное применение всех его полей в Vanessa `.45`. [Приоритеты параметров](technical/compiler.md).

## Подключить уже идущий прогон по журналу

Откройте выполняемую feature → **KOT → Логи и отслеживание запуска** → привязка журнала. Можно переключить привязанный прогон или прекратить отслеживание. Обратный маршрут начинается из открытого log-файла.

Это полезно для запуска вне KOT. Выбирайте фактический журнал текущего сеанса и нужную feature: соседний старый журнал не доказывает результат нового запуска. [Наблюдение за выполнением](guides/vanessa-control.md).

## Вынести повторяемый шаг в свою библиотеку

**Создать экспортный сценарий** подходит для переиспользования нескольких Gherkin-шагов. **Создать пользовательский шаг** создаёт исходник реализации на BSL; **Собрать библиотеку пользовательских шагов** получает EPF из исходников при подготовленном окружении.

Библиотечные каталоги добавляются в параметры проекта. Бинарной EPF недостаточно для переходов и полного индекса: нужны читаемые исходники определений. [Создание библиотек](guides/scenario-creation.md).

## Привести имена и номера к правилам команды

Нумерация тестов задаёт авторские серии и счётчики; свойства используют общие каталоги проектов, ответственных, категорий и функций системы. Это помогает выбирать существующее значение вместо новых вариантов написания.

Сведения для команды хранятся в `.kot`, а личное избранное и раскрытие панелей — локально. Для функций системы и серий номеров есть отдельные команды управления. [Общие каталоги](guides/shared-project-library.md).

## Подготовить файлы для запуска и обмена

В **Файлах** свойств можно добавлять, переименовывать и вставлять вложения до компиляции. MXL открывается штатным действием KOT. **Собрать архив FirstLaunch** готовит ZIP из указанного каталога с поддерживаемой подстановкой версии конфигурации.
